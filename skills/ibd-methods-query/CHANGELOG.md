# CHANGELOG

## [0.3.0] - 2026-09-18

### 新增：冷启动引导档——首次使用无库不再报错（用户反馈修复）

- **背景**：外部用户反馈首次触发检索时出现「方法论调用索引读取失败」——库未建时 S2 直接读索引必失败，原缺失降级只覆盖「库存在但索引缺失」，未覆盖「库不存在」；「提示先去 ops 完成库配置」则把任务中断踢给另一 skill，客户端 AI 接不住
- **三态降级重构**（替换原单句缺失降级）：① 库正常索引过期 → 照常检索 + 提示刷新；② 库已建索引缺失 → Grep 兜底档（原档保留）；③ **库未建/配置缺失 → 冷启动引导档（新增）**
- **冷启动引导档动作**：一问定路径（默认 `~/methods/`）→ 按 ops methods-guide「起步结构 4 文件」+「§九 空库模板」建骨架 → 生成最小 `library.config.json`（A 档默认；schema 单一事实源仍在 ops，四问引导自动认账）→ 本次交付「无命中 + 待沉淀登记」+ 起步路径指引
- **配套裁定**：ops「边界与协作」补冷启动分工——query 建骨架属「检索前置条件自举」，非蒸馏生产；内容生产仍归 ops
- **知识来源**：冷启动知识原在生产侧（methods-guide §五/§九），本次在消费侧（query）补直达引导，两包引用同一规范文件，无第二源
- 性质：新增降级行为（文档层流程约定，零脚本变更）→ bump Y（0.2.1 → 0.3.0）

## [0.2.1] - 2026-09-18

### 修复：接入点声明补第三问「缺失降级」（P2+ 门禁项）

- **背景**：全局一致性体检发现发布仓 `skills/` 实际纳管 7 包（含本包与 `ibd-methods-ops`），而 `docs/ATTACHMENT-POINTS.md` 总表仍写「5 个公开包」且未给方法包建行。经用户裁定（方案 A：按事实刷新）→ 总表扩为 7 个公开包，本包正式入表
- **原缺口**：「依赖与工具」节只有「工具」「索引资产」两项，**第三问缺失降级未写**
- **本次补入**：索引缺失或库未建 → 标准检索链路不可用，退回 **Grep 全库关键词扫描兜底档**（查得到、token 成本升高）；调用方 `ibd-doc-write` 另有**内嵌流程**（无本 skill 时按其内嵌流程运行），本包缺失不阻断写作链路；纯检索流程零脚本，不存在运行时依赖缺失问题
- **关联**：`docs/ATTACHMENT-POINTS.md` 总表补本包三问行；`docs/CONVENTIONS.md` 接入点行 5→7；`skill-publish-pipeline` 0.10.0「③ 修复与口径对齐」节
- 性质：补声明属描述补全、行为零变更 → bump Z
