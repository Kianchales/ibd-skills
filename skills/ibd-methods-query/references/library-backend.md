## 1. 库接入适配（先读配置 · 按档位分派）

> 库为**开放后端**（本地目录 / Obsidian / 乐享 / ima / 任意 MCP 知识库 / 云文档……示例非穷举），配置由 `ibd-methods-ops` 管理（其安装目录下 `library.config.json`）。检索前先读该配置，按**能力档位**分派：

| 档位 | 检索方式 | 说明 |
|---|---|---|
| **A · 文件型**（本地/Obsidian/同步盘等） | 索引定位 → 行号定向读（Read offset/limit / Grep） | 全能力：渐进披露完整（token 最优） |
| **B · 检索型**（云知识库连接器，如乐享、ima 等） | 连接器搜索（关键词/语义）→ 拉取条目全文 | 无行号定位；先搜再拉，避免整库载入 |

- **配置缺失 → 走冷启动引导档**（见下方「缺失降级」第 3 档，本 skill 就地完成，不中断任务）
- B 档检索：优先关键词精确检索，命中不足再用语义检索；拉取条目后按「编号 + 出处」输出（编号体系见库规范）

## 2. 依赖与工具（含缺失降级三态）

- **工具**：`Read`（定向读取 offset/limit）+ `Grep`（索引关键词搜索）——内置，零外部依赖
- **索引资产**：见 retrieval-chain.md §8（检索入口，由库维护脚本生成；`ibd-methods-ops` ≥1.5.0 的 `refresh_index.py` 一键刷新）；库接入配置亦由 ops 管理（`library.config.json`，置于 ops 安装目录）
- 无第三方依赖、无脚本、无输出资产（纯检索流程 + 文档）

**缺失降级（三态）**：

1. **库正常、索引过期**（条目变动未刷新索引）→ 标准链路照常，检索结果可能滞后——提示用户跑 `ibd-methods-ops` 的 `refresh_index.py` 刷新
2. **库已建、索引缺失** → 退回 **Grep 全库关键词扫描兜底档**（查得到、token 成本升高）；调用方 `ibd-doc-write` 另有**内嵌流程**（无本 skill 时按其内嵌流程运行），本包缺失不阻断写作链路
3. **库未建 / 配置缺失（冷启动）→ 冷启动引导档**（首次使用必经此态，不再报错中断）：
   - **一问定路径**：向用户确认库根目录（默认建议 `~/methods/`，用户给定即为准）
   - **建空库骨架**：创建 `{METHODS_ROOT}` 目录 + 按 `ibd-methods-ops` methods-guide.md「起步结构」+「§九 空库起步模板」生成骨架（纯结构零内容：`通用方法论_最终版.md` / `方法论调用索引.md` / `方法论_条目标题目录.md`）——**编号唯一性由调用索引全量映射 ＋ 条目标题目录保障**，不再另建编号登记表（该资产已于 2026-09-01 退役迁 archive）
   - **生成最小配置**：写 `library.config.json`（A 档默认：本地目录 + 文件读写 + 自建索引）——schema 单一事实源仍在 ops；下次跑 ops 四问引导时自动认得此配置，不冲突
   - **如实交付本次结果**：「库已就绪但为空 → 本次无命中」；命中需求登记为待沉淀缺口（归 ops 蒸馏域），并提示两条起步路径（methods-guide §五：A 边用边长 / B 蒸馏式积累）
   - **边界**：只建骨架、不造内容——蒸馏生产仍归 `ibd-methods-ops`

纯检索流程零脚本，不存在运行时依赖缺失问题。
