# ibd-quality-gates（IBD 投行交付质量门禁）

投行文档交付前的内容质量把关工具，用于确保文档内容在交付前达到**可信、可溯源、表述克制**的标准。

本技能对文档质量实施全过程管理，覆盖两个环节：

- **开工前（入口）**：任务启动内核——复述任务、识别本任务最大风险、区分已有数据与待补数据，防止理解偏差与内容编造
- **交付前（出口）**：五道质量门（G1-G5）——数字可溯源、判断有依据、无绝对化表述、引用有对照、自评达标

适用范围：分析报告、尽调报告、反馈回复、备忘录等投行文档的内容质量检查。
格式边界：排版样式、标题序号、表格规范等格式问题归 `ibd-doc-review`；金额**文本格式**（千分位/小数位）与数值自洽机械检查归本 skill（check_data.py），金额**呈现格式**（表格内对齐/字号/合计加粗）仍归 review。

## 使用流程

### 1. 任务启动内核（Task Core · 开工前必过）

> 多角色团队的「任务启动内核」章节只保留本角色参数，通用 4 条骨架统一引用本 skill [task-core.md](references/task-core.md)（单用户模式直接按骨架执行即可）。

通用骨架 4 条：**① 先复述再动笔**（1 句话复述任务 + 3 个最大风险 + 明确交付物）→ **② 先加载后动手**（知识库/模板/权威简称/台账，按角色）→ **③ 数据清单二分**（已有/待补，不编造）→ **④ 工具命中即调**（失败按降级执行并披露）。各角色参数表 + 写作 Pre-Flight 8 点 + 归档前置见 [task-core.md](references/task-core.md)。

### 2. 五个模块（每个先一句话说清）

**2.1 数字五要素**

每个数字都要能回答五个问题：**多少**（单位）、**什么时候**（时点）、**哪来的**（来源）、**多精确**（精度）、**跟谁比**（可比口径）。答不全的数字不许留在正文里——要么补全，要么明确标注「待补」。

> 例：`2024 年营业收入 11.20 亿元（来源：发行人 2024 年度审计报告）`——单位"亿元"、时点"2024 年"、来源"审计报告"齐全，合格。
> 反例：`营收 11.2 亿`——哪年的？谁的营收？哪来的数？三个都答不上。

**2.2 反模式扫描**

初稿写完后，照着清单把常见的"投行文档病"过一遍，分四类：**数据类**（无来源、口径混用）、**论证类**（观点没支撑、风险不披露）、**表述类**（AI 腔、套话、堆形容词）、**编造类**（红线，出现即整段作废）。清单见 [antipatterns.md](references/antipatterns.md)。

**2.3 交付前自检（10 条）**

交稿前逐条问自己，一条不过就不交。比如：每个数字都有来源吗？有没有"我认为"？前瞻判断都附了风险提示吗？完整清单见 [rules.md](references/rules.md) §3。

**2.4 质量自评（6 维 30 分）**

给自己的稿子打分：数据准确性、合规性、专业深度、逻辑完整性、风险披露、文笔可读性，每维 5 分。**总分低于 25 分，回炉重写，不交付。** 量表见 [rules.md](references/rules.md) §4。

**2.5 五道质量门（G1-G5）**

最后过五道关卡，全过才算合格：G1 数字五要素门、G2 绝对化清零门、G3 引用可追溯门、G4 来源对照门、G5 自评报告门。定义见 [rules.md](references/rules.md) §5。

> **G6 已移交**：docx 文件完整性检查（officecli validate + view issues）已移交 `ibd-doc-review` S6 补充门禁（见「与 ibd-doc-review 的分工」）——本 skill 不再持有 officecli 能力，只管内容，不管「文件能不能打开」。

### 3. 执行流程

```
初稿完成
  → ① 跑脚本：python scripts/check_gates.py <文件>          （G1 裸数字粗筛 + G2 绝对化/AI 痕迹扫描）
  → ①' 数值自洽机械门：python scripts/check_data.py --input <草稿.md|docx>   （data 组：金额文本格式/数值前后一致/合计勾稽/跨表比对）
       —— G1 管单个数字合法（来源/口径），check_data 管跨位置一致/合计勾稽；md 草稿阶段即可跑（改 md 零排版成本），docx 正式稿复核亦可跑
  → ② 人工过反模式清单（references/antipatterns.md）          （脚本查不了的语义问题）
  → ③ 交付前自检 10 条逐条过
  → ④ 质量自评打分（6 维 30 分）
  → ⑤ 出「质量自评报告」随文档交付
```

### 4. 质量自评报告（交付时附在文末）

```
质量自评报告
- 自评总分：__ /30（数据准确性 _/5 · 合规性 _/5 · 专业深度 _/5 · 逻辑完整性 _/5 · 风险披露 _/5 · 文笔 _/5）
- 质量门状态：G1 __ | G2 __ | G3 __ | G4 __ | G5 __
- 反模式命中：无 / 命中 __ 条已修复（清单）
- 遗留「待补」项：__ 处（位置清单）
```

### 5. 关于 G4（来源对照门）

凡引用了外部资料——研究报告、法规条款、他人观点、方法论条目——都要能回答三个问题：**引了什么、出处编号是什么、用在正文哪个位置**。交付前附一张对照表。

如果你维护自己的方法论索引（如「问题类型 → 条目编号」的映射表），把它放进用户级配置 `~/.config/gates-index.json`（格式：`{"名称": "索引文件路径"}`），G4 会按你的索引核对；没有这个文件就按通用规则人工核对，不影响其他模块使用。

### 工具说明（安装时读 · 每个工具为什么是这个层级）

**🔴 必须 · Python 3**
- 本 skill 规则全内置（数字五要素 / 反模式 / 自检 / 自评 / G1-G5）；check_gates.py + check_data.py 均**仅标准库**（re/zipfile/argparse），零 pip 依赖——装上就能跑

**🟡 推荐 · KB_BACKEND 知识库后端**
- 用途：检索同类案例做对比参考（任务启动内核「先加载后动手」的加载对象）
- 为什么推荐：有同类案例参照，判断更有依据（如「同类案怎么处理过」）；没有则跳过加载步骤，**规则仍全量执行**
- 可选后端：公司内部知识库 / 云文档 / 本地资料库 / 笔记库（功能等价）

**🟡 推荐 · 外部金融数据终端（可选）**
- 用途：数字交叉验证（「数字五要素」的溯源辅助）
- 为什么推荐：验证数字可靠性的权威渠道；没有则依赖文档自身来源标注，靠人工判断

**🟢 可选 · 方法论库 `{METHODS_ROOT}`〔⬛私有本地〕**
- 用途：G4 来源对照门的增强（有方法论索引则「引了什么/出处编号」对照更严）
- 为什么可选：无库按通用规则人工核对，**门禁仍有效**；有库可做精确编号溯源

**🟢 可选 · `ibd-doc-review`〔🔗 外部 skill〕**
- 用途：格式/样式类问题（序号/表格样式/排版）的移交出口；本 skill 的数值一致/勾稽核对已内置于 check_data.py，不依赖 review
- 为什么可选：本 skill 只报内容质量问题、不查排版；有 doc-review 可一键移交样式处理，没有则报告中标注（缺依赖按「断链自助」从其发布渠道安装）

## 与 ibd-doc-review 的分工（先看清边界再用）

| 检查项 | 归属 |
|--------|------|
| 排版样式、标题序号、标点、表格规范 | `ibd-doc-review` |
| 金额**呈现格式**（表格内对齐/字号/合计加粗） | `ibd-doc-review`（table 组） |
| 金额**文本格式**（千分位/小数位）、数值前后一致、跨表勾稽、合计校验 | **本 skill**（check_data.py data 组，md/docx 双载体——md 草稿阶段即可跑，写作前段做数值一致门） |
| 数字有没有来源和口径 | **本 skill** |
| 观点有没有论据、风险有没有披露 | **本 skill** |
| 绝对化用词（"领先/最优/第一"） | **本 skill**（词表本 skill 独有，见资源索引） |
| AI 写作痕迹、套话堆砌 | **本 skill** |
| OpenXML 架构合法性 / 渲染层物理缺陷（文件损坏、文本溢出、公式错误） | `ibd-doc-review`（S6 补充门禁，officecli 驱动；结构底线，非样式规范） |

推荐顺序：初稿（md）→ 本 skill 过内容门禁（G1-G5 + check_data.py 数值一致门，md 即可跑）→ 样式化定稿 → `ibd-doc-review` 查 text/table 组格式 → 交付。
