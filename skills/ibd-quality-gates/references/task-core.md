# 任务启动内核（Task Core）· 单一事实源

> 归属 skill：`ibd-quality-gates`（L1 通用质量层）
> 用途：全团 7 个 agent 收到任务后、动笔/动手前的强制启动检查。
> 引用方式：各 agent MD 的「任务启动内核」章节只保留本角色的参数表，通用骨架一律引用本文件，禁止在 MD 内复制骨架全文。
> 版本：v1.0（2026-08-29 从 6 份 MD 去重提取，用户裁定「铁律全保留，原始内容绝不删除」——历史全文归档于专家包 `_legacy_ipo_names/` 对应档案）。

## 通用骨架（4 条，所有角色必过；任一未过不开始）

1. **先复述再动笔**：用 1 句话复述任务（角色相关要素：项目/板块/范围）；列出本任务 3 个最大质量风险（见下表角色参数）；明确交付物与风格。
2. **先加载后动手**：按角色加载对应的「参考源」（知识库后端同类案例/模板、权威简称、台账快照等，见下表角色参数）；无直接案例再走外部数据源。
3. **数据/文件清单二分**：明确"已有"与"待补"两份清单；缺失处写"待补"并说明需上游/用户提供什么，**不编造**。
4. **工具命中即调**：对照本角色的工具路由表（见各 MD 对应章节），命中 Skill/工具立即调用；工具输出返回前不基于假设继续；失败按各角色降级协议执行并披露。

> 记忆口诀："复述-加载-二分-调工具；输出前自检 + 五要素"。

## 角色特有附加（不通用，保留在对应 MD）

### writer：Pre-Flight 8 点检查单

| # | 检查项 | 通过标准 | 未过处置 |
|---|--------|---------|---------|
| 1 | 任务类型 | 已明确 报告/表格/修订/清单 | 1 句复述向使用者/负责人确认 |
| 2 | 模板已加载 | 已读知识库同类模板 + 000-009 样式 | 返回加载 |
| 3 | 多维专业意见齐备 | 财务/法律/行业等专业意见均已收到原文 | 缺意见→标"待补"，不自行编造 |
| 4 | 数据清单 | 已有/待补两份清单已列出 | 不明确处 AskUserQuestion |
| 5 | 口径对齐 | 财年/单位/币种/主体称谓已统一 | 建立口径对照表 |
| 6 | 风险识别 | 3 个最大质量风险已列出 | 风险不明则暂停 |
| 7 | 输出结构 | 章节/表格/交付物清单已定 | 先列大纲 |
| 8 | 版本同步 | 涉及专家包修改时 plugin.json 版本一致 | 不同步先修复 |

### manager：知识库连接器前置（2026-08-22 新增）

上传前先确认知识库连接器已登录 + 接口版本（按连接器文档的流程执行）；**401 不重试**，读连接器设置文档引导续期；`file_apply_upload` 的 `size` 参数必须=文件实际字节数（否则 PUT 403 SignatureDoesNotMatch）、`upload_type=PRE_SIGNED_URL`；PUT 用 urllib + 显式 Content-Length（Windows 下 curl 反斜杠路径易失败——保留 urllib 为 Windows 铁律）。
