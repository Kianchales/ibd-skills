# Changelog

## [0.3.1] - 2026-10-02

### 出件补齐下游指向：清单结构以 interface §3 为准、落地交 doc-annotate

- **缺陷**：出件段原只写「⇒ 交复核包汇总」，**未点名汇总口文件与落地执行器**——而同属复核线清单产出侧的 `ibd-finance-review` 已在对应章节点名 `ibd-doc-annotate`，**链路声明不对称**（用户不知出件该落到哪个工具）。
- **修法**：出件段补一行——**清单结构与字段以 `ibd-doc-review/references/interface.md` §3 为准**（机器版 `problems.schema.json`）；**落地交 `ibd-doc-annotate`**（批注/修订交付执行器）。
- **定位不变**：仍**只对照、不定性、不自出报告**（四条红线不变）。

## [0.3.0] - 2026-10-02

### 库调用治理：判据来源上提 ＋ 检索预算 ＋ 库对账 ＋ 同构件互指

- **判据本体上提判据集**：立族门槛（**≥3 案例复现**）的**单一事实源**改指 `docs/CONVENTIONS.md` §一「**库↔消费侧的演进判据**」（**判据内容零变更**），本册保留**执行所需简版 ＋ 回指**。动机：该判据此前在**两个消费包各写一遍**（本册族回环 ／ `ibd-finance-review` §3.2），改一处必忘另一处。
- **加「同构件」互指**：标明 `ibd-finance-review` 的维度演进回环与本回环**同构、改动须同批**（未装该包可忽略）。
- **新增「检索预算」**（`families.md` 取例方式节）：查询面限「**已声明 D 域查项对应的族**」／每族**命中 ≥3 条即止**／全文路兜底**仅在族卷读空时启用**、同义词变体宜为个位数／**需跨族时另起一轮**。判据：**预算优先于覆盖率**。
- **新增「库对账」**（`families.md` 巡检回环节 · **零脚本**）：列期望 → 列实况 → 逐条比对（**册有库无 ⇒ 以库为准同步**；**库有册无 ⇒ 登记候选**；卷名不一致 ⇒ 以库卷标题为准）→ 回填。**为何不做脚本**：落消费包会两份重复、落库侧则成跨包耦合。

## [0.2.0] - 2026-10-02

  `蒸馏（ibd-methods-ops）→ 库法律域新增条目／族卷 → 本包巡检比对 → 更新族内快照 或 登记新族候选`。

- **依赖节点名**：方法论库行补「建库／蒸馏／维护 → `ibd-methods-ops`；按问题查库 → `ibd-methods-query`」——**皆缺时按族卷自足路径运行**（仍为 🟡 推荐，**非硬依赖**）。
- `SKILL.md` 维护节补「族与条数回填」条。

## [0.1.1] - 2026-10-01

### 修订：取例表述收掉「方法概念副本」——改为**指针 ＋ 自足降级**

- **动因**：`references/families.md` 原把**检索侧的方法名目**（「双路检索：索引路 ＋ 全文路」）**复述**了一遍，而该概念的**单一事实源在方法论检索能力侧** ⇒ 检索链路一改，本包描述即**静默过期**。裁定依据：跨包约定「**检索能力的共享面 ＝ 规程层、不落建包依赖层**」（单一事实源落 `docs/CONVENTIONS.md` §一）。
- **修法**（三处 · 同一口径）：
  - `references/families.md`「取例方式」② → **指针**（按方法论检索能力定位，**未安装可忽略**）＋ **自足路径**（定位族 → 读该族卷 → 按条目编号取用）；
  - `references/sources.md` L2 惯例行 → 去掉机制名目，改为「其库接入与降级细则**以该能力为准**，**本包不复制**」；
  - `SKILL.md` 四步法 ① → 同步为「方法论检索能力 ＋ **未安装可忽略**（退化为按族卷定向读）」。
- **边界（未变）**：**不新增建包依赖** —— 本包对检索能力仍是**软提示**；取例的**自足降级路径**由 `families.md` 的族→卷路径承担。

## [0.1.0] - 2026-10-01

### 初版：法律惯例对照复核（D 域执行承载）

**定位**：A 股投行文档的**法律惯例对照**——查「同类情形市场上别家怎么写、本稿像不像样」，**只对照、不定性**（法律定性归签字人）。作为格式复核包声明单 **D 域（法律）的执行承载**，与财务域之于财务复核包同构。

**入库件**

- `SKILL.md`：定位／何时使用（触发面 ＋ 与法律分析线的区分）／复核流程（**第 0 步 · 时点匹配** → 进门 → 惯例对照四步法 → 出件）／判定标准（三档 ＋ 人机分层 ＋ 四条红线）／边界／依赖与工具（**三问声明**）／资源索引／踩坑／维护。
- `references/criteria.md`：判定标准唯一事实源——§0 **时点匹配**（先定事实发生时点，取该时点有效版本）／§1 三档（A 明文／B 惯例／C 敏感）／§2 人机分层／§3 **四条红线**（不以措辞论、不引未核实条款、敏感议题禁三类、**版本匹配**）／§4 反例。
- `references/check-items.md`：D 域查项明细——**19 族各一项（D1–D19）＋ 3 项缺口占位（D20–D22，待蒸馏，未填前不勾不提）**；每项四字段（查什么／判据来源／产出形态／档位）。
- `references/families.md`：**19 族索引册**（族号 → 族名 → 案例库卷路径 → 条目数），**只回指针、不复制正文**。
- `references/sources.md`：依据链与法规取用规程——三层依据源（L1 法规／L2 惯例／L3 案例）＋ 各自可得性与降级／L1 **开放后端三档 ＋ 缺失降级三态**／版本纪律／取源障碍与官方源清单／**公布版承诺边界**。
- `scripts/fetch_law.py`：法规原文取件器（**可选加速件**）——官方公开源 URL → 可读 Markdown（含质检：条号非 1→N 连续且中文不足即**不落盘**）；HTML 路径零依赖，PDF 路径需可选依赖 PyMuPDF。

**同批跨包改动**

- `ibd-doc-review` 侧：新增 `references/convention-compare.md`（**惯例对照四步法**，跨域共用件、方法唯一事实源）；`references/check-scope.md` 的 **D 域由「0（预留）」落号为 22 项**（19 现役 ＋ 3 占位），A/B/C/F/S 编号与档位零改动，E 行业域仍为预留。
- 体系侧：本包按**公布包标准**入册（名单两处 ＋ 接入点总表 ＋ 全库数量表述去数字 ＋ 工程范式清单 ＋ 产线视图）。

**说明**：本包**不内置法规原文、不写死任何私有路径**；依据源一律为「开放后端 ＋ 缺失降级」。缺口族（明股实债／无真实交易背景票据·信用证／虚开发票）已有敏感议题门、**尚无对照**，待案例蒸馏后填入。
