# ibd-finance-review（IBD 财务章节深度复核）

A 股 IPO 招股书及申报文件的**财务专业内容复核**执行规范——把投行财务核查框架固化为可复用复核链路，产出可直接落地批注的结构化问题清单。

**What**：按 16 维固定清单（损益循环/资产与投资/报告主体与政策/报表勾稽与披露四组）核查财务章节的收入确认、毛利率、应收/存货、资产减值、现金流勾稽等专业判断与披露质量。
**When**：招股书财务章节复核、反馈回复财务问题核查、单点财务问题审查、跨处数据勾稽专项。

## 何时使用（触发词）

财务复核 / 财务章节审查 / 招股书财务复核 / 财务章节帮我审查 / 收入确认这段帮我看看 / 毛利率核查 / 收入确认审查 / 财务勾稽 / 财务数据前后对不上 / 研发资本化合理吗。

## 使用流程

> 最小复现示例（对话触发 → 核对执行 → 问题清单样例）见 [examples.md](references/examples.md)。

### ① 锁定范围与数据基准

1. 明确复核对象章节与范围（只复核被点名的财务内容，不扩散全篇）。
2. **锁定数据基准**：以审计报告/最新调整后数据为唯一事实源；存在多版数据时先定基准再动手——口径混用是财务复核第一反模式。
3. 确认报告期与币种单位口径，全程统一。

### ② 全量核对登记（范围内零遗漏·铁律）

打开 [execution-discipline.md](references/execution-discipline.md) 执行**全量核对铁律**：复核范围内出现的**每一个财务数字**（报表科目数/指标表数值/分析段引用数/同行对比数/附注明细数）一律纳入核对、逐数登记台账，禁止以「关键/主指标」为由抽样跳过；机械可算项先跑脚本全量扫，人工聚焦脚本扫不了的语义层。每个数先打口径标签再比对——报表列示多为净额（应收账款=账面余额−坏账准备、存货=账面价值），引用/重算前先到附注还原分母三态（**账面余额/账面价值/均值**），防净值当余额（实测教训）；**算式留痕**：凡「已重算一致」必附算式。跨表比对建**正文-表格-附注-审计报告**四方勾稽，口径差异先过 [term-caliber.md](references/term-caliber.md)。需外部过程披露（加权股数/折旧拆分）与缺期初数的项按 A/B/C 三级显式标记，列入交付说明，不默认通过。

### ③ 按维度清单逐项复核

打开 [check-dimensions.md](references/check-dimensions.md)（四组 16 个维度：损益循环与税务 / 资产与投资 / 报告主体与会计政策 / 报表勾稽与披露，每维含核查要点/关注信号/常见问题类型），对每个维度问三件事：**数据齐不齐、口径对不对、披露够不够**。命中关注信号即起草一条问题，不命中不硬凑。对存在监管口径的场景，再对表 [case-signals.md](references/case-signals.md)（监管案例信号库，按维组织）核对实务争议点的既定口径。

### ④ 依据检索（依据先行，防空口判断）

每条问题须能回答「依据是什么」，按序检索：
1. **会计准则与监管口径**：《企业会计准则》具体准则条款、证监会首发业务问答、交易所审核问答
2. **同类案例**：已公开的同类项目问询与回复中该问题的实际处理
3. **可比对标**：毛利率/指标异常时拉同行业可比公司数据对照；解析外部行情数据时**保留单位/币种溯源列并做量级校验**（实测教训：单位错配是高频翻车点）

### ⑤ 汇总问题清单

按 [issue-list-format.md](references/issue-list-format.md) 的字段规范汇总：code（复核人代号+序号）、type（固定 10 类词表）、severity（三档）、anchor（最小可定位句段）、title/description/suggestion。**批注全量覆盖**（执行纪律铁律 2）：高/中/低危问题一律进批注、一个不落，同时清单/台账照常保留并与批注编号一一对应——禁止「只进清单、不批注」；锚点难定位时换策略（长锚/组合短语/唯一数值），确实无法自动锚定才记总览「未锚定」。清单可对接批注工具原位落地（Word 审阅批注 / PDF 高亮），交付 = 批注版原文 + 精简总览（编号一一对应），**只加批注不改原文**。**交付口径**（默认形态「双轨并存、批注优先」/ 触发语路由 / 批注纪律）见 `ibd-doc-review` skill 的 delivery.md——本 skill 只产问题清单，交付形态不另立口径。

### 输出样例（问题清单 → 批注形态）

示例 1（数据·正负号｜高）：

> 【J-01｜数据·正负号｜高】
> 「汇兑净损失」负值实为净收益，方向矛盾
> 问题描述：正文披露「汇兑净损失为 -26.14 万元」，负值表示汇兑收益而非损失，措辞与数值方向矛盾。
> 建议：核对财务报表附注口径后改为「汇兑净收益 26.14 万元」或统一表述为「汇兑损失（收益以负号列示）」。

示例 2（数据·口径｜中）：

> 【J-02｜数据·口径｜中】
> 毛利率对比未说明是否扣运费
> 问题描述：业务与技术章节将毛利率与可比公司对比，未说明运费计入销售费用还是营业成本，口径不可比。
> 建议：补充说明运费会计处理口径，或按可比口径还原后重新对比。

## 依赖与工具

- **零硬依赖**：纯规范 + Markdown，无脚本、无第三方包、无运行环境要求——任何能读 md 的环境即可执行复核
- **可选增强**（有则用、无则跳过，不影响交付）：
  - 数值自洽核对脚本：有则先跑机械检查（金额格式/数值一致/合计勾稽），人工聚焦剩余存疑项
  - 批注/修订工具：问题清单按字段规范产出后可直接对接（Word 审阅批注 / PDF 高亮）；**交付落地链**由 `ibd-doc-annotate` 执行，其依赖 `ibd-doc-review ≥ 0.16.2`（= 交付口径单一事实源 `delivery.md` 的引入版，低于此版该指向成死引用）——缺则本包仍可独立产出清单，仅无法落地为批注版/修订稿
  - 案例/行情数据服务：依据检索第 2/3 顺位的增强来源，缺省按 [integration-and-fallbacks.md](references/integration-and-fallbacks.md) 降级公开源
- 工具性依赖刻意为零：产出物可人工复核、可人工落地，不绑定任何特定工具链
## 边界与协作

### 在审查体系中的位置（三层分工）


投行文档审查按三层分工，本 skill 属第三层：

| 层 | 管什么 | 不管什么 |
|---|---|---|
| 1 格式/结构层 | 序号、日期、标点、表格、排版样式 | 财务含义 |
| 2 通用内容质量层 | 数字可溯源、绝对化表述、反模式、自检门禁 | 财务专业判断 |
| 3 **专业判断层（本 skill）** | **财务口径、勾稽关系、会计处理、披露充分性** | 排版与通用表述 |

每层可独立运行；若工作区另有对应审查 skill，保持问题清单字段一致即可互操作（字段规范见 [issue-list-format.md](references/issue-list-format.md)）。

### 对接声明与替代管理


本 skill **单层公开、完全自足**——不设私有层，不含本机路径/内部知识库标识，整个目录可原样分发。与外部组件协作全部通过**声明**完成：

| 对接点 | 协议声明 | 组件缺失时的替代 |
|---|---|---|
| 复核结论落地 | 问题清单字段/code（J=财务）即为协议，交付 = 批注版原文 + 精简总览（交付口径见 `ibd-doc-review` 的 delivery.md），只加批注不改原文 | 问题清单 markdown 本身即交付物，零工具依赖 |
| 依据检索 | 准则条款 → 同类案例 → 可比对标（前序缺源即降级） | 公开法规为底线依据；无内部案例库用交易所公开问询件；无行情服务用可比公司公开年报数据 + 单位溯源列 |
| 类型词表同步 | 本包 issue-list-format.md 为公开自足版，字段/词表与工作区同源规范保持一致即可互操作 | 独立可用，不依赖外部事实源 |

详细协议与降级路径见 [integration-and-fallbacks.md](references/integration-and-fallbacks.md)。使用方的本机接线（知识库入口、数据服务凭据等）由使用方自行配置，不进本包。
## 维护

每完成一次真实复核，把新遇到的关注信号与问题类型回填 check-dimensions.md 对应维度；新增问题类型须先在 issue-list-format.md 词表登记，禁止复核时自造标签。
