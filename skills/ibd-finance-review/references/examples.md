# 使用示例（examples.md）

> 最小复现示例：对话触发 → 核对执行 → 交付物结构。本包为规范清单型 skill，示例展示复核如何启动与收尾。
> 16 维清单见 [check-dimensions.md](check-dimensions.md)；问题清单字段规则见 [issue-list-format.md](issue-list-format.md)。

## 示例 1：招股书财务章节复核（核心场景）

**用户触发**：「复核招股书『财务报表分析』章的收入与毛利率披露」

**AI 执行链路（节选）**：
1. 加载 16 维清单定位相关维度（损益循环 / 收入确认 / 毛利率口径…）
2. 逐段核对：勾稽（主表↔附注）、口径一致性（收入确认政策 vs 实际拆分）、术语规范
3. 产出结构化问题清单（字段规则见 issue-list-format.md §1）

**清单样例行**：

```json
{
  "code": "J-01",
  "type": "数据·勾稽",
  "severity": "高",
  "anchor": "汇兑净损失为 -26.14 万元",
  "title": "负值实为净收益，方向矛盾",
  "desc": "汇兑损益段落披露 -26.14 万元，按上下文应为净收益 26.14 万元（正数）。",
  "suggestion": "核对财务费用明细后改为「净收益 26.14 万元」或修正表述。"
}
```

> 类型仅取固定词表内值（J/L/I/Z 编号前缀：J=财务 / L=法律 / I=行业 / Z=综合）；锚点为问题句段最小可定位文本，不锚整章。

## 示例 2：复核结论落地（对接交付）

问题清单确认后 → 交 `ibd-doc-annotate` 注入原位批注（Word/PDF）→ 批注版原文 + 精简总览（编号与清单一一对应）。

**执行纪律提示**（见 execution-discipline.md）：确认的问题不分大小全部进批注；同源连锁错合一条，覆盖单元 = 根因问题。
