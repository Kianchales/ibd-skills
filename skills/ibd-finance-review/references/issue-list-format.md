# 复核问题清单字段规范（issue-list-format）

> 复核产出的结构化问题清单字段定义。清单是「复核结论」与「批注/修订落地工具」之间的标准接口：字段保持一致，任何批注工具均可消费。
>
> **字段名与语义源 = `ibd-doc-review/references/interface.md` §3（复核问题清单 schema 结构契约）**，机器可执行版 `problems.schema.json`。本册是面向使用者的公开自足版，**字段名与 §3 逐字一致、不另立口径**；两处若不一致，以 §3 为准并视为本册缺陷即修。

## 1. 条目字段

| 字段 | 规则 | 示例 |
|---|---|---|
| code | 复核人代号（1-2 个大写字母）+ 全局递增序号（01 起） | `J-01`（J=财务、L=法律、I=行业、Z=综合） |
| type | 固定 12 类词表内取值（见 §2），**禁止自造** | `数据·勾稽` |
| sev | 三档（见 §3） | `高` |
| anchor | 问题句段**最小可定位文本**（docx 按段落子串、PDF 按字符匹配），不锚整章整节 | 「汇兑净损失为 -26.14 万元」 |
| title | 问题一句话最小概括 | 负值实为净收益，方向矛盾 |
| desc | 具体矛盾点 + 原文依据 | 正文披露「汇兑净损失为 -26.14 万元」，负值表示收益…… |
| advice | 指令式修改建议（「改为…」「核对…后统一…」） | 核对附注口径后改为「汇兑净收益 26.14 万元」 |
| rev | **可直接粘贴的替换文本**（文本定稿/修订形态用） | 汇兑净收益 26.14 万元 |
| nature | 可选；**问题性质**（**复核报告分页轴**，与 12 类 `type` 不是一套）；推荐五类 ①数据不一致/②表述不一致/③自身逻辑/④格式规范/⑤事实存疑 | `③自身逻辑` |
| line | 可选；被复核文档的**行号或行号区间**（供复核报告列「回复行号」定位） | `340`、`9044-9046` |

> `advice` 与 `rev` **二者至少其一**（`anyOf`）——批注形态给 `advice`；文本定稿/修订形态给 `rev`（此时 `advice` 可省）。**二者皆空 → 入口校验拦截**。

### 1.1 覆盖单元：一条问题 = 一个根因（同源合并）

- **归并单元 = 根因**：清单条目以「根因问题」为最小单元。同源连锁错误（一个错数带出多处衍生错）**合成一条**——anchor 锚源头位置，desc 内联全部衍生位置与数值（如「该错误同时影响（三)2 毛利合计 4,052.80、(三)3 毛利率 11.10%…」），**禁止每条衍生位置单独成条**
- **位置全量由清单/台账兜底**：合并的每个衍生位置须能在逐数台账/复核报告中逐行找到（编号可回溯）——批注按根因覆盖、清单按位置覆盖，双轨各自全量
- **家族子编号（扩展形态）**：同根因但位置跨章过远、单锚无法就近覆盖时，可共享主编号拆分 `J-01a/J-01b`（子条各自锚定一处）；默认推荐 desc 位置内联（批注门禁现兼容），家族拆分需落地工具编号规则扩展（见 ibd-doc-review annotations.md §3）
- **数量卫生**：单文件批注 ≤200 条；>400 拆分交付（细则见 execution-discipline 细则 9）——上限触发时处置是合并/拆分，**不是从清单删条目**（错误不分大小、确认即批注的铁律不破）

## 2. 问题类型词表（固定 12 类）

| 大类 | 类型标签 | 释义/触发场景 |
|---|---|---|
| 数据 | 数据·口径 | 统计口径不清/约数表述/口径不可溯源 |
| 数据 | 数据·勾稽 | 同指标跨处数值不一致、表内勾稽不平 |
| 数据 | 数据·完整性 | 缺年度标注/缺口径说明/披露要素缺失 |
| 数据 | 数据·正负号 | 收益/损失方向与措辞矛盾 |
| 表述 | 表述·绝对化 | 龙头企业/领先/唯一等无依据的绝对表述 |
| 表述 | 表述·衔接 | 表述与上下文/其他章节口径不衔接 |
| 表述 | 表述·歧义 | 指代不明、读者易误读 |
| 披露 | 披露·充分性 | 期后重大事项、风险量化、影响披露不足 |
| 披露 | 披露·时效 | 数据/政策截至时点与披露时点不匹配 |
| 合规 | 合规·一致性 | 与法规/审核要求/申报口径不符 |
| 合规 | **合规·禁用表述** | **禁词表逐字命中**（经核查/核查程序/确保上市/领先全球/全球第一…）——判据单一事实源 `ibd-doc-review/references/banned-terms.json`，**恒「高」**；**文档类型敏感**：行为禁语仅招股书适用，回复件命中不成立 |
| 合规 | **合规·来源限定** | **出处限定违规**——「市场数据只能引自招股书」「回复不得引入新证据（承诺函/新核查程序）」「敏感议题只用品文原文」类越界引用 |

> 新增类型属规范变更：先在本表登记并 bump version，再投入使用；复核执行中不得临时造标签。本表与 `ibd-doc-review/references/annotations.md` §4 **同源同步**（**两册同源、禁单册私改**）。

### 2.1 易混淆类型辨析（选择判据）

相邻类型边界容易选错，按「先分域、再定类」的口诀判定：

**分域**：先问「事实/数字错没错」→ 错 → 数据类；没错 → 看问题出在披露叙述还是规则遵循 → 披露/表述/合规。

| 易混淆对 | 区辨判据 | 自问句 |
|---|---|---|
| 数据·勾稽 vs 数据·口径 | 勾稽 = 同指标跨处**数值不一致**；口径 = 数值一致但**算法/口径没说明**或不可比 | 数字对不上 → 勾稽；说得不清 → 口径 |
| 数据·完整性 vs 披露·充分性 | 完整性 = **数字要素缺失**（缺年度/期间/口径标注）；充分性 = **风险/影响叙述不足**（该说的定性内容没说） | 缺的是数字要素 → 完整性；缺的是风险叙述 → 充分性 |
| 数据·口径 vs 合规·一致性 | 口径 = 披露层没说明白；合规·一致性 = **做法本身违反准则/监管要求** | 只是没说清 → 口径；做法不合规 → 合规·一致性 |
| 表述·衔接 vs 表述·歧义 | 衔接 = 与上下文/其他章节**口径冲突**（跨处不一致）；歧义 = 单句**局部指代不明**、可多种理解 | 与其他处打架 → 衔接；单独读不懂 → 歧义 |
| 表述·绝对化 vs 合规·一致性 | 绝对化 = **用词无依据**（领先/唯一/龙头）；合规·一致性 = 行为/口径与规则不符 | 说得太满 → 绝对化；做得不合规 → 合规·一致性 |
| 表述·绝对化 vs 合规·禁用表述 | 绝对化 = 依赖**判断**「有无依据」（弹性、可论证）；禁用表述 = **逐字命中禁词表**（硬规则、恒「高」） | 命中词表逐字 → 禁用表述；词表外的同义夸大 → 绝对化 |
| 合规·禁用表述 vs 合规·来源限定 | 禁用表述 = **用词**违规；来源限定 = **引用出处**违规（引了不该引的材料/引入了新证据） | 词不能说 → 禁用表述；东西不能引 → 来源限定 |

> 选错类型不改变问题本身，但会破坏批注链路的类型统计与门禁判定——拿不准时优先选更保守的一侧（披露层 < 规则层），并在 desc 里写明实际矛盾点。**硬规则优先**：凡逐字命中 `banned-terms.json` 或触发出处限定条款者，一律按上两行归类，不得降格为弹性类型。

## 3. 严重度三档

| 档 | 判据 | 处理 |
|---|---|---|
| **高** | 事实错误/口径错误/合规错误（必改） | 阻断交付，必须修复或明确豁免理由 |
| **中** | 披露充分性、表述规范（应改） | 默认修复，可随批次处理 |
| **低** | 完整性、衔接、可读性（建议改） | 择机处理 |

**升档规则（双维度定档 · 取高者）**：定档不只看**错误性质**，还看**监管后果**（无后果／问询风险／否决风险）。

- **硬性升档**：① `合规·禁用表述`／`合规·来源限定` → **恒「高」**；② 涉及**审核关注点**（持续经营、减值、收入确认、关联交易、控制权、资金占用…）的**披露充分性问题** → 升「**高**」。
- **判据**：严重度的功能是决定**处置优先级**。「数学上没错但披露不充分即被问询」属**必改**——如减值计提比例区间的原因说明不充分，事实无错，档位不得停在「中」。
- 本规则与 `ibd-doc-review/references/annotations.md` §4 同源同步。

## 4. 清单交付要求

- 编号一次性分配登记，与**复核报告**条目一一对应（同一编号互相回溯）
- 无法自动锚定的条目：不硬注，在批注总览（中间件）单列「待人工定位」
- 交付形态 = 批注版原文（第一交付物）+ **复核报告（Excel，按问题性质分表）**——规格 → `ibd-doc-review/references/delivery.md` §八之二；批注总览 md 为**中间件**（不交付用户）
- 修订稿（直接改好原文）仅在用户明确要求时另行执行，与批注同源同一份清单

## 5. 批注正文结构（对接渲染时的约定）

每条批注正文固定 4 行、无空行，引导词加粗承担分界：

```
【J-01｜数据·正负号｜高】               ← 标签行（加粗）
问题一句话概括                           ← 标题行（加粗）
问题描述：具体矛盾点/原文依据……          ← 仅「问题描述：」加粗
建议：指令式修改建议……                   ← 仅「建议：」加粗
```
