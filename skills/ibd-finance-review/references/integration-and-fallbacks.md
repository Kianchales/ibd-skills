# 对接声明与替代管理（Integration & fallbacks）

> 本 skill **单层公开、完全自足**：整个目录可原样分发，不内置任何本机私有配置，不要求外部组件存在。
> 与外部组件的协作一律通过**文档内声明**完成——本节声明每条对接协议与可选的增强来源；
> 对应组件缺失时按「替代方案」降级，本 skill 功能不受损。

## 1. 复核结论交付（对接协议）

问题清单的字段与编号设计本身就是对接协议，任何消费方按字段读取即可，无需改造：

| 协议点 | 约定（详见 issue-list-format.md） | 对接方动作 |
|---|---|---|
| 字段 | code / type / sev / anchor / title / desc / advice（或 `rev`） | 按字段消费；锚点最小可定位句段 |
| 复核人代号 | J=财务、L=法律、I=行业、Z=综合（前缀进 code） | 多专业复核时按代号分流汇总 |
| 交付形态 | 批注版原文 + 复核报告（Excel，按问题性质分表；编号一一对应）；**只加批注，不改原文** | 支持 Word 审阅批注或 PDF 高亮的批注工具均可落地 |

- **有批注/门禁体系时**：问题清单直接对接——docx → Word 审阅批注，PDF → 高亮弹注；数值自洽类机械检查脚本先跑，人工聚焦剩余存疑项；走修订流程时先确认形态（修订留痕 / 直接改好 / 双版）。
- **没有时**：问题清单 markdown 本身即是交付物，零工具依赖。

## 2. 依据检索（证据链路径，缺源即降级）

每条问题须能回答「依据是什么」，按序检索；前一顺位不可用即降级到下一顺位：

| 顺位 | 来源类型 | 缺失时替代 |
|---|---|---|
| 1 | 《企业会计准则》具体准则条款、证监会/交易所审核问答（**公开法规**） | 无——公开法规是底线依据，任何环境可获取 |
| 2 | **同类案例**（两级）：① **先查方法论库财务域**（已蒸馏的同类案例：规则要点 ＋ 多案实证 ＋ 适用场景，按卷组织）→ ② 再取**公开原文核验**（已公开项目的问询与回复） | 无库 → 直接查交易所公开披露的问询函件与回复（**功能等价，仅定位效率差**）；**引用一律回源**，不复述库内页码 |
| 3 | 可比对标：毛利率/指标异常时拉同行可比数据 | 无行情数据服务 → 用可比公司年报/招股书**公开财务数据**人工摘录；解析外部数据必须**保留单位/币种溯源列并做量级校验**（单位错配是高频翻车点） |

**机械勾稽执行（范围含表格数据时的可选增强）**：工作区若有面向**一手表格**的勾稽引擎（读 `xls/xlsx/csv/pdf`、自动跑四步勾稽并出差异表），可先跑它取机械层结论，人工聚焦语义层；**无该工具时按本包 [articulation-checks.md](articulation-checks.md) 的算式、方向约定与容差判据人工复算**——算式判据以本册为**单一事实源**，引擎结果与之不一致时以本册为准（口径重叠时的分工声明见 `SKILL.md` 边界与协作节）。

### 2.1 检索预算（防无界查询）

| 项 | 预算 | 理由 |
|---|---|---|
| **查询面** | 只查**本次已声明查项**对应的维度；**不遍历全库** | 复核是**定向**的，不是普查 |
| **每维命中即止** | 命中 **≥3 条**相关条目即够（惯例通常在 3 案内收敛）；不足 3 条则读满该卷 | 与「加维判据 ≥3 复现」同源 |
| **全文路兜底** | **仅在索引路无匹配时启用**；同义词／别名变体**宜为个位数**；命中即止 | 承上游 `ibd-methods-query` 的双路纪律 |
| **需跨维时** | **另起一轮**，不在同轮内顺手扩大面 | 防「顺便都查一遍」 |

> **为何要定预算**：大库下全文路兜底可能**无界** ⇒ 查得越多、结果越不聚焦。**预算优先于覆盖率**。

## 3. 演进与同步

### 3.1 维度演进的输入源：方法论的蒸馏产物（**回环**）

**本包 16 维不是静态清单**——它的主要更新源是**方法论库的蒸馏产物**（库财务域**按卷组织、卷名即复核维度**）：

```
蒸馏（ibd-methods-ops）→ 库财务域新增条目 / 新增卷 → 本包巡检比对 → 回填对应维度 或 登记新维度候选
```

**巡检动作**（每次蒸馏入库后，或复核开工前顺手做一次）：

| 情形 | 动作 | 落点 |
|---|---|---|
| 新条目落在**现有 16 维**内 | 提取其「规则要点 ＋ 关注信号」→ 回填该维的**核查要点／关注信号** | [check-dimensions.md](check-dimensions.md) 对应维度 |
| 库出现**16 维之外**的新卷 | 登记「**新维度候选**」，**不直接加维**（先攒复现） | 本册 §3.2 |
| 冒出新的**问题类型标签**需求 | 先在词表登记，**禁止复核时自造标签** | [issue-list-format.md](issue-list-format.md) §2 |
| 新关注信号（无论来源） | 回填对应维度 | [check-dimensions.md](check-dimensions.md) |

> **软依赖**：巡检读库需 `ibd-methods-query`（检索通道）；库的**生产与维护**归 `ibd-methods-ops`；**两者皆缺时**本包仍按 §2 原路径独立运行，功能不受损。

### 3.2 新维度候选（攒复现 · 未达门槛不加维）

| 候选维度 | 来源（蒸馏批次／卷） | 复现次数 | 状态 |
|---|---|---|---|
| —（暂无） | | | |

> **加维判据**（**单一事实源** → `docs/CONVENTIONS.md` §一「**库↔消费侧的演进判据**」）：同一候选在 **≥3 个不同案例**中复现，且现有 16 维确实容纳不下 ⇒ 升为第 17 维并同步四组分组序；**未达门槛只登记候选，不直接加维**。
> ⚠️ **同构件**：`ibd-legal-review` 的「**族演进回环**」与本回环**同构**（那边是 19 族）——**改动须同批**（未安装该包时忽略本行，不影响本包运行）。

### 3.3 库对账（巡检动作 · **零脚本**）

**为什么不做脚本**：对账要同时读「**本册的维 ↔ 卷对应表**」与「**库的卷目录**」——脚本落**消费包**会两份重复、落**库侧**则成跨包耦合（本包**不假定**库侧有该脚本）。故落成**动作**，用现成工具即可：

1. **列期望** —— §3.1 的「维 ↔ 库卷」对应关系；
2. **列实况** —— 列出 `{METHODS_ROOT}` 财务域目录下的卷文件；
3. **逐条比对**：
   - **册有、库无** ⇒ 卷被改名或移除 ⇒ **以库为准**同步本册；
   - **库有、册无** ⇒ **新卷** ⇒ 登记「新维度候选」（§3.2）；
   - **卷名不一致** ⇒ **以库卷标题为准**；
4. **回填**本册的对应关系表（条目数快照随之更新，**仅供规模参考、不作用据**）。

### 3.4 其他同步约定

- 若工作区既有词表／格式规范与本包同源（字段、类型词表一致），保持同步维护即可；本包词表为**公开自足版**，独立可用

## 边界：本 skill 不含什么

- 无本机路径、无内部知识库标识、无内部项目名、无数据服务凭据——目录内无任何分发前需剔除的内容
- 使用方的本机接线（知识库入口、数据服务凭据、内部规范位置）由使用方自行配置，不进 skill 包
- 内部案例库 / 内部行情服务在公开版中一律表述为「可选增强来源」，非必需依赖

## 为什么采用此模型

- **单层维护**：只有一份公开内容，发布即整包，无「打包排除/私有目录」心智负担
- **声明驱动**：对接方看到协议即可互操作；替代路径保证任何环境下都能独立交付复核结论
- **天然过发布门禁**：全目录可扫、零私有引用，隐私/外部引用/依赖来源门禁一键通过
