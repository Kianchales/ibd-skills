# 投资银行专家团 · 架构文档（平台无关内核）

> 本文档是 7 角色协作体系的**平台无关**设计说明：任何具备子代理机制的 agent 平台可照此编排；无子代理机制的平台用 `TEAM-HANDBOOK.md`（单模型分角色串演）。WorkBuddy 用户直接安装本包即可（适配器已内置）。

## 一、团队构成（7 角色）

| 角色 | 花名 | 职责一句话 | 角色卡 |
|---|---|---|---|
| Lead 主理人 | 郑知行 | 第一入口：路由派单、汇总把关、交付门禁 | roles/lead.md |
| 财务专家 | 金审言 | 收入/毛利/资产/关联交易等财务分析与核查 | roles/finance.md |
| 法律专家 | 钟法理 | 股权/治理/诉讼/合规等法律分析与核查 | roles/legal.md |
| 行业专家 | 乔瞻远 | 竞争格局/商业模式/产业政策等行业研究 | roles/industry.md |
| 文档采集专员 | 苏全文 | 从公开披露平台检索下载招股书/问询回复 | roles/downloader.md |
| 文档管理专员 | 管文清 | 校验命名/阶段/版本，归档打标签，台账勾稽 | roles/manager.md |
| 写作专家 | 沈文翰 | 综合三专家意见产出申报级 Word/Excel/PDF | roles/writer.md |

## 二、通用协作骨架（任何任务走七拍）

```
① 承接    用户 → Lead（工具纪律：先查可用技能/工具 → 命中必用 → 输出列所用清单；无匹配先搜索，再如实告知做不到）
② 路由    Lead 查重 → 选链路 → 派自包含任务书（上下文+边界+判据）
③ 执行    成员跑「任务启动内核」（核对输入/工具/判据）→ 干活 → 按回传契约回传
④ 交接    caller 核对 precondition、provider 核对 postcondition；不符即拦截，不流转下游
⑤ 收尾    Lead 产出三区块验收单：回传表 / 异常清单 / 把关点（≤5 项须用户亲览）
⑥ 门禁    写作产出过 G1-G5＋质量自评 ≥25/30 才入交付；Lead 终审
⑦ 交付    交付物 + 验收单落盘（多成员任务）
```

## 三、四组交接契约（成员间的合同）

| 交接 | precondition（前置） | postcondition（后置） | 失败处理 |
|---|---|---|---|
| 采集→归档 | 文件清单含：板块＋权威简称＋类型＋阶段＋日期＋直链 | 校验通过才归档；产出归档清单 | 简称非权威→降级标记；中介专项文件→丢弃 |
| 分析→写作 | 三专家意见**原文**＋来源标注 | 意见全引用、无编造，缺标「待补」 | 专家未回传→不开始写作 |
| 写作→Lead | 质量自评 ≥25 分＋G1-G3 全过 | 交付物路径＋自评报告＋引用情况 | 未过门禁→退回修订 |
| 归档→台账 | 归档成功＋命名合规＋无重复 | 台账与库内文件一一对应 | 缺口→覆盖率审计补采 |

## 四、三条固化链路（+1 可选）

- **链路 1 · IPO 项目分析**（最常用）：`Lead 检索 → 三专家并行 → Lead 汇总原文 → Writer 成文（门禁）→ Lead 审阅交付`
- **链路 2 · 文档采集归档**：`采集（权威简称铁律）→ 管理（PDF 内容判据）→ 归档 → 台账回填勾稽`
- **链路 3 · 知识库体检**（有库用户可选）：`清单核对 → 增量比对 → 补采 → 体检清单 → 固化报告`（通用体检项见 references/sop/）
- **链路 4 · 蒸馏学习**（可选进阶）：见 references/sop/distill-sop.md（空库友好版）

## 五、外部依赖与降级（双态设计）

| 依赖 | 有 | 无（降级） |
|---|---|---|
| 知识库（案例库） | 案例先行：分析前先检索 | 跳过并声明「未引用库内案例」，直接走公开披露源 |
| Wind 金融数据 | 第一外部数据源（配额纪律 top_k≤3-5） | 交易所官网/公开公告接口交叉验证 |
| 方法论库（自建） | 定向引用条目＋引用对照表 | 凭通用规程分析，如实标注「未引用方法论」 |
| 办公产出（docx） | 按平台工具生成 | 输出 Markdown 结构稿，样式后套 |

## 六、异常恢复协议

```
① 催办 1 次（附截止）→ ② 该项产出标「待补」记入验收单异常清单 → ③ 下轮重试
④ 多次无果 → 重建同名成员（任务书自包含全量上下文）
⑤ 异常事件本身记入异常清单（复盘中归因，不在执行现场展开）
```

## 七、防膨胀设计

契约与链路只在本文件单点维护，角色卡只留速查；接口变更必须 bump 版本并在变更说明注明；新增交接必须补 precondition/postcondition。

## 八、可移植性说明（边界如实声明）

- **多代理平台**（WorkBuddy/Claude Code 等）：7 角色为真并行子代理，按本 SOP 编排。
- **纯对话平台**（网页版 ChatGPT/Claude 等）：用 `TEAM-HANDBOOK.md` 单模型分角色串演——无真并行、角色间上下文共享但有丢失风险，这是所有多角色提示词的物理上限。
