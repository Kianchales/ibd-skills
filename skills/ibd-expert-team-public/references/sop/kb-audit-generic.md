# 知识库体检 SOP（通用版 · 链路 3）

> 适用：任何「文档库＋台账」结构的 IPO 案例库（知识库平台或本地目录皆可）。执行者：文档管理专员＋Lead 把关。触发：定期体检（如每周）或用户要求全库体检。

## 体检清单（10 项）

1. **增量比对**：外部权威源（交易所披露）与库内清单 diff，新受理/状态变更/新文档三类差异
2. **覆盖率缺口**：在审项目应有目录 vs 实际目录，缺失即补采候选
3. **命名合规**：目录与文件名 100% 符合命名规则（`[板块]_[权威简称]`；问询回复带轮次）；权威性用 Wind title/交易所详情页核验
4. **简称权威性**：`short_name` 来源应为权威源；发现非权威来源且与库内目录不一致 → 查是否已确认过权威简称，确认则固化覆盖表而非仅改快照
5. **空目录审计**：空目录＝子项为空列表（注意与「无子项字段」区分）；空目录→补采
6. **重复文件**：同名聚合＋内容哈希确认；同目录同名≠一定重复（同日多轮），删除前内容验证＋二次确认
7. **缺失检测**：台账有记录但库内无实体 → 补采；以库内实际文件为准，不信台账单方
8. **中介文件混入**：标题含会所/律师特征词的开卷验证，混入即清理（删除前进内容二次确认）
9. **指针有效性**：台账/索引中的引用 ID 或路径逐个可解析；失效 → 以实际文件为准判定漏采
10. **固化报告**：体检结果写结构化报告（JSON/MD）＋错误类型归类（采集类/归档类/裁定类），修复方案回流对应角色卡

## 铁律

- diff 基线必须用上一次快照，禁「当场重抓当基线」
- 新受理判定必须交叉核对受理日期与更新日期（多年前受理无近期动态=历史项目状态回退，非真实新增）
- 同一公司更换外部代码（代码迁移）会造成「消失+新增」双误报——先按公司全称比对再判定
- 体检发现的错误模式沉淀进对应角色卡「失败模式」栏，循环改进
