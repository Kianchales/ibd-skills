# README — 库使用手册

> 给 AI 的操作手册：**任何新会话 / 新设备先读本文件**，按「⚡ 三秒速览」接续。
> 维护：**低频**——仅体系结构 / 规则变更时顺手更新，不专门维护；日常记录走 AI 工作日志（做了什么）+ 待办看板（还要做什么）

---

## ⚡ 三秒速览（必读）

| 问题 | 答案 |
|---|---|
| 这是什么库 | 个人工作台记忆库（本机文件夹，可放在同步盘实现多端同步） |
| AI 的职责 | **记**（工作日志）＋**管**（待办）＋**读**（状态）——三件事，规则都在本文件 |
| 接续顺序 | 本文件 → `04 AI Work/工作日志/YYYY-MM-待办.md`（做了什么；已办结节迁在同目录 `YYYY-MM-办结.md`）→ `04 AI Work/待办事项.md`（还要做什么） |
| 日志 / 待办唯一写点 | `04 AI Work/工作日志/YYYY-MM-待办.md`（Tasks 语法、按性质分类，见 §二） |
| 手机 / 对话加待办 | 说「给<项目>加待办：…」即可，摘要见 §五（完整规则内联于 skill `ibd-life-manager`） |
| 动手前必扫 | **§六 踩坑清单**（path includes 不加引号等，全是实测血泪） |
| 不懂先查 | **§七 参考资源**（官方文档优先；给用户解释必须中文） |

## 一、库结构（写哪）

```
Home.md                ← 仪表盘 + 周期按钮（📅 今日日报 / 📆 本周周报 / 🗓️ 本月月报）
01 资料/               ← 私人资料区（AI 不介入）
02 工作/               ← 01 任务（团队任务 / 视图）/ 02 项目（01 进行中 / 02 待开始 / 03 已完成 / 04 模板）
03 报告/               ← 01 日报（含 01 日报.base 数据库）/ 02 周报 / 03 月报 / 04 模板
04 AI Work/            ← 工作日志/（YYYY-MM-待办.md 当月活跃区 + YYYY-MM-办结.md 已办结归档 + 工作日志.md 仪表盘）+ 待办事项.md（看板）+ AI资料库/（AI 沉淀资料处：研究 / 学习笔记长期留存）+ 临时文件/（暂存 md 唯一落点：待处理暂存件读取处 + 生成 / 中间产出件写入处）；跨机交接单直接放本层（YYYYMMDD_主题.md），办完即删
README.md              ← 本文件
```

> ⚠️ 上述目录名（`01 资料` / `02 工作` / `03 报告` / `04 AI Work` 等）**被库内各查询语句按字面路径引用**，请**勿改名**；改名会导致 dataview / Tasks 查询全部失效。

## 二、工作日志铁律（怎么写）

**长什么样**（Obsidian Tasks 语法）：

- 做了什么：`- [x] 标题 ✅ YYYY-MM-DD #性质`
- 还需要做什么：`- [ ] 标题 #性质`（**默认不带日期**；有明确截止日期才写 `📅 YYYY-MM-DD`，须为**绝对日期**）
- **一天一节** `## YYYY-MM-DD`（同一天不开子章节）；节内两段 `### ✅ 已完成` / `### ⏳ 待办`；任务行＝标题＋结论（≤30 字），细节下沉缩进子行；行尾必带性质标签
- 完成勾选后**保留 ✅ 不删除**（铁律全保留）

**归档**：**节级**——节内**零未完成** 且 距今 **≥7 天** 时，整节迁入同目录 `YYYY-MM-办结.md`（原文零改动、节序升序；全月零未完成则整月文件更名）。**每次读日志 / 查待办都要顺带跑一次归档检查**，不等专门指示、不留待下次。

> ⚙️ **执行细则以 skill `ibd-life-manager` 为准**（唯一事实源）：同日节的写入锚点、跨日销项的就地标记、子行两类例外、「不按行切」的完整理由、三重守恒校验——**本节只列「照做能上手」的摘要，不复述条文**；变更时改该 skill，本处只同步摘要。

**分类体系**（示例，可按自己的业务改；改名须同步改 `04 AI Work/待办事项.md` 的查询）：

| 标签 | 涵盖 |
|---|---|
| `#体系搭建` | 库 / 工作流 / 自动化 / 插件 / 记忆体系 |
| `#skill开发` | skill / 自动化脚本 / 发布 |
| `#文档写作` | 报告 / 材料 / 方案 |
| `#项目跟进` | 具体项目推进 |
| `#研究学习` | 法规 / 行业 / 专题研究 |
| `#其他` | 兜底 |

## 三、接续入口（读哪）

| 目的 | 读 |
|---|---|
| 当前机有什么能力 | `04 AI Work/` 下的本机环境说明（**多机使用者自建**，可选） |
| 最近做了什么 | `04 AI Work/工作日志/YYYY-MM-待办.md`（当月完成记录；更早的已办结节在同目录 `YYYY-MM-办结.md`） |
| 还需要做什么 | `04 AI Work/待办事项.md`（按性质分类的未完成待办，AI 按此干活） |

## 四、日报系统（只读理解，AI 不写日报）

四区块（模板 `03 报告/04 模板/日报模板.md`）：

| 区块 | 查询 |
|---|---|
| ↑ TOP TASK | `due before 明日` + `priority is high` + `path includes 02 工作` |
| ✓ COMPLETED TODAY | `done date is 今日` + `path includes 02 工作` |
| ◧ Intention | **纯手写日记区**（无查询） |
| ◔ AI WORK LOG | `done date is 今日` + `path includes 04 AI Work/工作日志` |

- 日报数据库 `01 日报.base`：filters 用 `file.hasTag("Periodic/daily-note")`，views 为 table——`.base` 本质是 YAML
- **值流定位**：日报 = 原始记录（不总结）→ 周报 / 月报 = 日报的总结
- **AI 边界**：日报——AI **不补建、不代写**；整理（归拢 / 补结构）由使用者**单独发起**，不自动化。周报 / 月报——**总结正文**可由 AI **起草 → 使用者确认 → 落盘**（数据源＝日报 `◔ AI WORK LOG` ＋ `04 AI Work/工作日志`）；其余区块一律不碰（含 `◧ Intention` 手写区）

## 五、写入通道与待办位置（怎么执行）

**通道**（按优先级）：

1. **Obsidian CLI**：`"<Obsidian 安装目录>/Obsidian.com" vault="<你的库名>" <命令>`（files / read / move）——**需 Obsidian 桌面端正在运行**（走本地通道）
2. **文件系统直连**：库根文件夹（CLI 不可用时兜底）

**待办写哪**：

| 任务 | 落点 |
|---|---|
| 一切项目待办（无论谁做） | `02 工作/02 项目/01 进行中/<项目>/待办事项.md`——**唯一写入点**（项目不存在则按模板建） |
| 团队任务 `<人名>.md` | `02 工作/01 任务/团队任务/`——**仅成员工作量统计视图，不是写入点**，AI 不往这里写 |
| AI 自身待办 / 日志 | `04 AI Work/工作日志/YYYY-MM-待办.md` |

- **对话 / 手机快速加待办**：说「给<项目>加待办：…」即触发（任何端、任何会话通用）。要点＝写进该项目 `待办事项.md`、**负责人写在 `### 人名` 标题下**（团队统计靠 `heading includes 人名` 跨项目聚合，写进事项文字就不聚合）、**默认不带日期**、回执即止不跟踪
- **边界铁律**：`02 工作/` 是使用者业务跟踪区，AI 工作日志**不跟踪、不汇总、不催办、不引用**其中的手动待办；AI 只记录 / 跟踪自己（`04 AI Work/`）的事，两边互不干涉

> ⚙️ **完整规则以 skill `ibd-life-manager`「待办写入三路径」为准**（7 条快速加待办、章节归属、语法细节）；本节不复述条文。

**项目文件夹长什么样**（模板 `02 工作/02 项目/04 模板/`，整夹复制改名即用）：

```
<项目名>/
├── <项目名>.md        项目面板（frontmatter 与 tags 见模板）
├── 待办事项.md        唯一任务写入点
├── 已完成归档.md      单文件持续追加
├── 工作进程.md        一项目一个，append-only，一天一节
├── 注意事项.md        持续更新型要点（固定名）
├── 纪要/              纪要模板.md + YYYY-MM-DD <主题>纪要.md
└── 资料/              可选轻量附件；正式底稿 / 大文件留库外
```

- 命名：持续更新型固定名不带日期；快照型（纪要）日期＋主题开头
- 完结迁移：整夹 `01 进行中` → `03 已完成` 平移 ＋ 面板状态改「已完成」，内部结构不动
- **字段与查询口径以 skill `ibd-life-manager`「项目文件夹标准结构」为准**（本节不复述，避免两处漂移）

**完成习惯**：划掉保留 ＋ 追加新状态（`- [ ] ~~旧事项~~，新状态`），不硬删历史。

## 六、踩坑清单（动手前必扫，全是实测）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **Tasks `path includes` 加引号** → 当成带引号字面路径，永远匹配不到 | 参数**不加引号**：`path includes 04 AI Work/工作日志` |
| 2 | **`not (...)` 布尔内嵌引号** → 报「Combinations of those delimiters」 | 排除用原生 `path does not include X`（也不加引号） |
| 3 | **Iconize 图标映射写 `icons` 字段** → 插件不读，图标全不显示 | 映射在 data.json **顶层键**（`"路径": "图标ID"`）；图标名用 `RiXXXLine`（remix） |
| 4 | **改图标配置与改目录名分开做** → 插件中途重载会清理失效键 | 一气呵成：先改名再写配置，或写完立即验证 |
| 5 | **Buttons `action` 填命令 ID** → not found | 填「插件显示名: 命令显示名」（如 `Periodic Notes: Open daily note`） |
| 6 | **CLI 报错 / 无输出** → Obsidian 桌面端没在运行 | 先确认 Obsidian 进程存在；CLI 只认真实运行实例 |
| 7 | **同步盘中间态窗口** → 刚写完的文件可能读到旧版 | 读同步区文件前先**静止采样**：间隔数秒比对 `mtime` / `size` 一致后再据内容判断 |
| 8 | **Obsidian linter 会格式化文件** → 改完内容被重排 | 写后重读再改；格式化插件会动表格 / 空白 |
| 9 | **workspace.json 里的旧文件名残留** | 无害，Obsidian 下次启动自动刷新，勿手改 |
