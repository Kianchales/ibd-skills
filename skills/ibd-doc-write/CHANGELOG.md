## [0.11.0] - 2026-09-10

### 修复：语言范式链路断裂 —— 库内 474 条语言句式此前仅被引用 0.4%（功能级 Y+1）

- **问题实证**（用户指出：「我在蒸馏时已经做了相关内容的提取，但我发现 write 压根没用上」）：
  - 方法论库回复语言专项文件现有 **474 条**语言句式（115 KB）＋ **41 份**单案写作范式（3.47 MB）
  - **write 三个 references 实际引用的语言域编号仅 2 条 → 覆盖率 0.4%**
  - 索引侧早已就绪：方法论调用索引含语言域编号 **433 行**，其中 **418 行带 Q 域标注（96.5%）**
  - → **不是缺资产、不是缺索引，是链路没接**
- **断点定位**：五步链路 ②③ 查的是「业务方法论」（F- 财务／L- 法律／I- 行业域），**语言被压缩到 ④ 一步**且指向 skill 内静态 `writing-style.md`；依赖表又把「方法论检索」标为 🟡 可选、降级路径明说可跳过 → 474 条资产永远进不了写作现场
- **修复**：
  - **④ 步改为「取语言范式（与 ②③ 同源检索 · 必做）」**——沿用 ② 已定位的 Q 域，从索引取该 Q 下的语言域条目 → 行号定位定向读 → 套用；语言与业务方法论**同一次检索取得**
  - **`writing-style.md` 降为兜底**（无库/无检索时降级用），文件头加显式声明，防「只读它就动手」
  - **新增单案范式入口**：写具体项目时先查该案/同类案的单案写作范式——此前 3.47 MB 资产**无任何消费路径**
  - **⑤ G4 清单扩围**：语言域条目的引用须一并列入（证明句式取自库、非臆造）
  - **依赖定位修正**：方法论库 + 检索由「🟡 推荐（可选）」改为「🔴 必须（有条件）」——无库仍可写作，但明确标注为降级档位（「能写、但不地道」）

## [0.10.0] - 2026-09-10

### 功能：接入交付门禁 `deliver_gate.py` —— 文字规范门禁前移 + 交付前综合核验（功能级 Y+1）

- **流程新增两步**（`### 3. 格式落地串联` 流程图）：
  - **①'' 文字规范机械门（必跑 · 套样式之前）**：`ibd-doc-review scripts/deliver_gate.py --md <草稿.md> [--anchors "36,507.55;19.96"]` —— md 侧预检五项（标点全半角 / 禁用词红线 / 占位符 / 锚点计数 / 文档结构），PASS 只输出一行
    - **动机**：标点全半角虽属格式项，**返工成本却落在文字层**——拖到套样式之后才发现，改文字会导致样式重做（实测 384 处半角引号漏到套样式之后才被抓出，白跑一轮样式）
  - **④ 交付前综合核验（交付件全套九项）**：`deliver_gate.py --docx <交付件.docx> --md <草稿.md> --expect-vmerge N` —— 一次跑完、exit 0/1 即交付判据；原「④ check_content 格式核对」降为 ④'（可选）
- **依赖下限提升**：`ibd-doc-review` **≥0.15.0 → ≥0.15.7**（`deliver_gate.py` 为 0.15.7 新增）；依赖表 / 依赖声明 / 工具说明三处同步，并写明 review < 0.15.7 时的降级路径（手工自查标点 + `check_content.py --checks text`）
- **边界与协作新增「格式门禁前移」条**：内容定稿后必须先跑 `--md` 再套样式
