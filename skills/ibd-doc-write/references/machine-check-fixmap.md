# 机检 FAIL 换写表与复核 SOP

> 适用：`ibd-quality-gates` 的 `check_gates.py` 判 FAIL（G1 黑名单词 / G2 绝对化）。
> 由来：2026-10-18 四案重蒸中，三份 writer 稿曾自报「黑名单 0 命中」但实测 FAIL（综合成文 error 8／PL 4／S 3），根因是只跑了自建扫描、未跑机检脚本，且自述句把黑名单词抄进了正文。

## 一、判定口径（唯一可信指标）

**唯一判定依据是脚本实测**：`verdict=PASS` 且 `error=0`。自建正则扫描的结果**不得**作为「已通过」的依据。

```bash
python <skills>/ibd-quality-gates/scripts/check_gates.py <文件>          # 人读
python <skills>/ibd-quality-gates/scripts/check_gates.py <文件> --json   # 机读（取 verdict/error/warn/issues）
```

## 二、换写表（实测命中词 → 投行替代表述）

| 命中词 | 替换建议 | 说明 |
|---|---|---|
| 闭环 | 收口／完整链条／衔接／链条 | 投行常用但被列入 AI 痕迹词表；按语境分取，如「三段闭环」→「三段衔接」、「整改闭环族」→「整改收口族」 |
| 对齐 | 比对／校核／折算 | 同上 |
| 综上／综上所述 | **引文内保留原句**，同行挂来源标记；**自述收束句**改为「因此／据此／可见」 | 见 §三 三态复核 |
| 沉淀 | 成果／归集 | 「纪律沉淀」→「纪律归集」 |
| 抓手／赋能／底层逻辑／颗粒度 | 切入点／支持／原理／细化程度 | — |
| 值得注意的是 | 直接删去，或改「需注意」「另需说明」 | 多为多余过渡语 |

## 三、三态复核（PASS 不等于引文合规）

`warn` 项按引文标记状态分三档处理，**不得只为压 error 而改写原文**：

| 状态 | 表现 | 处置 |
|---|---|---|
| 已挂标记 | 行内含「引自原文／来源／据／援引」＋页码 | 保持原文，warn 可接受（人工确认项） |
| 未挂标记 | 行内含「综上」等原句，但无来源标记 | **补标记，不改原句**——改了属引文失真 |
| 自述句 | 行内自己陈述「黑名单词 0 命中」并**枚举词面** | **必须改**：只写「机检 0 命中」或列 wordlist 文件名，不列词 |

> 注意：标记集含单字「据」，行内出现「数据／依据」会自动降级 → **不能只看 warn 数判断引文是否合规**。

## 四、两个反复踩的陷阱

1. **自述句陷阱**：在正文写「全文无『显著／明显／领先』等词」——这行本身命中全部列举词，一行可贡献 6 个 HIGH。正确写法：引用 wordlist **文件名**，或只写「机检 0 命中」。
2. **过度改写陷阱**：「第一节 释义」这类**照录原文的节名**不必改成「第 1 节」——词表无裸「第一」，只有「行业第一／国内第一／全球第一」这类复合词。属引文的表述改了反而失真。

## 五、批量复核（多稿同批时）

```python
# 逐件取实测 verdict/error/warn，禁止只看一份
issues=[i for i in j['issues'] if i['level']=='HIGH']
# 输出 行号 + 命中词 + 原文行，形成修件清单再派回 writer
```

**纪律**：writer 自报与机检冲突时，以机检为准；修件清单须给到**行号＋命中词＋原文片段**，否则 writer 会凭印象改。
