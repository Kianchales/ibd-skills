# 上下文管理 · 失败降级 · 输出格式

> 适用：🟢 通用（所有文档类型）
> 归属：ibd-doc-write

## 上下文管理规则（长任务）

1. **任务清单显性化**：复杂文档用 TaskCreate/TaskUpdate/TaskList 维护；每完成一个章节标记完成。
2. **阶段性复述**：每完成 2-3 个章节，向使用者/负责人 1-2 句复述进度。
3. **分支确认**：重大分支（新增章节/换模板/扩范围）先 AskUserQuestion，不替用户决定。
4. **信息密度控制**：单条回复 ≤70 行正文（不含表格）；能用表格不用段落；表格后 1-2 句解读。
5. **长文档连贯性**：每完成 3 节建立"术语对照表"；核对关键指标跨节一致；>20 页或 8 节采用**分章节交付策略**（每章产出确认后再下一章，最终全文一致性复核）。
6. **多文件口径统一**：Word+Excel 同时交付时，首文件建立"跨文件术语与数据口径对照表"。

## 失败降级协议（文档生成）

| 失败场景 | 立即动作 | 交付物披露要求 |
|---------|---------|--------------|
| Word 生成 skill 报错 | 换备选（tencent-docx ↔ tencent-local-office-edit 手动 OOXML） | 注明降级方案与格式合规复核提示 |
| Excel 生成 skill 报错 | 换备选（sheetagent ↔ tencent-local-office-edit） | 注明降级方案 |
| 多维专业意见缺失 | 标"待补"，不编造；向使用者/负责人催办 | 报告中注明"XX 维度待专家补充" |
| 数据缺失 | 不编造，写"待补"+说明需提供什么 | 文末"待客户/上游提供资料清单" |
| 长文档质量衰减 | 分章节交付 + 跨节术语/数据对照 | 最终全文一致性复核声明 |
| 自检/门禁未过 | 返回对应环节修复重跑 | 门禁结果摘要（G1-G4 状态） |
| 排版引擎异常 | 尝试 tencent-local-office-edit 或输出 Markdown | 注明"因排版引擎异常采用备选方案，格式合规性须人工复核" |

**核心原则**：绝不因工具失败降低质量标准；降级必须披露；给使用者/负责人明确下一步。

## 输出格式（交付声明）

```
## 文档生成完成：[文档类型] - [项目名称]

### 文档信息
- 类型：[Word报告/Excel表格]
- 文件名：[文件名]
- 本地路径：[文件路径]
- 页数/行数：[X页/X行]

### 内容概要
- 涵盖章节：[章节列表]
- 数据来源：[专家意见 + 知识库案例 + Wind数据]
- 关键结论：[1-3句话概述]

### 专家意见引用情况
- 财务专家意见：[已引用/部分引用/未引用] - [说明]
- 法律专家意见：[已引用/部分引用/未引用] - [说明]
- 行业专家意见：[已引用/部分引用/未引用] - [说明]
```
