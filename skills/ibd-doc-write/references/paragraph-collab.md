# 逐段协作模式（人机协作载体核心流程）

> 本 skill = 方法论载体 + 人机协作框架，**逐段协作、非 AI 独立成稿**。
> 本文件是逐段写作模式的操作规程：**接活分层 → 骨架 → 口径 → 案例素材 → 段前注入 → 敏感识别 → 段中草拟 → 段后自检 → 交付四件套 → 用户复核定稿 → 状态更新**。
> 适用：招股书章节 / 问询回复定稿 / 盈利预测说明等长文档逐段推进场景。整篇委托场景仍走 SKILL.md 主流程（1-3）。

## -1. 写前分层（接活与前置属性 · 2026-09-29 流程框定）

写作委托动手前，先分清**两层属性**——层数不同，确认方式不同：

### 层一：文档类型（项目级 · 定一次管全程）

- **判据**：本项目当前在写什么——招股书章节 / 问询回复 / 报告 / 备忘录。
- **确认方式**：项目首次写作委托时判定一次；**项目内所有后续写作/改稿委托沿用，不再问**；**换项目 ⇒ 重新判定**；同一项目切换文档类型（如回复定稿后回头写招股书章节）⇒ 更新并声明。
- 类型决定：骨架（本文件 §0.1）、样式集、禁词作用域、数据基准默认（§0.2）。

### 层二：动作判定（委托级 · 每次按句段标）

- **判据**：本委托对既有内容做什么。**混合形态高频**（同一段里保持＋改写＋新增并存），不做「新写/改稿」二选一，按**句段逐个标记**：

| 动作 | 判据 | 处理 |
|---|---|---|
| **保持** | 该段沿用原文不动 | 不处理（动作清单中列出即可） |
| **改写** | 按新口径/新要求重写既有段 | 先走读稿净化（探测修订/批注→取终稿，**原件零改动**），再重写 |
| **新增** | 补写不存在的段 | 直接起草 |
| **删除** | 整段去掉 | 动作清单标注，不产出文本 |

- **动作清单**：改稿/混合委托，动手前先给清单（段号×动作×一句说明）——**先声明再动手**，与复核线声明单同哲学。

### 层三补遗：写作线与复核线的分岔

意图是「产出内容」→ 写作线（本文件）；意图是「检查内容」→ `ibd-doc-review` 复核线。分岔词：「写/改/起草/补充」vs「看看/核对/查/研究」；判不清反问一句。

## 0.1 写作骨架（不确认 · 直接取用）

- **规则**：AI 按**文档类型＋问型族**直接从方法库取跨案蒸馏的结构模板动笔，**不设骨架确认环节、不出结构表请示**——结构纠偏后置：用户看到初稿后对结构不满，直接说，当次修改＋该问型族后续沿用新结构。
- **问型族**（问询回复类目的沿用与纠偏单位）：**财务信息披露类**（重表格对比，核查可简化）／**收入真实性核查类**（完整四段式不可简化）／**法律类**（条款锚定规则—事实—结论，中介分主体）／**行业业务类**（递进论证＋市场数据表）。
- 招股书章节：按章节取既有结构模板（概览 11 模块 / 业务与技术 12 模块等，→ [doc-structures.md](doc-structures.md)）。
- **板块体例识别**：动笔前识别科创板/创业板/北交所体例差异（勾选式 vs 否定式单句、专属模块），选对模板用——是写作动作，非核查动作（北交所格式核查归北交所自身插件，本 skill 不做）。

## 0.2 内容口径（写前锁定 · 用户主场）

- **数据基准按文档类型默认**：写招股书 ⇒ 默认**审计报告版**；写问询回复 ⇒ 默认**招股书版**（回复围绕招股书已披露数据作说明，引用口径必须与招股书一致）。**例外用户点名切换**（「这段用底稿调整后的数」），点名即生效并全程锁定。与复核线 S4 门同源。
- **新指标取数口径**：无先例时按合理判断写＋正文显式标注口径，**动笔前不打断**。
- **表述方向**：指令说了照办；没说按库内同型案惯例写（纠偏后置，同 §0.1 哲学）。
- **敏感边界**：命中敏感词族 → §2 识别即停协议，只用品文原文、不加核查程序、不用承诺函。
- **口径与待核清单（交付必附）**：每次写作交付，正文后附清单——①新指标的口径判断依据 ②待用户拍板的点 ③引用的案例编号（methods 编号）。＝写作线的「报告头」。
- **审改倾向记忆＝项目级**：用户对初稿的审改倾向（措辞偏好如「显著→较高」、详略取舍）同项目内后续起草沿用；**换项目清零**，不跨项目带。硬伤提醒义务不变：数字对不上/准则引用错 → 举手一次，用户坚持即定稿。

## 0. 写作状态文件（双文件分层 + 漂移检测协议）

逐段写作跨多轮、跨多会话，维护两个**项目级**状态文件（放项目工作区目录——**不进 skill、不进方法论库**，属项目资产）：

| 文件 | 内容 | 读写权限 |
|---|---|---|
| `{项目}_口径卡.md` | 全部口径裁定 + 特殊禁令；每条带状态（✅生效 / ⏳待确认 / 🚫失效保留）；记录**源文件指针 + 版本指纹（日期/哈希）**，**不抄数字本体** | 用户裁定生效；AI 记录新候选（⏳），用户确认后转 ✅ |
| `{项目}_写作进度.md` | 每段一行：段号 / 类型 / 状态（草拟·复核中·定稿）/ 疑点余留 | append-only，AI 维护 |

- 每轮开始 AI 从磁盘读**口径卡全量 + 进度尾部**；用户无需粘贴状态文件，仅在口径变化时口头说明，AI 记录后提请确认
- 口径卡头与进度头**互相指针**防走散
- 分层理由：口径裁定 = 低频、高险、需留痕；进度 = 高频、可追加——读写权限天然分离

### 口径漂移检测协议（源文件更新时触发）

> 原则：**口径卡记录裁定而非数据快照**——源文件更新 ≠ 可以静默改内容。数字不复制进卡（自检时直接读源文件），卡里只记「哪个文件、哪个版本、按什么规则用」。

1. **触发**：每轮自检核对源文件版本指纹，不符即停
2. **分支 A · 规则不变（数据更新）**：更新指纹 → 输出**数字差异清单（旧值→新值）+ 受影响段落标注（含已定稿段）** → 回改范围由用户裁定（全改 / 只改未交段 / 暂不动）
3. **分支 B · 规则变更（新口径）**：旧条目标「失效（日期）」**保留原文**；新条目 ⏳ 待用户确认 → 生效后输出**影响面分级清单**（未写段 / 草稿段 / 已定稿段），逐段处置由用户裁定
4. **铁律：修订留痕**——旧条目永不删除，可回溯「当时为何这么写」；与「用户裁定冲突提请再裁定」同构

> 为什么不静默改：口径全变意味着已定稿段落可能整批作废——静默更新会让用户拿着按旧口径写的稿子却以为它还是对的，这是最危险的不一致。

## 1. 段前：输入包标准

用户每轮提供的输入包，标准四项：

1. **前文已定稿段**（衔接用，末尾 1-2 段即可）
2. **本段数据口径**（源文件 + 口径裁定，如「盈利预测按 PDF 调整数据 + Excel 底层逻辑，忽略招股书原始数据」）
3. **本段类型**（业务技术 / 募投 / 问询回复…）
4. **本段特殊指令**（如「本段不得出现核查程序」）

- **缺项处置**：缺口径**必问**（口径错全段白写），缺其余按默认推进
- **口径冲突停问**：输入口径与原文 / 前文矛盾 → **停下问，不硬写**；仅当矛盾明显为原文笔误时按给定口径写 + 标注

## 2. 敏感问题启动协议（硬规则）

命中敏感词族——**识别即停，不先行书写**：

1. AI 识别本段命中 → 停笔，报「本段涉及 X 类敏感问题」
2. 等用户定性结论，定性后按下述约束执行：**只用品文原文、不外加核查程序、不使用承诺函等新证据点、陈述事实不评价性论证**
3. 敏感词族（随实战持续迭代）：明股实债 / 无真实交易背景票据 / 信用证 / 内部交易虚开发票 / 对赌 / 同业竞争 / 社保公积金…

## 3. 段中：草拟与多版本

- **默认单版** + 疑点标注【待确认】
- **出 2-3 版 + 表格对比**的触发：敏感段 / 口径复杂段 / 用户明说要选项
- 版本对比表固定四维：**措辞强度 / 信息量 / 监管风险 / 与前文衔接**

## 4. 段后自检（中档默认）

| 档位 | 范围 | 触发 |
|---|---|---|
| 轻 | 禁词 + 口径一致 | — |
| **中（默认）** | 轻 + 数字五要素 + 与前文数字勾稽 + 中文不留空格（中英／中数） | 每段默认 |
| 重 | 中 + 逐字比对 + 跨段核对（四合一全量） | 用户说「严检」；逐字比对仍以 doc-review 复核为主 |

## 5. 交付形态与四件套

### 5.0 交付形态默认值：对话内纯文本，不出文件

**默认只返回文本**——不生成／不更新 Word 文件、不跑样式落地、不跑交付门禁。走文档链路（套样式 ＋ `deliver_gate`）**仅当用户明确要求出文件时**（「出个 Word」）或**整章大稿**触发。每次交付（无论何种形态）**文末必附口径与待核清单**（§0.2）。

| 子场景 | 触发 | 交付内容 |
|---|---|---|
| **起草型** | 用户按 §1 给输入包（AI 草拟新段） | 草稿段 ＋ 下方四件套 |
| **改稿型** | 用户**直接粘贴自己已写好的段落**要求修改 | **修改后文本定稿 ＋ 逐条修改点清单（改前→改后）**；仍附疑点清单与自检一行 |

- **依据**：用户原话「我的需求是我粘贴给你，你帮我直接修改，不需要再给我返回 word 了」
- **理由**：逐段粘贴—逐段改稿的节奏下，**中间态出文件是纯开销**——样式落地与交付门禁只在「定稿要交付」时才有意义；每轮都出 Word 会把改稿节奏拖成文档工程
- **不因此降质**：改稿型仍须过 §2 敏感即停、§4 中档自检；四件套的「疑点清单／自检一行」照附，不因不出文件而省略

### 5.1 交付四件套

每段交付固定附，缺一可打回：

1. **正文段**（改稿型 ＝ 修改后文本定稿；或版本对比表）
2. **数据来源标注**（每个数字：出自哪个文件哪张表）
3. **疑点清单**（拿不准的标【待确认】）
4. **自检结果一行**（档位 + PASS 与否）

## 6. 复核与定稿

- 用户复核（可走 doc-review 四合一：逐字比对 / 跨段核对 / 表述诊断 / 逐句优化）
- 定稿 → 段落状态更新进 `{项目}_写作进度.md`；疑点余留未清的定稿段须在进度中标记
- 返工 → 按「否」分支回到本文件 §3/§4 对应环节，进度状态标「复核中」

## 7. 演进与维护（文档类型拆分判据）

- **拆分提示门槛 = 同一文档类型跨项目/案例复现 ≥3 次**（原讨论 2 次过松，提高至 3 次防过早碎片化）。复现不足 3 次的新类型一律用本文件规程 + 通用结构兜底，反复口头补充的要点记入该项目的口径卡，**不主动建议建新 references**
- 达线拆分时：SKILL.md §1 路由表加行 + 新建 `references/<类型>.md` + 触发词/templates-map/README 三同步，常规升版收尾
- 与方法论库的蒸馏阈值（复现 2 次并入）**相互独立**：本条只管 skill 结构层，管不到 methods 库

## 0.0 协作模式路由（由 SKILL.md §0 下沉 · 先选模式再写作）

| 模式 | 适用场景 | 流程 |
|---|---|---|
| **逐段协作（默认推荐）** | 长文档逐段推进（招股书章节 / 问询回复定稿 / 盈利预测说明等）、口径敏感、需用户逐段把关 | 本文件全文——状态双文件（口径卡/进度）→ 段前输入包 → 敏感识别即停 → 草拟/多版本 → 中档自检 → 交付四件套 → 复核定稿 |
| **改稿协作（粘贴即改）** | 用户**直接粘贴自己写好的段落**要求修改 | 同逐段协作，但**只返文本定稿 ＋ 逐条修改点（改前→改后）**——**不出 Word、不跑样式落地与门禁**（用户说了要文件才走文档链路）。详见本文件 §5.0 |
| 整篇委托 | 短文档 / 结构成熟 / 用户一次性交办 | 走 SKILL.md 主流程 1-3（文档类型路由 → 五步链路 → 格式落地串联） |
