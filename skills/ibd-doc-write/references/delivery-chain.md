# 交付链路与通道详规（delivery-chain.md）

> 适用：🟢 通用——所有文档类型写完草稿后都要走的本段链路。
> 归属：ibd-doc-write。本册承载 **SKILL.md §3（格式落地串联）／「依赖与工具」中闸门与通道细节／「与内置文件操作层（L2）的接口」** 的详规；SKILL.md 只留步骤名 ＋ 一句话判据 ＋ 本册指针。

## 1. 格式落地串联（SKILL.md §3 详规 · 写作完成后必做）

> **本 skill 只产出内容草稿**；样式落地与格式核对一律走 `ibd-doc-review`（格式层单一事实源，本 skill 不重复维护格式细节）。
> **顺序规则：内容质量校验在前、格式落地在后**——内容未定稿不套样式，改稿成本最低。

```
草稿完成
  → ① ibd-quality-gates 内容质量校验（草稿阶段：数字五要素 / 反模式 / G1-G5，md 即可跑）
  → ①' 数值自洽机械门：ibd-quality-gates scripts/check_data.py --input <草稿.md|docx>
       （md 载体即可跑——金额文本格式 / 数值前后一致 / 表格合计勾稽 / 跨表比对；
         此刻改的是 md，零排版成本；docx 正式稿复核亦可跑）
  → ①'' 文字规范机械门（**必跑 · 套样式之前**）：
       ibd-doc-review scripts/deliver_gate.py --md <草稿.md> [--anchors "36,507.55;19.96"]
       （md 侧预检五项：标点全半角 / 禁用词红线 / 占位符 / 锚点计数 / 文档结构；PASS 只输出一行）
       ⚠️ 为什么必须卡在这一步：标点全半角虽是格式项，**返工成本却落在文字层**——
          若拖到套样式之后才发现，改文字将导致样式重做（实测 384 处半角引号白跑一轮样式）
  → ② 声明样式场景（招股书版 / 反馈回复版）
  → ③ ibd-doc-review 套样式（其 assets/templates/ 为使用源）→ 其 check_styles.py 校验
  → ④ 交付前综合核验（交付件全套九项，exit 0/1 即判据）：
       ibd-doc-review scripts/deliver_gate.py --docx <交付件.docx> --md <草稿.md> --expect-vmerge N
  → ④'（可选）ibd-doc-review check_content 格式核对（text/table 组依赖样式化 docx，套样式后跑）
  → ⑤ 交付（附样式应用声明，使用者/负责人最终确认）
```

**格式门禁前移（2026-09-10 固化）**：内容定稿后**必须先跑 `deliver_gate.py --md` 再套样式**——标点全半角虽是格式项，返工成本却落在文字层（套样式后再改文字 = 样式重做）。实测一份交付件 384 处半角引号漏到套样式之后才被发现，白跑一轮样式；同类问题（全角框号/引号、禁用词、锚点缺失）都能在 md 阶段一次拦下。

## 2. 工具说明（安装时读 · 每个工具为什么是这个层级）

**🔴 必须 · `ibd-quality-gates`（内容+数值校验）〔🔗 外部依赖·断链自助，≥0.7.0〕**
- 用途：内容质量校验（数字五要素 / 反模式 / G1-G5）+ 数值自洽核对（`ibd-quality-gates` 的 check_data.py，md/docx 双载体）
- 为什么必须：流程 ①/①' 的检查主体，**没有它内容不过门就进排版，问题回头改成本高**（md 阶段改零排版成本）

**🔴 必须 · `ibd-doc-review`（格式层）〔🔗 外部依赖·断链自助，≥0.15.7〕**（下限登记 → `references/interface.md` §6）
- 用途：给草稿套投行标准样式（招股书 000-009 / 反馈回复版）+ 格式校验 + **交付门禁 `deliver_gate.py`**
- 为什么必须：本 skill 只产出内容草稿，样式落地与格式核对全靠它；**没有它交付物只能是未排版文档**，无法通过投行格式审查
- `deliver_gate.py` 的两种模式直接嵌进本 skill 流程：`--md`（①'' 套样式**前**预检：标点全半角/禁用词/占位符/锚点/结构）与 `--docx`（④ 交付件全套九项，exit 0/1 即判据）。**review < 0.15.7 时无此脚本**，两步降级为「手工自查标点全半角 + `check_content.py --checks text`」

**🔴 必须 · `tencent-docx`〔🟦内置〕 / `minimax-docx`〔🟨官方市场〕（docx 生成，二选一）**
- 用途：生成/编辑 Word 文档（minimax-docx 还能把模板样式套到已有文档）
- 为什么必须：docx 成品的唯一产出通道；**没有它只能输出 Markdown**，交付物需人工转 Word

**🔴 必须（有条件） · 方法论库 `{METHODS_ROOT}`〔⬛私有本地，自建〕**
- 用途：按问题域索引的经验知识库——五步链路 ②③ 的查询对象（「这题以前怎么答得好」）
- 为什么必须：**语言范式与业务方法论均取自该库**（W 系列回复句式、P 系列招股书语言范式、单案范式三路；条数随蒸馏升版，以库内索引标注为准）；G4 引用自检的溯源核心。**无库只能走降级档位**（凭 skill 内精选句法库，属「能写、但不地道」），有库后须回到标准链路
- 建立方式：见 `methods-guide.md`（边用边长，积累 10-20 条后体验质变）

**🟡 推荐 · Wind 数据**
- 用途：可比公司对标、行业数据、公告检索（反馈回复的数据支撑）
- 为什么推荐：数据权威性，**避免「编数字」风险**；没有则用招股书/公开披露数据，质量略降但可用

**🟡 推荐 · `sheetagent`（Excel）**
- 用途：财务对比表 / IPO 核对表生成（仅 Excel 文档场景）
- 为什么推荐：Excel 产出的标准通道；没有则表格改用 Markdown 或手工制作

**🟢 可选 · KB_BACKEND 知识库后端**
- 用途：检索同类案例（写作范式参考）+ 存取模板/方法论归档
- 为什么可选：有则写作有「范例参照」；**没有则靠高频句法库 + 方法论库，仅少案例锚点**，不影响主线
- 可选后端：公司内部 Wiki / 云文档 / 本地目录（功能等价）

## 3. 依赖声明（断链自助 + 版本下限 · 由 SKILL.md「依赖与工具」下沉）

> **本 skill 离开多角色团队也能独立运作**——团队协作只是可选增强，不是前置条件。
>
> `ibd-quality-gates`（≥0.7.0，内容+数值自洽校验）与 `ibd-doc-review`（**≥0.15.7**，样式落地 + text/table 格式核对 + `deliver_gate.py` 交付门禁；**下限登记 → `references/interface.md` §6**）均为外部依赖，**不随本包携带**——安装本技能后须自行另装（获取途径 = GitHub 发布渠道：Kianchales/ibd-skills 集合仓库 `skills/` 子目录，与获取本技能同一来源）。缺 gates 则内容/数值校验不可用，缺 review 则样式落地与格式核对不可用（断链），写作只能产出未过校验的草稿；补装对应依赖后即可完整运行。**review < 0.15.7 时 `deliver_gate.py` 不存在**（①'' 与 ④ 两步不可跑），此时降级为「手工自查标点全半角 + 跑 check_content.py --checks text」。格式规范以 review 为准、质量规则以 gates 为准，本 skill 不重复维护。版本下限 = 当前已验证版本，任一依赖升版后须复核并同步。

**知识库后端（KB_BACKEND）**：下文「知识库后端」字样均指「你配置的检索/存取环境」——公司内部 Wiki / 云文档 / 本地目录任一均可，功能等价（检索同类案例、存模板、存方法论归档）。

## 4. 与内置文件操作层（L2）的接口（由 SKILL.md 同名节下沉）

> 依据 ADR-0020（产物型任务两层路由模型）。

本包是**产物型入口**（L1 作业层）——管「文档类产物的活该怎么做」；**落到哪个工具执行归内置 `tencent-docs-routing`（L2）**：

| 情形 | 由谁做 |
|---|---|
| 通道选择（`tencent-docx`／`local-office-edit`／`minimax-docx`／`officecli` 等） | **归 L2**；本包不自行分派、不覆盖其分支 |
| **任务性质判定与表述整形** | **本包**——把任务判清并表述成 L2 认得的形态（「新建文档」vs「编辑既有文档」vs「整篇美化」），使其落到正确通道 |
| docx 工具的首选与降级序 | **ADR-0014**（L2.5 层）；本包依赖表按 🔴🟡🟢 分层标注，与之一致 |

**为什么写明**：此前本包与 L2 的衔接是**隐性的**，每次都要临场判断「该走哪条」——这正是 ADR-0014 点出的成本（「同一件事多入口的真实成本是每次重新判断用哪个」）。同批 `ibd-excel-ops` 按同一口径写明接口。

## 5. 边界与协作详规（由 SKILL.md「边界与协作」下沉）

- **上游开放**：`ibd-doc-review` 是格式层公共服务，**不限于本 skill 接入**——人工撰写、其他 AI 流程、外部导入的 Word 文档均可直接调用它套样式 / 格式核对；外部产出也可从上述任意环节接入
- **本 skill 产出可交其他复核**：内容草稿除走 doc-review 格式落地外，也可交 `ibd-quality-gates`（内容质量校验：数字五要素 / 反模式 / G1-G5）或用户指定复核方审查；本 skill 不做格式与质量的最终定夺，最终判定归使用者/负责人
