# ibd-doc-write（IBD 投行文档写作）

A股 IPO 投行文档写作总入口。**定位 = 人机协作载体**（逐段协作、非 AI 独立成稿——AI 草拟、用户逐段裁定定稿），且**方法论强制引用、不引用即打回**。

> **详规在册**：每一步的详规都在 `references/` 对应册的对应节——本文件只留**步骤名 ＋ 一句话判据 ＋ 册指针**（判据与方法分离，避免同一内容两处维护）。
## 何时使用

- 写审核问询反馈回复 / 回复报告（「写XX的反馈回复」「起草问询回复」）
- 写招股书章节 / 分析报告 / 尽调报告 / 备忘录（「写招股书」「写尽调报告」「写备忘录」）
- **逐段协作写长文档**（「逐段写」「逐段协作」——招股书章节 / 问询回复定稿 / 盈利预测说明等）
- 做财务对比表 / IPO 项目核对表（Excel）
## 使用流程

> 最小复现示例（对话触发 → 执行链路 → 交付物结构）见 [examples.md](references/examples.md)。

### 0. 协作模式路由（先选模式再写作）

| 模式 | 判据（一句话） | 详规 |
|---|---|---|
| **逐段协作（默认推荐）** | 长文档逐段推进（招股书章节 / 问询回复定稿 / 盈利预测说明等）、口径敏感、需用户逐段把关 | [paragraph-collab.md](references/paragraph-collab.md)——状态双文件（口径卡/进度）→ 段前输入包 → 敏感识别即停 → 草拟/多版本 → 中档自检 → 交付四件套 → 复核定稿；**路由表全文**见 §0.0 |
| **改稿协作（粘贴即改）** | 用户**直接粘贴自己写好的段落**要求修改 | 同逐段协作，但**只返文本定稿 ＋ 逐条修改点（改前→改后）**——**不出 Word、不跑样式落地与门禁**（用户说了要文件才走文档链路）；详见 [paragraph-collab.md](references/paragraph-collab.md) §5.0 |

### 2. 五步强制调用链路（反馈回复专用 · 缺一步即不合格）

> **所有文档类型均须走方法论调用链路**（回复／招股书／报告／备忘录一致）——差别仅在第 ②③ 步查什么：回复查业务问题域、招股书查章节体例与披露口径；**不存在"可跳过方法论"的文档类型**。链路全文见 [response-chain.md](references/response-chain.md) §五步链路。

| 步 | 动作 | 判据（一句话） | 详规 |
|---|---|---|---|
| **⓪** 方法论版本感知 | 读 `{METHODS_ROOT}/通用方法论_最终版.md` 头部版本指引行 | 凡引用方法论必做——本次引用一律以当前 vN 为准，⑤ 对照表标注「依据方法论点 vN」 | [response-chain.md](references/response-chain.md) §五步链路 |
| **①** 拆问询问题 | 把每个问询问题拆解为方法论主题（收入确认/毛利率/对赌清理/实控人/客户集中/募投产能消化等） | 每个问题都能归到一个方法论主题 | 同上 |
| **②** 查映射索引 | 打开 `{METHODS_ROOT}/方法论调用索引.md` → 速查表找 Q 编号 → 全量映射表查该 Q 下条目 | 命中 Q 域；**未命中 → 提示使用者「暂无对应条目」→ 标记待沉淀 → 跳③ 继续④** | 同上 ＋ §第 ② 步补充·跨域桥接 |
| **③** 定向读方法论 | **行号定位**（条目标题目录含「行号」列，用 Read offset/limit 精准读条目正文） | 读到条目正文，不全文翻找 | [response-chain.md](references/response-chain.md) §五步链路 |
| **④** 取语言范式（**与 ②③ 同源检索 · 必做**） | 沿用 ② 已定位的 Q 域取该域语言条目 → 行号定向读 → 套用句式 | 句式取自库、非臆造（W／P 系列**按文档类型分流**） | [response-chain.md](references/response-chain.md) §语言范式取用 |
| **⑤** G4 引用清单自检 | 交付前生成「问询问题类型→方法论条目编号→使用位置」对照表 | 对照表非空且编号实际用于正文；**④ 步取用的语言条目须一并列入** | [response-chain.md](references/response-chain.md) §G4 引用自检 |

### 3. 格式落地串联（写作完成后必做 · 先审内容后定格式）

> **本 skill 只产出内容草稿**；样式落地与格式核对一律走 `ibd-doc-review`（格式层单一事实源，本 skill 不重复维护格式细节）。**顺序规则：内容质量校验在前、格式落地在后**——内容未定稿不套样式，改稿成本最低。

| 步 | 动作 | 判据（一句话） |
|---|---|---|
| **①** 内容质量校验 | `ibd-quality-gates` 内容质量校验（草稿阶段：数字五要素 / 反模式 / G1-G5，md 即可跑） | 内容不过门不进排版（md 阶段改零排版成本） |
| **①'** 数值自洽机械门 | `ibd-quality-gates check_data.py --input <草稿.md｜docx>` | 金额文本格式 / 数值前后一致 / 表格合计勾稽 / 跨表比对全过 |
| **①''** 文字规范机械门（**必跑 · 套样式之前**） | `ibd-doc-review deliver_gate.py --md <草稿.md> [--anchors "36,507.55;19.96"]` | md 侧预检五项（标点全半角/禁用词/占位符/锚点计数/文档结构）PASS 才进 ② |
| **②** 声明样式场景 | 招股书版 / 反馈回复版 | 场景声明在先，套样式在后 |
| **③** 套样式 | `ibd-doc-review` 套样式（其 assets/templates/ 为使用源）→ 其 check_styles.py 校验 | 样式校验通过 |
| **④** 交付前综合核验 | `ibd-doc-review deliver_gate.py --docx <交付件.docx> --md <草稿.md> --expect-vmerge N` | 交付件全套九项，**exit 0/1 即判据** |
| **④'**（可选）格式核对 | `ibd-doc-review check_content`（text/table 组依赖样式化 docx，套样式后跑） | 套样式后才跑 |
| **⑤** 交付 | 附样式应用声明 | 使用者/负责人最终确认 |

> 各步命令全文、「为什么必须卡在 ①''」、「review < 0.15.7 时的降级做法」→ [delivery-chain.md](references/delivery-chain.md) §1。

### 4. 协作模式（可选 · 团队增强）

> 单用户模式**不需要本节**——直接按上述流程写作即可。以下仅为「多角色协作」时的增强说明。

- 团队模式：TeamCreate → 多维专家并行分析（财务/法律/行业）→ 写作角色综合成文 → 负责人按 G4 引用清单自检
- 综合成文时：按本 skill 路由（反馈回复走五步链路）+ 投行语言写作规范 + 回查原文补齐数据（**不能只写框架，每个结论要配表格数据/合同条款原文/页码**）

### G4 引用自检（使用者/负责人核对）

- 交付必须附「问询问题类型→方法论条目编号（`域-族号2位-族内4位`，如 F-010001 / WL-010001）→使用位置」对照表
- **未引用任何方法论（对照表为空）即打回补引**；引用条目须实际用于正文论证，不得空挂编号
- 交付物末尾附质量自评报告（含 G1-G4 状态 + AP-W 命中/修复清单）
- **降级与待沉淀**（无库 / 有库缺条目两场景、「暂无对应条目」声明须附的两项、库须持续更新）→ [response-chain.md](references/response-chain.md) §G4 引用自检·降级两场景与库更新 ／ [methods-guide.md](references/methods-guide.md) §库缺失/缺条目时的降级

## 边界与协作

- **上游开放**：`ibd-doc-review` 是格式层公共服务，**不限于本 skill 接入**——人工撰写、其他 AI 流程、外部导入的 Word 文档均可直接调用它套样式 / 格式核对
- **本 skill 产出可交其他复核**：内容草稿也可交 `ibd-quality-gates`（内容质量校验：数字五要素 / 反模式 / G1-G5）或用户指定复核方审查；本 skill 不做格式与质量的最终定夺，最终判定归使用者/负责人
- **格式门禁前移（2026-09-10 固化）**：内容定稿后**必须先跑 `deliver_gate.py --md` 再套样式**——标点全半角虽是格式项，返工成本却落在文字层（实测一份交付件 384 处半角引号漏到套样式之后才被发现，白跑一轮样式）
- 详规（上游开放 / 交复核 / 门禁前移）→ [delivery-chain.md](references/delivery-chain.md) §5
## 与内置文件操作层（L2）的接口

> 依据「产物型任务两层路由模型」。本包是**产物型入口**（L1 作业层）——管「文档类产物的活该怎么做」；**落到哪个工具执行归内置 `tencent-docs-routing`（L2）**：通道选择（`tencent-docx`／`local-office-edit`／`minimax-docx`／`officecli` 等）**归 L2**，本包只负责**任务性质判定与表述整形**（「新建文档」vs「编辑既有文档」vs「整篇美化」）；docx 首选与降级序归 **L2.5 层**。分工表与「为什么写明」→ [delivery-chain.md](references/delivery-chain.md) §4。
## 踩坑与要点

- **数据密度**：①每个结论配表格数据 ②引合同条款原文（证明力）③模拟调整后对比（毛利率质疑杀手锏）④主动回应追问点（跨期/废料影响量化）⑤风险揭示收尾
- **行业定位先行**：先确认该案证监会行业分类（招股书"业务与技术"披露口径），再选行业方法论对应类
- **方法论索引为最新**：若刚蒸馏新案，先运行你的蒸馏脚本刷新方法论索引（如 `--refresh-index`，脚本位于你的工作空间内）再查；无蒸馏脚本则跳过（索引仅影响反馈回复 ②③ 步）
- **格式单一事实源**：样式/序号/表格归 `ibd-doc-review` skill，本 skill 不重复维护格式细节
