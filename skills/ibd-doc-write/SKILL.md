# ibd-doc-write（IBD 投行文档写作）

A股 IPO 投行文档写作总入口。核心：让 AI 写文件像投行人、不是 AI，且**方法论强制引用、不引用即打回**。

## 何时使用

- 写审核问询反馈回复 / 回复报告（「写XX的反馈回复」「起草问询回复」）
- 写招股书章节 / 分析报告 / 尽调报告 / 备忘录（「写招股书」「写尽调报告」「写备忘录」）
- 做财务对比表 / IPO 项目核对表（Excel）

## 使用流程

> 最小复现示例（对话触发 → 执行链路 → 交付物结构）见 [examples.md](references/examples.md)。

### 2. 五步强制调用链路（反馈回复专用 · 缺一步即不合格）

> 完整链路见 [response-chain.md](references/response-chain.md)；仅"写反馈回复"类任务执行，其他文档类型跳过第 ②③ 步方法论读取，但仍需 G4 来源对照。

```
拿到问询函
  → ⓪ 方法论版本感知（凡引用方法论必做）：读 {METHODS_ROOT}/通用方法论_最终版.md 头部版本指引行 → 确认当前 vN（蒸馏每轮升版由 --refresh-index 自动同步）——本次引用一律以该 vN 条目为准，⑤ 对照表标注「依据方法论点 vN」，防蒸馏刚升版时误引旧版编号/行号
  → ① 拆问询问题：把每个问询问题拆解为方法论主题（收入确认/毛利率/对赌清理/实控人/客户集中/募投产能消化等）
  → ② 查映射索引：打开 {METHODS_ROOT}/方法论调用索引.md → 顶部「28 个问询问题域速查表」找到 Q 编号 → 去全量映射表查该 Q 下所有条目 → **跨域补充**：查「三、跨域桥接速查表」看各域代表条目（财务/法律/行业/写作桥接，A-Mem 语义链接）
  → ③ 定向读方法论（**行号定位**：条目标题目录含「行号」列，用 Read offset/limit 精准读条目正文，不全文翻找）
  → ④ 套投行语言词汇句法库：回复表述套用 WL-xx-xxxx 句式（v37 族号体系），避免 AI 痕迹
  → ⑤ G4 引用清单自检：交付前生成「问询问题类型→方法论条目编号（v37：F-010001 / F-C15-01 / WL-xx-xxxx）→使用位置」对照表，随质量自评报告附上
```

### 3. 格式落地串联（写作完成后必做 · 先审内容后定格式）

> 本 skill 只产出**内容草稿**；样式落地与格式核对一律走 `ibd-doc-review`（格式层单一事实源，本 skill 不重复维护格式细节）。
> **顺序规则：内容质量校验在前、格式落地在后**——内容未定稿不套样式，改稿成本最低。

```
草稿完成
  → ① ibd-quality-gates 内容质量校验（草稿阶段：数字五要素 / 反模式 / G1-G5，md 即可跑）
  → ①' 数值自洽机械门：ibd-quality-gates scripts/check_data.py --input <草稿.md|docx>
       （md 载体即可跑——金额文本格式 / 数值前后一致 / 表格合计勾稽 / 跨表比对；
         此刻改的是 md，零排版成本；docx 正式稿复核亦可跑）
  → ② 声明样式场景（招股书版 / 反馈回复版）
  → ③ ibd-doc-review 套样式（其 assets/templates/ 为使用源）→ 其 check_styles.py 校验
  → ④（可选）ibd-doc-review check_content 格式核对（text/table 组依赖样式化 docx，套样式后跑）
  → ⑤ 交付（附样式应用声明，使用者/负责人最终确认）
```

### 4. 协作模式（可选 · 团队增强）

> 单用户模式**不需要本节**——直接按上述流程写作即可。以下仅为「多角色协作」时的增强说明。

- 团队模式：TeamCreate → 多维专家并行分析（财务/法律/行业）→ 写作角色综合成文 → 负责人按 G4 引用清单自检
- 多维分析时：读 KB_BACKEND 同类案例 + 各领域方法论表
- 综合成文时：按本 skill 路由（反馈回复走五步链路）+ 投行语言写作规范 + 回查原文补齐数据（**不能只写框架，每个结论要配表格数据/合同条款原文/页码**）

### 工具说明（安装时读 · 每个工具为什么是这个层级）

**🔴 必须 · `ibd-quality-gates`（内容+数值校验）〔🔗 外部依赖·断链自助，≥0.7.0〕**
- 用途：内容质量校验（数字五要素 / 反模式 / G1-G5）+ 数值自洽核对（`ibd-quality-gates` 的 check_data.py，md/docx 双载体）
- 为什么必须：流程 ①/①' 的检查主体，**没有它内容不过门就进排版，问题回头改成本高**（md 阶段改零排版成本）

**🔴 必须 · `ibd-doc-review`（格式层）〔🔗 外部依赖·断链自助，≥0.15.0〕**
- 用途：给草稿套投行标准样式（招股书 000-009 / 反馈回复版）+ 格式校验
- 为什么必须：本 skill 只产出内容草稿，样式落地与格式核对全靠它；**没有它交付物只能是未排版文档**，无法通过投行格式审查

**🔴 必须 · `tencent-docx`〔🟦内置〕 / `minimax-docx`〔🟨官方市场〕（docx 生成，二选一）**
- 用途：生成/编辑 Word 文档（minimax-docx 还能把模板样式套到已有文档）
- 为什么必须：docx 成品的唯一产出通道；**没有它只能输出 Markdown**，交付物需人工转 Word

**🟡 推荐 · 方法论库 `{METHODS_ROOT}`〔⬛私有本地，自建〕**
- 用途：按问题域索引的经验知识库——五步链路 ②③ 的查询对象（「这题以前怎么答得好」）
- 为什么推荐：G4 引用自检的溯源核心，**写作质量的关键差异**；没有它走 G4 降级（引用高频句法库），仍可写作但缺「案例经验」
- 建立方式：见 `methods-guide.md`（边用边长，积累 10-20 条后体验质变）

**🟡 推荐 · Wind 数据**
- 用途：可比公司对标、行业数据、公告检索（反馈回复的数据支撑）
- 为什么推荐：数据权威性，**避免「编数字」风险**；没有则用招股书/公开披露数据，质量略降但可用

**🟡 推荐 · `sheetagent`（Excel）**
- 用途：财务对比表 / IPO 核对表生成（仅 Excel 文档场景）
- 为什么推荐：Excel 产出的标准通道；没有则表格改用 Markdown 或手工制作

**🟢 可选 · KB_BACKEND 知识库后端**
- 用途：检索同类案例（写作范式参考）+ 存取模板/方法论归档
- 为什么可选：有则写作有「范例参照」；**没有则靠高频句法库 + 方法论库，仅少案例锚点**，不影响主线
- 可选后端：公司内部 Wiki / 云文档 / 本地目录（功能等价）

## 边界与外部接口

- **上游开放**：`ibd-doc-review` 是格式层公共服务，**不限于本 skill 接入**——人工撰写、其他 AI 流程、外部导入的 Word 文档均可直接调用它套样式 / 格式核对；外部产出也可从上述任意环节接入
- **本 skill 产出可交其他复核**：内容草稿除走 doc-review 格式落地外，也可交 `ibd-quality-gates`（内容质量校验：数字五要素 / 反模式 / G1-G5）或用户指定复核方审查；本 skill 不做格式与质量的最终定夺，最终判定归使用者/负责人

## 关键要点

- **数据密度**：①每个结论配表格数据 ②引合同条款原文（证明力）③模拟调整后对比（毛利率质疑杀手锏）④主动回应追问点（跨期/废料影响量化）⑤风险揭示收尾
- **行业定位先行**：先确认该案证监会行业分类（招股书"业务与技术"披露口径），再选行业方法论对应类
- **方法论索引为最新**：若刚蒸馏新案，先运行你的蒸馏脚本刷新方法论索引（如 `--refresh-index`，脚本位于你的工作空间内）再查；无蒸馏脚本则跳过（索引仅影响反馈回复 ②③ 步）
- **格式单一事实源**：样式/序号/表格归 `ibd-doc-review` skill，本 skill 不重复维护格式细节
- **内容质量单一事实源**：数字五要素/反模式/自评归 `ibd-quality-gates` skill

## G4 引用自检（使用者/负责人核对）

- 交付必须附「问询问题类型→方法论条目编号（F-/L-/I-/W- 六位，如 W-000001）→使用位置」对照表
- **未引用任何方法论（对照表为空）即打回补引**；引用条目须实际用于正文论证，不得空挂编号
- **方法论库降级（两种场景，均保持可写）**：
  - **场景一 · 无库**：新使用者无 METHODS_ROOT 时，②③ 跳过，凭 `writing-style.md` 高频句法库完成写作
  - **场景二 · 有库但缺条目**：查索引未命中该问题时，**向使用者明确提示**「该问题（如：XXX）在方法论库暂无对应条目」，再继续降级写作
  - 两种场景的 G4 对照表均允许「本库暂无对应条目」声明，但必须附：① 引用的通用高频句式（writing-style.md 条目）② 该问题标记「待沉淀」（积累清单，随方法论库持续更新补上）；**不允许零引用直接写**
- **方法论库持续更新**：方法论库是活资产——每次写作/蒸馏后沉淀新条目（见 `methods-guide.md` 方式 A 回环），保持索引与条目常新；久不更新的库会导致「缺条目」频发
- 交付物末尾附质量自评报告（含 G1-G4 状态 + AP-W 命中/修复清单）

## 维护与更新

> **蒸馏沉淀后必做自检**：每轮蒸馏完成后对照本表检查一次——方法论内容更新（vN 升版/索引刷新）→ **无需改本 skill**（`--refresh-index` 已自动维护稳定入口）；五步调用链路/G4 引用自检规则变化 → **必须同步更新本 skill**；检查结果记录到蒸馏笔记。
