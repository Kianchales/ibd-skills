# 复核工作区结构（workspace-layout.md）

> **这份文档管什么**：复核一份文档时，文件该放在哪个文件夹。**只管放的位置，不管怎么查**——查什么见 [check-scope.md](check-scope.md)，怎么交付见 [delivery.md](delivery.md)。
> **为什么需要它**：复核常做多轮（同一份稿子改一版核一遍），产物形态又多（批注版、报告、问题清单、过程日志、中间脚本）。没有固定位置时，一轮下来几十个文件平铺在同一目录，隔几天回来已无法判断：**哪份是本轮基准、哪份能发给客户、哪份只是中间产物**。本册把这三件事用文件夹固定下来。

---

## 一、两种模式（先选模式，再动手）

| 模式 | 什么时候用 | 判据 |
|---|---|---|
| **单文件模式**（默认） | 只复核一份文档 | 被复核对象 ＝ **1 个** |
| **多文件作业区** | 同时复核两份及以上不同文档 | 被复核对象 **≥ 2 个** |

> **「被复核对象」怎么数**：**同一文档的多个版本算 1 个**（v1 → v2 → v3 只是换基准，不另起）；招股说明书、问询回复、保荐书这类**不同文档**才算多个。数错会把每次改版都变成新建作业区，反而散。
>
> **反向判据**：不要因为「预计要核好几轮」就提前建多文件作业区——轮次多不等于文件多，单文件模式同样支持多轮。

---

## 二、单文件模式（默认）

位置：**与被复核文件同级**，源文件本身不动、不复制。

```
<被复核文件名>_复核/
├── 00_基准说明.md      ← 有多个版本时才需要；单版本可省
├── 参考资料/           查的时候要对照的东西（见 §四）
├── 问题记录/           每轮一份：查出的问题（json）＋本轮声明单（md），不删
├── 复核结果/           批注版、复核报告、修订稿（能发出去的）
└── 过程文件/           总览、台账、门禁日志、临时脚本（只给自己看）
```

例：被复核文件是 `某专项说明.docx`，则产物落在 `某专项说明_复核/` 下。

> 单文件模式的路径**可由源文件直接推出**，不写元数据文件、不建五层——一份稿子不值得铺五个目录。

---

## 三、多文件作业区

位置：自选一个工作区根目录，其下**一个项目一个文件夹**。

```
<项目简称>/
├── README.md              一页说明书：本项目在核什么、以哪版为准、每层干什么
├── .review-workspace.json  机器读的作业区元数据（脚本据此推导落点）
├── 01_待复核材料/          客户发来的各版文件，平铺，不再建子目录
│   └── 00_基准说明.md      本轮以哪份为准（见 §五）
├── 02_参考资料/            对照依据，四类（见 §四）
│   ├── 01_规则与准则/      证监会/交易所规则、会计准则、格式规范
│   ├── 02_内部口径/        项目组统一说法、公司体例、已定过的调子
│   ├── 03_同类范例/        其他项目的招股书/问询回复，对照用
│   └── 04_数据来源/        财务台账、行情导出、往来函证
├── 03_问题记录/            按原文名分子目录（脚本识别上一轮用）
│   ├── <原文名A>/
│   └── <原文名B>/
├── 04_复核结果/            **不分子目录**，靠文件名前缀自然聚合
└── 05_过程文件/            **不分子目录**
```

### 每层职责与边界

| 层 | 放什么 | 不放什么 |
|---|---|---|
| `01_待复核材料` | 客户发来的文件（全部版本）＋`00_基准说明.md` | 任何本人生成的产物 |
| `02_参考资料` | 判依据时要用到的外部与内部材料 | 本轮问题、本轮结论 |
| `03_问题记录` | 每轮的问题清单（json）＋**本轮声明单（md）** | 已交付的报告、批注版 |
| `04_复核结果` | 批注版、复核报告 xlsx、修订稿 | 问题清单原始 json、过程日志 |
| `05_过程文件` | 批注总览 md、轮次台账、门禁日志、临时脚本 | 任何要发给客户的成品 |

### 为什么只有 `03` 分子目录

`round_diff` 类脚本从**目录**里认「上一轮清单」，按文件名里的「日期＋轮次」取最新一份，**不看原文名**。两份不同文档的清单混在同一目录时，它会把 A 的上一轮当成 B 的上一轮，产出全错位的对比表且不报错。按原文名分一层即可根除。

`04`、`05` 没有这个约束：同一原文的产物文件名前缀相同，按名称排序天然聚成一组，**不为对称而加层**。

### `03` 里放两种文件（缺一种，跨轮就没法对账）

| 文件 | 命名 | 谁读 | 作用 |
|---|---|---|---|
| **问题清单** | `<原文名>_<YYYYMMDD>_v<N>_issues.json` | `round_diff.py`／报告生成器 | 本轮查出了什么 |
| **声明单** | `<原文名>_<YYYYMMDD>_v<N>_scope.md` | 人 | 本轮查了哪些项、覆盖方式是全文还是抽核、依据来源是哪几类 |

> **为什么声明单也进 `03`**：它与清单是**同一轮的两半**——清单说「查出什么」，声明单说「查了什么」。只留清单，下一轮就回答不了「上次到底查没查这一项」，标准漂移也就无从发现。
> **为什么不影响 `round_diff`**：`find_prev()` 只读 `.json` 且要求文件名含 `issues`，md 天然被跳过（实测）。**声明单不要存成 `.json`**——会被当成上轮清单认错，且不报错。
> 声明单**只存档、不交付**：它是过程件，对外交付物里不出现。

## 四、参考资料（复核的依据从哪来）

### 四类（不要再加第五类）

| 子类 | 内容 | 典型形态 |
|---|---|---|
| `01_规则与准则` | 硬约束：审核规则、信息披露准则、会计准则、格式规范 | 规则条文、准则原文 |
| `02_内部口径` | 项目组已定过的说法、公司体例、领导拍过的调子 | 会议纪要、口径备忘、往期定稿 |
| `03_同类范例` | 其他项目的对应章节，只作参考 | 招股书章节、问询回复 |
| `04_数据来源` | 数字的出处 | 财务台账、行情导出、函证 |

> 上轮问题清单不在此层——它按定义就在 `03_问题记录` 里；客户对上一轮的整改回复属于本轮待复核材料，进 `01`。**同一类东西只有一处存放**，才不会出现「哪份才是最新的上轮结论」。

### 引用纪律（五条，与只读纪律同级）

1. **依据层级**：法规/准则（硬约束）＞ 项目组书面口径 ＞ 行业惯例与同类范例（仅供参考）。**冲突时以法规为准**，拿不准的标「待项目组裁定」，不得自行选一个当结论。
2. **只读**：参考件不改、不移动、不改名。
3. **引用可追**：报告里的每条依据要能指到**具体文件＋位置（页码/条号/段号）**，不许写「据相关法规」「参照同类项目」这种无法复核的话。
4. **缺件必须声明**：某一类参考件缺失时，写「无对应规则/范例，本项按通用判断」，并在交付里点名缺哪类——**「没找到依据」不等于「不需要依据」**，更不许照常出结论而不说。
5. **不交付**：参考资料不进 `04_复核结果`，对外交付物里不得夹带内部口径与同类项目的原文片段。

---

## 五、基准识别（哪一版才算数）

`01_待复核材料` 里可能躺着七八个版本。**每个时刻只认一份**，写进 `00_基准说明.md`。

### 为什么文件名叫 `00_`

文件夹默认按名称排序，`00_` 保证它永远排在一串 docx 之前——**不用点开就能看见**。这份说明是纯表格，不写散文。

### 必须记的六项

| 项 | 内容 |
|---|---|
| 文件名 | 完整文件名（含扩展名） |
| 收到日期 / 来源 | 什么时候、从哪来（邮件/网盘/客户当面） |
| 认定依据 | **为什么是这一版**——不比日期新旧，要写具体改动（如「已并入第二轮问询回复口径」） |
| 本轮轮次 | 第几轮复核 |
| 认定人 / 时间 | 谁定的、什么时候定的 |
| 历史对照 | 第 1 轮用哪版、第 2 轮用哪版……一行一轮，越滚越长，本身就是基准台账 |

### 换基准三步（必须动手，不许只在口头说）

1. 旧版留在 `01` 里不动（`01` 全版本共存，不做移出）；
2. 新版放进 `01`；
3. `00_基准说明.md` 的「历史对照」追加一行。

> **不要另建「历史版本」目录**：`01` 本来就是全版本共存区，`00_基准说明.md` 指明当前认哪份即可。多一层「现行/历史」会让人在两处之间搬运，搬运过程正是「哪份是真身」的歧义来源。

## 六、命名与轮次

正式产物统一 `<原文名>_<YYYYMMDD>_v<N>_<形态>`（例：`某专项说明_20261116_v2_批注版.docx`）。

| 项 | 规则 |
|---|---|
| `v<N>` 怎么定 | 同一原文、同一形态，**取已有文件里最大的 N 再加 1**；本轮首次即 v1 |
| 同轮重跑 | 同日同 vN 同形态 **直接覆盖**（修 bug 重跑不产生新文件） |
| 跨轮 | **必升 N**，旧轮产物保留可回溯 |
| `<原文名>` | 取基准文件的简称，**不随版本号变化**——变前缀会让跨轮比对认不出同一份文档 |

---

## 七、自动落位（让放错变难）

初始化脚本按模式建好目录并写元数据，后续脚本据元数据推导默认落点，**人不用记路径**：

```bash
# 多文件作业区
python scripts/new_workspace.py --mode multi --root <工作区根> --project <项目简称>

# 单文件模式（在源文件同级建 <文件名>_复核/）
python scripts/new_workspace.py --mode single --source <被复核文件>
```

- 两者都**幂等**：目录已存在不报错、不覆盖已有文件；加 `--force` 才重建空目录结构。
- `--root` **必填**，脚本不猜默认位置（工作区放哪是本机习惯，写死会与别人的环境冲突）。
- 多文件作业区写 `.review-workspace.json`（记录五层目录名、项目名、创建日期）；单文件模式**不写**——路径可由源文件推出。

## 八、反模式（这几件事别做）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 同一份文件存两处 | 改一处另一处不同步，说不清以哪份为准 | 只留一份真身，另一处只放指针 |
| 参考件混进复核结果 | 内部口径/别家项目原文被当成我方结论发出去 | 参考资料只在 `02`，交付物只从 `04` 取 |
| 单文件硬建五层 | 空目录一堆，下次没人愿意建 | 单文件用最小四层，目录随内容长 |
| 多轮产物落临时目录 | 系统清理后上一轮无法比对，台账断链 | 单文件也要建 `<文件名>_复核/` |
| 在 `01` 里直接改原件 | 基准被悄悄替换，事后无法复原 | 改动另存新版本，再走换基准三步 |
| 靠文件夹对称性攀层 | 04/05 各多一层，找东西多一次点击 | 只在脚本有硬约束处（`03`）分层 |

---

## 九、沿革

- 首版：两档模式（单文件默认 / 多文件作业区）立稿；目录名取「待复核材料、参考资料、问题记录、复核结果、过程文件」，全部为见名知意的日常词，不使用内部缩写。
- 同期裁定：`03` 按原文名分子目录（脚本识别上一轮的硬约束）；`04`、`05` 不分（无约束不为对称加层）；参考资料固定四类，不设「上轮遗留」（上轮清单归 `03`，整改回复归 `01`）。
- 同期裁定：基准识别用置顶的 `00_基准说明.md` 单文件承载，不另建「现行/历史」子目录。
- 2026-11-19 补：**`03` 增第二种文件——声明单（`_scope.md`）**。此前只有问题清单，「查了什么」只在对话里，跨轮无法对账。命名刻意用 `.md`：`round_diff.find_prev()` 只认 `.json` ＋ 文件名含 `issues`，md 不会被误认成上轮清单。
