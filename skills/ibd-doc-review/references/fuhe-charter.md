# 「复核」章程（fuhe-charter.md）

> **本册是「复核」一词的定义与约束的唯一事实源。** 只要用户以「复核」（或复核类的同义说法）提出要求，本册全部条款**自动生效**，不需要用户再说"全量""逐项""不要抽检"。
> 与其它册的关系：查什么 → [check-scope.md](check-scope.md)；怎么切 → [chunked-review.md](chunked-review.md)；怎么交付 → [delivery.md](delivery.md)；链路 → [pipeline.md](pipeline.md)。

---

## 一、定义

**「复核」＝ 对用户指定范围内 100% 的对象，逐项按其判据判定一遍，并给出可回溯的结论。**

四个要件缺一不可，任一缺失即**不构成复核**（只能叫"看了一下"）：

| 要件 | 含义 | 反例 |
|---|---|---|
| **全对象** | 范围内每一个段落／表格／文件都过一遍，无遗漏 | 只核了前几章 |
| **逐项判定** | 每个对象按判据给"符合/不符合/不适用"，不是通读一遍凭印象 | 读完说"整体还行" |
| **可回溯** | 每条结论能定位到 `P####`／`TAB###`／文件名 | 只给结论不给位置 |
| **覆盖可证** | 声明的分母 ＝ 实际处理的分母，且能对账 | 说"全文"，实际只读部分 |

## 二、触发条件

出现下列任一情形，**即按本册执行**，无需追加提示词：

- 用户说「复核 X」「帮我把 X 核一遍」「X 有没有问题」「过一遍 X」「查一遍 X」「X 质检」
- 用户说「按 ibd-doc-review 复核」「全套复核」「逐项核」
- 用户把文件交给你并要求"检查/核对/看看有没有错"，且对象是投行申报文件

**反向触发（用户明说要抽样时）**：只有用户**明确**说「只看第四节」「抽几段看看」「先看重点」这类缩范围指令，才允许非全量；此时按 §四 留痕，且报告不得声称"复核完毕"。

## 二·补、两种口径：全套复核 vs 单件复核（降级）

**"全量"的对象是用户给的文档，不是"能想到的所有比对"。**

| 口径 | 触发 | 范围 | 报告必须写 |
|---|---|---|---|
| **全套复核** | 给了配套材料（申报报表／附注等） | 该文档 100% ＋ 与配套材料的跨文档勾稽 | 覆盖方式＋勾稽结论 |
| **单件复核（降级）** | **只给一份文档** | **仅该文档 100%**（格式／自身自洽／内部一致性／六问） | 明写「本轮为单件复核，未做跨文档勾稽」 |

规则：

1. **不得自动去别处找配套材料**——同目录有报表也不算"已提供"；不猜、不借用。
2. 降级**不是抽检**：对象仍是 100% 覆盖，只是少了"跨文档"这一维；但**不得**用降级口径声称"财务数据干净"。
3. 要升级为全套复核，由用户提供材料；`pending_inputs.json` 会写明"给什么可升级"。

## 二·补二、深度四档（查什么 × 读多细）

| 档 | 查什么 | 读多细 |
|---|---|---|
| L1 快扫 | 表面项 | 扫关键句 |
| L2 标准（默认） | 机器能判的全项 | 扫关键句 |
| **L3 通读** | 同 L2 | **逐字** |
| **L4 深核** | ＋专业判断 | **逐字** | 

> **L4 的边界**：C-P／D 两款由 `ibd-finance-review`、`ibd-legal-review` 承载，**本包不产、也不验证其执行**。声明 L4 却没调这两个包，`--prepare` 会把两项写进 `pending_inputs.json`，`check_runlog` 判 R3b WARN「L4 实际只到 L3」。**不允许只看档名就当成深核。**

- **单调**：高档含低档；**L3/L4 必须逐字**（工具按 30 段／批切，批更短才读得完）。
- 原"档位 × 颗粒"两轴合并为四档：六个组合里两个本就无效（L1＋逐字、L3＋逐项），无需并存。
- **声明单与报告头写同一档名**，不得一个写 L2、一个写"逐字"。

## 三、全量覆盖范围

| 维度 | 覆盖要求 |
|---|---|
| **段落** | 全部段落（正文／标题／短句），**不只正文**——标题序号类问题全在标题段 |
| **表格** | 全部表格：逐表判表头、单位行、期间列、表下注；单元格随表判，不单独计数 |
| **检查项** | 声明单列出的每一项都要有结论；未跑的项**逐项点名**（"未核即声明"） |
| **文件** | 指定了几份就核几份；本 skill 只评文件本身，其它文件的冲突作为**提示**不计入本文件结论 |
| **分母** | 以 `--prepare` 输出的实际计数为准（`总段／正文／表`），不得估算 |

## 四、禁止抽检的约束

| # | 禁止事项 | 为什么禁 |
|---|---|---|
| 1 | 以"文件太大""分批做""先看重点"为由缩小范围 | 缩范围只能由用户发起；跑不完就**分批跑，不改口径** |
| 2 | 未读全就出结论 | 结论必须建立在"全对象已过"之上 |
| 3 | 用抽样结果冒充全量（声明写全文、实际抽核） | 静默缩范围比明说抽核更严重 |
| 4 | 默认跳过某类对象（表格／标题／附件） | 跳过即遗漏，且用户无从发现 |
| 5 | 以"上一轮已核过"省略本轮 | 每轮独立全量；改动过就必须重核全量 |
| 6 | **事后补记运行指纹**（把没跑的步骤回写进 `_run.json`） | 指纹是**凭证**，不是台账：补记那一刻它就从"证据"变成"自述"。步骤晚于产物生成时间会被 `check_runlog` R1c 判 FAIL，写入不承接上一步哈希会被 R1b 判链断 |
| 7 | 只跑 `--prepare`／单点检查就宣称复核完成 | 覆盖可证要求**逐批状态机走完**（commit 数 ＝ 批数 ＋ finish），否则 R4 FAIL |

**唯一例外**：对象**无法读取**（缺件、加密、损坏）。此时逐项列出未核对象与原因，报告结论**不得覆盖**这些对象。

## 五、结果输出要求

| 项 | 要求 |
|---|---|
| 覆盖声明 | 报告封面写明「覆盖方式：全文逐段」＋ `总段／正文／表` 三个数 |
| 未核项 | 逐项点名（对象 ＋ 原因），不得写成"部分未核" |
| **缺材料项** | 声明要做但缺材料做不了的检查，自动落 `pending_inputs.json` 并进报告「行动项」：写清**缺什么、影响哪项判据、补了能解锁什么**——不许只在 stderr 提示后消失 |
| 每条结论 | 带定位（`P####`／`TAB###`）与原文片段；无定位的条目不进报告 |
| 流程凭证 | 报告封面含「流程指纹」行（步数／工具／skill 版本） |
| 交付形态 | Excel 分表报告；批注版按需另出（本 skill 不主动生成） |

## 六、自检标准（交付前必须全绿）

```bash
python scripts/review_file.py --input <文件> --financials <报表> --restr … --prepare
# … --begin / --commit 循环至全部批完成 …
python scripts/review_file.py --input <文件> --finish
python scripts/check_runlog.py --file <文件>
```

| 判据 | 期望 | 不满足即 |
|---|---|---|
| `check_runlog` 总体 | `PASS` | 不得交付 |
| R3 `check_content` | 有指纹且 rc∈{0,1} | 视为未做格式核对 |
| R5 声明单 | 校验 PASS，且覆盖方式＝**全文逐段** | 视为缩范围 |
| R1b 指纹链 | 逐条哈希相接 | 断链＝事后补写，凭证不可信 |
| R1c 时序 | 全部步骤早于产物生成时间 | 晚于产物＝疑似补记 |
| R4 编排器 | `finish rc=0` **且 commit 数 ＝ 批数** | 视为覆盖不可证，不得交付 |
| R6 报告 | 有 xlsx 且封面有流程指纹 | 视为无凭证报告 |
| 批完成度 | 全部批 `done`（`--status` 无未完成） | `--finish` 会拒绝（exit 3） |

**人工抽验（可选，用于验证不是抽样交付）**：任取报告未提及的一节，问"这一节讲了什么"——答不出即说明未真读。

## 八、节级回执：把"读了没有"变成必填表态

**为什么需要**：只交问题清单时，"这节没问题"与"这节没读"看起来一样——都表现为 0 条。实证：某轮报告 13 条硬伤质量很高，但**无任何逐节台账**，无法证明 27 份材料／12 节都过了一遍；另一轮覆盖台账齐全，但深度浅。两轮各占一半。

每批 `--commit` 必须同时交 **receipt**（节级六问，每项一句话；无异常写"未见异常"）：

| 键 | 问什么 |
|---|---|
| `self` | 本节内部：数据自洽？表内合计/占比对不对？ |
| `cross_prev` | 与前文是否冲突（数字、口径、承诺、时间线） |
| `cross_next` | 与后文是否冲突（尤其后文另有专章披露的） |
| `disclose` | **该披露的是否披露**（缺项比错项更常见） |
| `caliber` | 口径是否全文统一（同一指标多表不同算法） |
| `wording` | 表述是否绝对化/承诺性/与事实张力 |

缺任一键 → `--commit` 拒收；有批无回执 → `--finish` exit 3。**"未见异常"是有效回答，沉默不是。**

## 七、条款与工具的对应（为什么"不靠提示词也能生效"）

| 条款 | 落点（工具强制，不依赖自觉） |
|---|---|
| 只走一个入口 | `SKILL.md` 顶部铁律；报告生成器无 `_run.json` 即 exit 3 |
| 默认全文 | `--prepare` 自动生成声明单，覆盖方式写死「全文逐段」 |
| 禁自行缩范围 | `check_scope_decl.py`：`圈定/抽核` 无「指示来源」即 ERROR |
| 全对象（含标题） | 批次含全部段落类，`--begin` 标〔标题〕 |
| 不许半套 | 未完成批 `--finish` 直接 exit 3，不产出结果文件 |
| 覆盖可证 | `check_runlog.py` R5 强判覆盖方式；R1–R6 全绿才算完成 |
| 结论可回溯 | 每条须带 `anchor`，`--commit` 当场校验 |
