# 复核修订稿交付规范（revisions）— 单一事实源

> 适用范围：IPO 复核结论以「**修订稿**」形式落实到原文 docx 的**格式与行为单一事实源**。
> 关系：本文件只定义**规范与校验**；修订稿**执行器** = `ibd-doc-annotate` skill `scripts/revise_docx.py`
> （复核问题清单 + 原文 → 修订稿 docx + 修改清单），产出以本文件为合规依据。
> 与批注的关系：批注/修订同为复核结论落地形态、同源（同一份问题清单）；批注规范见 [annotations.md](annotations.md)。
> 边界：`check_styles.py --revise` 的**格式修订**（套样式差异转 Word 修订）属样式应用链路，与本规范无关。

## 1. 交付形态（--mode 三选一，先与用户确认）

> ⛔ **形态先确认（2026-09-06 用户裁定）**：任何修订需求（含「直接改好/干净版/定稿」等已指向某形态的措辞）→ 执行方**先反问确认形态再执行**，不按用户措辞自动路由 mode。修订触发词统一收敛为「修订」一个入口（生成修订稿/出修订稿/直接改好/两个都要…均为同一入口，进入后确认形态）；用户原话明显指向某形态时列为推荐项，仍由用户拍板。

| mode | 产出 | 说明 |
|---|---|---|
| `revise` | `<原文>_修订稿.docx` | **Word 修订模式**：原文本包 `w:del`（`w:delText`），新文本包 `w:ins`，作者 = 复核人；审阅面板逐条查看、可接受/拒绝 |
| `clean` | `<原文>_修订稿.docx` | 改动直接落定，无修订标记；对照《修改清单》查看 |
| `both` | `_修订稿.docx` + `_修订稿_clean.docx` | 双版本同时交付（clean = 接受全部修订后） |

> 与批注版并行规则：复核默认交付 = 批注版 + 精简总览；**用户说「修订」→ 先确认形态后再生成修订稿**，不主动生成修订稿。

## 2. 输入（问题清单 rev 字段）

批注清单字段基础上每条增加 `rev`：

| 字段 | 必填 | 语义 |
|---|---|---|
| `anchor` | ✅ | 原文待改句段（精确子串），**同时是替换范围**——须精确覆盖要改的文本 |
| `rev` | 视条目 | 替换后新文本（anchor 命中的原文整体替换为 rev）。**缺 rev 或 rev==anchor → 该条待人工**，不自动改 |
| author/type/sev/title/desc/advice | ✅ | 同批注清单（编号体系复用批注规范 §3：前缀由清单 `code` 字段自定义 + 前缀内序号） |

- 不可自动修订（记入修改清单「待人工」，不硬撑）：缺 rev；正文/表格未找到锚点；锚点覆盖复杂 run（换行 `w:br`/制表 `w:tab`/多 `w:t`）；锚点区间夹非 run 元素（超链接等）；与同段另一锚点重叠
- 同段多锚点：互不重叠时按段尾→段首倒序应用（坐标稳定）；重叠 → 靠前条待人工
- 修订只作用于 anchor 区间，**原文其余文字零改动**

## 3. 修订落定（Word 修订模式 OOXML）

- 每条修订一对 `w:del` + `w:ins`，同 `w:id`；`w:author` = 复核人花名、`w:date` = ISO8601（可归责、可接受/拒绝流转）
- `w:del` 内：原 run 逐个转 `w:delText`（保留各自 rPr），聚合为一条删除
- `w:ins` 内：新文本单 run，**rPr 继承锚点首 run**（字体/字号/加粗随原文，不另设格式）
- 锚点前/后 run 与段内非 run 顶层节点原样保留（含格式）；锚点中间切开的 run 拆 pre/mid/post 三片处理
- `settings.xml` 需开 `w:trackRevisions` + `w:revisionView`（元素名与插入位置见 `check_styles.py --revise` 实证：`trackRevisions` 合法名，位于 `bordersDoNotSurroundFooter` 之后）

## 4. 修改清单（`<原文>_修订稿_修改清单.md`）

- 表 1「已修订 N 条」：编号 / 类型·严重度 / 作者 / 原文 → 改为（截断展示）
- 表 2「待人工 M 条（未自动修订）」：编号 / 原因（未提供 rev / 未找到锚点 / 复杂 run / 区间夹非 run / 重叠）/ 建议
- 编号与批注/复核总览同一体系：同源清单时互相回溯

## 5. 校验门禁（scripts/check_revisions.py，只读）

- revise/both 的修订版：
  1. `w:ins` 数量 == `w:del` 数量（每修订一对）且 == 修改清单「已修订」条数（`--expect` 可显式指定）
  2. 每条 ins/del 带非空 `author`；id 全局唯一且 ins/del 成对
  3. `w:del` 内含 `w:delText`、`w:ins` 内含 `w:t`，均非空
  4. settings 已开 `trackRevisions` + `revisionView`
  5. **落定证明**：对文件做 clean 化（删 `w:del`、解包 `w:ins`）后，每个 ins 的新文本仍出现在 clean 全文（修订有效、未丢失）
- clean/both 的干净版：不含任何 `w:ins`/`w:del` 残留
- 输出 `<文件>_修订校验报告.md`；任一 FAIL → 退回 `ibd-doc-annotate` revise_docx.py 重新生成，不交付
