# IPO 文档序号与表格规则（rules.md）

> 规则来源：模板 docx 实证（标题序号链、三线表规范、反馈回复排版范式）+ 排版规范（段落间距靠样式 spacing 控制、禁止空段落、只改格式不改内容）。

## 一、标题序号九级链

完整序号链：`一、 → （一） → 1、 → （1） → 1） → ① → A、 → a、`

| 层级 | 序号格式 | 示例 | 对应 pStyle |
|------|---------|------|------------|
| 一级 | 文档自定义编号 **或** `一、` | 反馈回复"问题1.XXX"；招股书"第一节 XXX"；无自定义编号文档用"一、" | 反馈回复版=0011；招股书版=001 |
| 二级 | `一、` | "一、主营业务与产品" | 002 |
| 三级 | `（一）` | "（一）行业基本情况" | 003 |
| 四级 | `1、` | "1、市场规模" | 004 |
| 五级 | `（1）` | "（1）竞争格局" | 005 |
| 六级 | `1）` | "1）可比公司" | 006 |
| 七级 | `①` | "① 收入构成" | 007 |
| 八级 | `A、` | "A、按产品拆分" | 正文加粗（超出标题层级） |
| 九级 | `a、` | "a、按区域拆分" | 正文加粗（超出标题层级） |

**核心规则**：
1. **反馈回复**：一级标题 = 自定义编号"问题1.XXX"（0011），二级标题序号从"一、"开始（002），三级从"（一）"开始（003），以此类推。
2. **招股书**：一级标题 = 自定义编号"第一节 XXX"（001），二级标题序号从"一、"开始（002），三级从"（一）"开始（003），以此类推。
3. **无自定义一级编号的文档**（备忘录/分析报告/尽调报告等）：一级直接用"一、"（对应 001），其后按表顺延。
4. 序号层级最多到九级（a、）；超出用（a）等变体或拆分表格，避免嵌套过深。
5. 样式映射：0011/001（一级/问题标题）→ 自定义编号；002 → "一、"；003 → "（一）"；004 → "1、"；005 → "（1）"；006 → "1）"；007 → "①"；更深层级用正文加粗（008/009 为表格专用，不承担标题）。

### ⚠️ 序号段落判定：标题 vs 正文（双维度算法）

以「（一）」「1、」「（1）」「1）」「①」等序号开头的段落，**可能是标题也可能是正文**，按**段落长短 + 上下文是否分段**两个维度判定，存在两种典型结构：

| | **情况1：标题 + 展开** | **情况2：列举正文** |
|---|---|---|
| 结构 | `1、标题（标题样式）`<br>`　　正文内容（正文样式）`<br>`2、标题（标题样式）`<br>`　　正文内容（正文样式）` | `1、正文内容（正文样式）`<br>`2、正文内容（正文样式）` |
| **段落长短** | 短：≤40 字、冒号式/短语式（标题特征） | 长：完整论述句、>40 字（正文特征） |
| **上下文分段**（主判据） | 序号段**后段有独立正文展开**：紧邻下一段是非序号开头的完整正文段落 | 序号段**后段为连续序号段**（列举链）或后段不存在（到文末/表格） |
| 样式 | 序号段 → 对应标题样式（003/004/005/006/007）；后段正文 → **000** | 序号段本身 → **000 正文**（连同后续序号段均为列举正文） |

**判定流程**（两个维度综合）：
```
遇到序号开头段落 P：
① 看长短：P ≤40 字且短语式（冒号结尾/无句号）→ 倾向标题；P >40 字完整句 → 倾向正文
② 看下文：下一段 Q——
   Q 存在、非序号开头、有实质内容 → 情况1（P=标题，Q=正文 000）
   Q 不存在，或 Q 也是序号开头 → 情况2（P=正文 000）
③ 综合：两维度一致直接定；不一致（短句但后无分段 / 长句但后有分段）→ **以上下文分段为主判据**
```
> 主判据 = **上下文是否分段**（后段独立展开 → 标题；连续序号列举 → 正文）；长短为辅助信号。
> 实证（超聚变案）："（1）全球算力基础设施市场规模快速提升。…""①工程化壁垒：…"均为情况2列举正文 → 000。
> 辅助核对：`check_styles.py` 的序号段落核对输出（--check-numbering）列出序号开头段落及上下文，供快速扫描。

## 二、表格三线表规范（表格模板.docx 内置示例表格实证）

> **权威实证**：表格模板.docx 的 document.xml 内置完整示例表格（可比公司指标表，6 行 8 列，两行表头），以下规范全部来自该表格逐单元格解析。

### 表格级（tblPr）

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 表格宽度 | **页面 100% 宽，Word 自动调整** | `tblW w:w="5000" w:type="pct"`（5000 pct = 100%） |
| 表格对齐 | 水平居中 | `jc w:val="center"` |
| 上下框线 | **1.5pt 黑色实线**（sz=12） | tblBorders top/bottom sz=12 |
| 内部框线 | **0.5pt 黑色实线**（sz=4） | insideH/insideV sz=4 |
| 左右框线 | **不加**（三线表式） | left/right 无 |
| 边框颜色 | **纯黑 000000**（弃模板原 010000） | color 000000 |
| 单元格边距 | 左右 57 dxa | `tblCellMar left/right=57` |
| 表格样式标记 | `tblLook w:val="04A0"`（firstRow/firstColumn 特殊处理） | tblLook 04A0 |
| 列定义 | 每列 gridCol 均分或按内容；Word 自动调整优先 | tblGrid（模板 8 列不等宽） |

### 行属性（trPr，每行必带）

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 禁止跨页拆行 | `cantSplit` | 每行均有 |
| 行高 | `trHeight w:val="397"`（约 0.7cm） | 每行 397 |
| 行对齐 | 居中 `jc w:val="center"` | 每行均 center |
| 表头行标记 | **多行表头每行都设 `tblHeader`**（跨页重复） | 行0/行1 tblHeader |

### 表头结构（支持复杂表头）

| 能力 | 规范 | 模板实证 |
|------|------|---------|
| 两级表头 | 第一行组头（如年度「2026年度」跨列合并）+ 第二行子头（如「金额/占比」） | 行0（gridSpan=2 年度）+ 行1（金额/占比） |
| 跨列合并 | 组头单元格 `gridSpan`（值为占列数） | 年度 gridSpan=2 |
| 跨行合并 | 类别列（如「可比公司」）`vMerge restart` + 后续行 `vMerge continue` | 可比公司/项目 行0-1 vMerge |
| 表头格式 | **加粗 + 居中 + 10.5pt（sz=21）** | cell 均 bold+center+sz21 |

### 内容对齐细则（按模板固化）

- **表头单元格** → 加粗 + 居中
- **首列/前几列文字**（类别/项目名）→ 左对齐（默认，不设 jc）
- **会计数字**（金额/百分比/数量）→ 右对齐（`pjc w:val="right"`）
- **合计行** → 「合计」标签跨列合并（gridSpan）+ **加粗**；数字右对齐 + 加粗
- 其余正文性内容 → 两端对齐

### 其他格式

| 要求 | 规范 | 模板实证 |
|------|------|---------|
| 字体 | 全表 **10.5pt（五号，sz=21）宋体 + Times New Roman** | 单元格 sz=21 |
| 垂直居中 | 单元格内所有段落**上下居中** | tcPr vAlign=center |

### 生成要求

- 表格按上表逐项设置（tblPr / trPr / 表头合并 / 对齐 / 字号 / 行高）；有模板示例结构可参考 `assets/templates/表格模板.docx`
- 禁止手写不一致边框（如只有部分框线、粗细不一）
- 简单表格（单行表头）与复杂表格（两级表头+合并）均适用本规范

## 三、通用排版铁律

1. **字体**：正文宋体小四（12pt）首行缩进2字符1.5倍行距；标题黑体（招股书版）或加粗（反馈回复版）
2. **数据**：保留两位小数，金额单位统一（亿元/万元），每个数字带时点+来源
3. **中文与半角字符之间不加空格（一律）**（2026-09-11 用户裁定「数字前后不加空格」；2026-09-16 用户扩裁「中英文之间同口径」，全文适用）：**中文（含全角标点）与半角字符（阿拉伯数字、拉丁字母）之间不加空格**。
   - ✅ 正确：「2025年」「3至5年」「135,360.57万元」「2030年1-6月」「占比80.06%」「共12项」「XPU芯片」「SVAC国标」「AI技术」「符合GB 35114标准」
   - ❌ 错误：「2025 年」「3 至 5 年」「135,360.57 万元」「占比 80.06%」「XPU 芯片」「SVAC 国标」「AI 技术」「符合 GB 35114 标准」
   - 适用范围：正文、各级标题、表格单元格、表注、图注，一律适用；**中文与半角字符之间的任何空格一律删除，不设情形豁免**
   - **所引名录／目录的条目编号与名称之间不豁免**——如「1.5 人工智能」应写作「1.5人工智能」（2026-09-11 用户二次裁定「一律不加空格」后收窄）
   - **唯一保留（两处，均在「两个半角字符之间」、交界处无中文）**：
     - **西文缩写与数字之间**：「GB 35114」「ISO 9001」「IEEE 3122-2025」这类**标准号／编号**内部的一个半角空格——该情形不属"中文与半角字符之间"，且国标编号的规范写法即为带空格
     - **英文词与词之间**：「Total Solution」等纯英文短语内部的空格，不受本条款约束
     - 注：标准号**整体与中文的交界处仍按本条款去空格**——「符合 GB 35114 标准」应写作「符合GB 35114标准」
   - **校验**：`check_content.py --checks spaces` 的「数字/英文前后空格」子项 + `deliver_gate.py` 的「标点规范」项（三处同源，`RE_SPACE_CJK_NUM` / `RE_SPACE_CJK_ALPHA`）；该规则属**文字层**，check_content 须在**套样式之前**跑（文字层返工会导致样式重做）
4. **日期**：YYYY年MM月DD日 或 YYYY-MM-DD
5. **反馈回复双段式结构**：【发行人说明与披露】逐项编号四级标题＋【中介机构核查及说明】（核查程序逐项定义抽样标准+核查结论）——监管问题黑体、回复宋体本身是合规展示
6. **段落间禁止空行/空段落**：段落间距一律靠样式 spacing（段前/段后）控制，**不得插入无文字的空段落（空行）分隔段落**。原因：①空段落无 pStyle，破坏样式体系统一性（被裸段落检查命中）；②样式自带 spacing（如 000 正文 beforeLines=50/afterLines=50）已提供间距，空段落造成间距叠加、版面失控；③空段落可能破坏标题 keepNext 链与大纲结构。适用：正文与正文、正文与标题、标题与标题之间均不得有空行；换段直接另起一段并应用对应 pStyle。
7. **只改格式、严禁修改原文内容（最高优先级）**：样式应用不得增、删、改、移任何文字内容（含表格内文字、标点、空格、数字、单位）。套用样式后用 `check_styles.py --verify-content <原文件>` 校验，文本逐字不一致即 FAIL。内容修改属内容层任务，本 skill 一律不做。
8. **标点用法**（规范源＝**GB/T 15834—2011《标点符号用法》**，2026-09-24 起纳入门禁；与「标点全半角」分工——本条管**用法**、不 reshape 字符形态）：
   - **数值范围起止用浪纹线 `~`**（§4.13.3.2 b）——「40%~55%」「1,000~2,000万元」「2023~2025年」。短横线 `-` **只用于**：连接**号码**（门牌/电话/**用阿拉伯数字表示的年月日**，§4.13.3.1 b）、编号（表2-8）、化合物名、复合名词、产品型号、外来语内部分合 ⇒ 故「2011-02-15」「表2-8」「WZ-10」「盎格鲁-撒克逊人」均为**正确**用法，**不报**。
   - **省略号不得与「等」「等等」并用**（附录 A.9.2）——「猪肝、大豆、油菜、菠菜……等」为误，二者二选一。
   - **图／表的短语式说明文字末尾不用句号**（附录 A.1）——「注：」「资料来源：」「数据来源：」「来源：」等**表下注行末尾不加「。」**。
   - **引用原文豁免**：上三条在**引号内**（`「」`／`“”`）一律不报——引用须照录，不得按规范改写他方原文。
   - **严重度分工**：省略号并禁、表下注末尾句号 → **MEDIUM**（计入 PASS/FAIL）；**数值范围用短横线 → LOW（仅提示、不阻断交付；该档位经用户 2026-09-24 确认维持）**——实测实务语料该写法基数极大（库内 **1132 : 46**），判阻断会致「逢查必红 ＝ 等于没有门禁」（同 R-0015 教训）。
   - **校验**：`check_content.py --checks punct_usage`（实现在 `content_text.py` 的 `check_punct_usage`）＋ `deliver_gate.py` 的「标点用法」项；**两处同源 —— deliver_gate 直接 import 复用，勿双写正则**（自本条起，双处同源由「手抄两份」改为「import 单一事实源」）。属**文字层**，须在**套样式之前**跑。
