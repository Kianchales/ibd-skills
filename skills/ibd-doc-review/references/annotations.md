# 批注复核交付规范（annotations）— 单一事实源

> 适用范围：IPO 复核结论以「批注」形式打在原文（Word docx / PDF）对应位置时的**格式单一事实源**（2026-09-06 用户裁定，替代原 2026-09-01「默认只出独立审核报告」）。
> 关系：本文件只定义**规范与校验**；复核结论落地的**执行器** = `ibd-doc-annotate` skill（批注版 = annotate_docx.py/annotate_pdf.py；修订稿 = revise_docx.py，规范见 revisions.md），产出以本文件为合规依据。

## 1. 交付形态（双轨并存 · 批注优先）

| 交付物 | 内容 | 优先级 |
|---|---|---|
| **批注版原文** | 复核问题逐条打成批注，锚定在原文问题句段上（docx → Word 审阅批注；PDF → 高亮+弹注），**第一交付物** | 必须 |
| **精简总览报告**（≤1页） | 条目编号 + 类型·严重度 + 锚点摘要 + 作者，与批注编号一一对应；兜底无法自动锚定的条目 | 必须（双轨兜底） |

> **修订稿（直接改好原文文字，仅用户明确「生成修订稿」时）= 复核落地第二形态，职权属 `ibd-doc-annotate` skill**（与批注同源：同一份问题清单，批注/修订同为其执行器形态；执行器 = `revise_docx.py --mode`，见 [revisions.md](revisions.md)）。本规范只管批注版。另：`ibd-doc-review` `check_styles.py --revise` 的格式修订（套样式差异转 Word 修订）是样式应用链路产物，属格式层，与复核交付无关。

> 载体自适应：有 docx 原文 → Word 批注（体验最佳：可回复/解决/接受拒绝流转）；只有 PDF → PDF 高亮+注释。**招股书 PDF→docx 转换有版面失真风险，禁止作为批注载体转换链路**（重建载体仅限演示用途并注明）。

## 2. 正文结构（4 行紧凑 + 引导词加粗分界）

每条批注正文固定 4 行，**无空行**（2026-09-06 用户裁定：块间空行导致批注条过长，边界由加粗承担）：

```
【J-01｜数据·正负号｜高】               ← 行1 标签行（加粗，独占一行）
「汇兑净损失」负值实为净收益…           ← 行2 标题行（加粗，单独一行）
问题描述：正文披露「汇兑净损失为-26.14万元…」……  ← 行3（「问题描述：」加粗）
建议：核对财务报表附注口径后……                  ← 行4（「建议：」加粗）
```

| 行 | 内容 | 排版（Word） |
|---|---|---|
| 行1 标签行 | `【编号｜类型｜严重度】` | **加粗**，独占一行 |
| 行2 标题行 | 问题一句话概括（最小概括，不重复细节） | **加粗**，单独一行；较长时自然换行，不与标签挤同一行 |
| 行3 问题描述 | `问题描述：` + 具体矛盾点/原文依据 | 仅「问题描述：」引导词加粗，正文常规 |
| 行4 建议 | `建议：` + 修改建议（「改为…」「核对…后统一…」指令式） | 仅「建议：」引导词加粗，正文常规 |

实现：
- **Word**：4 行各为一个 `<w:p>`（CommentText 样式），**不插入空行段**；引导词加粗 = 独立 run 带 `<w:b/>`
- **PDF**：弹注为纯文本（无加粗/字体控制），行间 `\n` 分隔，靠行首引导词分界

## 3. 编号体系（全局贯通）

- 前缀 = 复核人代号，**由复核流程自定义**（1-2 个大写字母，如 `J`=财务复核人、`L`=法律复核人、`I`=行业复核人、`Z`=综合复核人——本规范不绑定具体人名，脚本不内置映射，清单条目以 `code` 字段提供前缀）
- 序号 = 该前缀下本次批注的全局递增序号（01 起，如 J-01/J-02）
- **家族子编号（同根因跨位置的扩展形态，2026-09-09 增补）**：同一根因问题需锚定多处且位置互不相邻（跨章/远距）时，共享主编号并追加小写字母序号 `J-01a`/`J-01b`——每条子批注正文同构（标签行 `【J-01a｜类型｜严重度】`），总览按主编号 J-01 聚合、子条分行列出位置。**默认推荐形态 = 单批注 + desc 位置内联**（同根因多位置合一条批注、desc 列全衍生位置——门禁现兼容，中星微 Z-06/Z-07 即先例）；家族拆分仅在「单锚无法就近覆盖」时使用，**采用前须扩展 check_annotations 编号唯一性校验支持子字母尾缀**（当前按纯数字序号校验）
- 与**精简总览报告**条目一一对应（同一编号互相回溯）；编号生成前一次性分配登记

## 4. 问题类型词表（固定）+ 严重度

| 大类 | 类型标签 | 释义/触发场景 |
|---|---|---|
| 数据 | 数据·口径 | 统计口径不清/约数表述/口径不可溯源 |
| 数据 | 数据·勾稽 | 同指标跨处数值不一致、表内勾稽不平 |
| 数据 | 数据·完整性 | 缺年度标注/缺口径说明/披露要素缺失 |
| 数据 | 数据·正负号 | 收益/损失方向与措辞矛盾 |
| 表述 | 表述·绝对化 | 龙头企业/领先/唯一等无依据的绝对表述 |
| 表述 | 表述·衔接 | 表述与上下文/治理架构/其他章节口径不衔接 |
| 表述 | 表述·歧义 | 指代不明、读者易误读 |
| 披露 | 披露·充分性 | 期后重大事项、风险量化、影响披露不足 |
| 披露 | 披露·时效 | 数据/政策截至时点与披露时点不匹配 |
| 合规 | 合规·一致性 | 与法规/审核要求/申报口径不符 |

严重度三档：**高**（必改：事实/口径/合规错误）｜**中**（应改：披露充分性、表述规范）｜**低**（建议改：完整性、衔接、可读性）。
词表为**固定清单**，新增类型须在规范登记，禁止复核人自造标签。

## 5. 字体字号（Word 批注统一）

| 项 | 规则 |
|---|---|
| 中文字体 | 宋体 |
| 西文/数字 | Times New Roman |
| 字号 | 10.5pt（五号，`w:sz=21`） |
| 加粗 | 标签行、标题行**整行加粗**；问题描述/建议**仅引导词加粗** |
| 段落样式 | CommentText（`w:pStyle`）——样式写入 `styles.xml` 统一控制，**不随复核人手笔变化** |

作者/日期/缩写由注入程序自动生成（`w:author`=复核专家花名、`w:date`=ISO8601、`w:initials`=花名拼音首字母），不手写进正文。

## 6. 锚点规则

- 每条批注锚定**问题句段**（最小可定位文本），不锚整章整节
- docx：`paragraph.text` 子串匹配；跨 run 按 start_char 拆 prefix/anchor/suffix 三段重排，`commentRangeStart/End/Reference` 顺序插入
- PDF：字符级匹配（容忍空格/换行/数字单位间断字），高亮覆盖锚点文本

## 7. docx 注入必备部件（Word/WPS 兼容最小集）

- `word/comments.xml`（必须）
- `[Content_Types].xml` Override（必须）
- `word/_rels/document.xml.rels` Relationship（必须）
- `word/styles.xml` 补 `CommentText` 段落样式 + `CommentReference` 字符样式（建议；缺失则 Word 显示批注但标记不上标）
- `commentsExtended.xml` / `commentsIds.xml`（可选：回复/解决状态，默认不生成）

## 8. 校验门禁（scripts/check_annotations.py）

docx 侧：comments 条数 == commentRangeStart/End/Reference 对数；每条 4 段且无空段落；标签行/标题行整行加粗；「问题描述：」「建议：」引导词 run 加粗而正文常规；编号前缀 ∈ {J,L,I,Z} 且不重复；CommentText/CommentReference 样式存在；Content_Types/rels 注册齐全。
PDF 侧（有 pymupdf 时）：高亮注释数与问题清单条数一致；每条弹注 content 首行以 `【编号｜` 开头；编号唯一。

> 输出：`<文件>_批注校验报告.md`；任一不符 → 退回 ibd-doc-annotate 重新注入，不交付。

## 9. PDF 载体差异速览（Word ↔ PDF 对照）

> 本节是 §1/§2/§5/§6/§8 中 PDF 差异点的**汇总视图**，不新增规则；规范本体仍以对应各节为准。执行器 = `annotate_pdf.py`（ibd-doc-annotate）。

| 维度 | Word（docx 审阅批注） | PDF（高亮 + 弹注） |
|---|---|---|
| 适用场景 | 有 docx 原文（体验最佳：可回复/解决/流转） | 仅有 PDF 原文 |
| 载体转换 | —— | **禁止 PDF→docx 转换作为批注载体链路**（版面失真风险；重建载体仅限演示用途并注明，见 §1） |
| 锚定方式 | `paragraph.text` 子串匹配；跨 run 拆三段重排，commentRangeStart/End/Reference 顺序插入（§6） | 字符级匹配（容忍空格/换行/数字单位间断字），高亮覆盖锚点文本（§6） |
| 4 行正文结构 | 同构 §2：4 个 `<w:p>`、无空行段 | 同构 §2，但**纯文本**：无加粗/字体控制，行间 `\n` 分隔，靠行首引导词分界 |
| 弹注首行 | 标签行 `【编号｜类型｜严重度】` 加粗独占一行（§2） | 首行以 `【编号｜` 开头（门禁强校验，§8） |
| 视觉承载 | 字体字号体系（§5：宋体/Times New Roman/10.5pt/加粗分界） | **高亮颜色不承载语义**——执行器用默认高亮色，未实现严重度→颜色映射；严重度靠弹注首行文字 |
| 作者/日期 | `w:author`/`w:date`/`w:initials` 自动生成（§5） | PDF 注释作者字段由执行器写入复核花名 |
| 校验门禁 | §8 docx 侧全检：comments 结构/样式/加粗/编号前缀唯一/Content_Types/rels | §8 PDF 侧（有 pymupdf 时）：高亮注释数 == 清单条数；弹注首行前缀；编号唯一 |
| 配套产物 | —— | `annotate_pdf.py` 同步生成总览表（编号/类型·严重度/锚点摘要/作者/状态），与精简总览报告口径一致 |
