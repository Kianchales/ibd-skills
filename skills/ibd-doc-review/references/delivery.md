# 章节复核交付约定

> 本文是「章节复核类委托」的交付形态与职权规范。**触发**：用户说「研究下XX节，帮我看看描述逻辑、语法有没有错误」等复核类指令。
> 细则来源：用户级长期记忆（补批注纪律），迁入本文件；记忆侧只保留铁律摘要。

---

## 零、进门第一档：检查项声明（先声明，再动手）

> **动因**：粗颗粒的「查格式／查内容／查财务」回答不了「到底查了什么」——复核覆盖面若无显式声明，就落入模型随机性：同一份稿两次复核查出两套东西，用户既无法判断结论覆盖到哪、也无法对照验收。**未声明即未约束。**

**顺序铁律**：任何复核委托，**动手第一步**是输出《本轮检查项声明》，然后才谈交付形态与深度。**三要素采「反问确认制」（R-0057）**：**每份文档首次复核委托时，AI 就三要素各出一问（合并为一张三行小表，不拆三连问），每问附推荐项**（推荐＝批注版／标准深度）；用户确认或改选后才动手。**同一文档内后续委托沿用已确认组合、不再反问**（不限时间）；**换文档 ⇒ 重新三问**；用户中途明示改任何要素即刻生效并作为该文档后续新默认。**措辞纪律（R-0046 延伸）**：三问表**人话为主、编号只作括注**（模板 → [check-scope.md](check-scope.md) §六）。

| 顺序 | 事项 | 说明 |
|---|---|---|
| **第一档** | **检查项声明** | 查哪些项／不查哪些／为什么——**明细清单与模板 = [check-scope.md](check-scope.md)** |
| 第二档 | 交付形态 | 批注版／文本定稿／修订稿（§五）——**反问确认，推荐批注版** |
| 第三档 | 深度档位 | L1/L2/L3——**反问确认，推荐 L2 标准预填**（§七） |

**声明单四要素**（模板见 [check-scope.md](check-scope.md) §六）：

1. **检查**——本次实际要跑的项，**按域 ＋ 性质**列编号（A 文字格式／B 内容质量／C 财务〔细分 **C-P 专业判断 / C-Q 数值正确性 / C-D 执行要求**〕）
2. **不查**——跳过的项**逐项点名 ＋ 原因**（写「未查」不算，要写清为什么）
3. **特别专项**——S1 读取前置／S2 片段模式／S3 敏感议题／S4 数据基准，命中情况写明
4. **交付前将跑**——域 F 交付件核验（自动执行，不进勾选；D 法律／E 行业为预留域，未启用不提）

**三条纪律**（与 SKIP 同纪律——静默缩范围＝静默失败）：

- **未核即声明**：跳过项必须点名，不许用「默认全查」蒙混过去
- **首尾一致**：动手前的声明 ⟷ 交付报告头的范围声明（§八）必须是**同一份**；中途增减项须**重新声明一次**，不许悄悄改
- **档位只是预设**：L1/L2/L3 只给默认勾选组合，用户点名加减某项一律照办

**唯一的简化情形**：命中 S2 片段模式时，声明单可以变短（只列本段可核的子集 ＋ 跳过的全文性项），但**「先声明再动手」本身不免除**。

**用户原话**（存档）：

> 「我觉得查什么东西需要再明细展开区分，要在每次检查前声明，上提到第一档」

## 一、默认交付形态 = 批注版原文 + 精简总览

**双轨并存、批注优先**：

- **主交付物**：章节复核结论以**原位批注**打在原文对应位置——载体自适应：
  - docx 原文 → Word 审阅批注
  - 仅 PDF → PDF 高亮注释
- **配套交付物**：另附 **≤1 页精简总览报告**，编号与批注**一一对应**，兜底无法自动锚定的条目。
  **总览报告 = MD 版 + Word 版双格式**——MD 供程序读取/检索归档，
  Word 供批阅流转；两版内容同源一致，由 `ibd-doc-annotate` 的 `overview_to_docx.py` 同链路自动产出
- **不主动扩展**：除非用户明确说「生成修订稿」，否则**不主动生成修订稿、不主动推进数据复核/法律复核等后续环节**

## 二、执行链路

```
复核问题清单 + 原文
  → ibd-doc-annotate 注入（脚本自动编号 J/L/I/Z+序号、锚点定位、4 行紧凑排版）
  → ibd-doc-review deliver_gate.py --annotated 门禁（含基础十项 + 批注两项）
  → 交付
```

**门禁是硬关卡**：门禁返回非 PASS 一律退回 `ibd-doc-annotate` 重注入，不得带瑕疵交付。

**推荐一条命令跑完**（基础十项 + 批注两项，共十二项）：

```bash
python scripts/deliver_gate.py --docx <批注版.docx> --annotated --expect-annotated <条数> \
       [--md <内容源.md>] [--anchors "36,507.55;19.96"]
```

`--annotated` 已覆盖 `check_annotations.py` 的 **docx 侧**全部硬性断言（部件 / 结构 / 编号）；只有 **PDF 侧**高亮注释校验仍需单独跑 `check_annotations.py --pdf`。修订稿同理：`deliver_gate.py --revised [--expect-revised N]` 覆盖 `check_revisions.py --mode revise` 的全部断言（含落定证明）。

## 三、批注/修订职权划分

| 产出形态 | 归属 skill | 说明 |
|---|---|---|
| **批注版**（原位批注） | `ibd-doc-annotate` | 复核落地形态之一 |
| **修订稿**（直接改好原文文字） | `ibd-doc-annotate` | 与批注同源、同为复核落地形态 |
| **格式修订**（套样式链路） | `ibd-doc-review` | `check_styles.py --revise`，**与内容复核无关** |

**修订稿执行器**：`ibd-doc-annotate/scripts/revise_docx.py --mode`
- `revise` = Word 修订模式（留痕）
- `clean` = 直接改好（无痕）
- `both` = 双版

按提示词区分模式；修订规范 = 本文所属 skill 的 [revisions.md](revisions.md)；门禁 = `deliver_gate.py --revised`（等价覆盖 `check_revisions.py --mode revise`）。

## 四、只加批注不改原文（红线）

- 注入**不改动原文任何文字**
- 锚点段落含**复杂 run**（换行/制表）或**骑跨超链接** → **不自动注入**，记入总览「未锚定」条目，交人工定位
- 格式单一事实源：批注正文结构 / 编号规则 / 10 类类型词表 / 字体 / 锚点规则 → [annotations.md](annotations.md)
  - 正文 4 行紧凑无空行；标签行/标题行加粗；问题描述与建议仅引导词加粗

## 五、触发语与路由（三形态）

| 用户措辞 | 路由 |
|---|---|
| 「研究下XX节，帮我看看描述逻辑、语法有没有错误」 | **批注版形态**：默认输出**批注版 + 总览**（原 Word 版完整审核报告降级为可选）——前提：该项目未声明过形态 |
| 「问题X定稿」「逐条列修改点」「直接给文本」「给出修改后文本」 | **文本定稿形态**：逐条「原文→改后」对照输出（不进批注、不出修订稿、不出独立审核报告）；清单条目 `rev` 字段全量填充（可粘贴定稿文本） |
| 「生成修订稿」「出一版修订稿」「直接改好」… | 进入修订流程，但**先反问形态**（revise / clean / both）再执行 |

**铁律 1（形态三选一）**：批注版／文本定稿／修订稿三形态互斥，一次委托只出一种；文本定稿形态是批注版的**对等替代**（不是降级）。

**铁律 2（文档级确认记忆 · R-0057）**：**每份文档首次复核委托，形态作为三要素反问之一确认**（附推荐「批注版」）；**同一文档内后续委托沿用已确认形态、不再反问**（不限时间）；**换文档 ⇒ 重新确认**；用户明示改形态 ⇒ 即刻生效并作为该文档后续默认。**铁律 3（修订先反问）**：不按措辞直接路由到修订——任何修订类说法都必须先确认 revise/clean/both，避免猜错模式导致返工。

**铁律 4（文本定稿形态 = 清单 `rev` 字段全量填充）**：文本定稿形态的交付物不是「问题清单」，而是**可直接粘贴的定稿文本**——清单条目 **`rev` 为必填**（承载「改后」全文）、**`advice` 可省**；输出按条目排列「原文 → 改后」对照。schema 层已用 `anyOf` 表达该条件：`advice`／`rev` **二者至少其一**（`problems.schema.json`）。
- **rev ≠ advice**：`advice` 是**指令式建议**（「核对…后统一…」），`rev` 是**可直接粘贴的文本**——复核员在文本定稿形态下同时承担「改稿建议人」角色，故 rev 升为主交付物、不再是例外。
- **一条链路两种用途**：rev 字段亦为修订稿形态（`ibd-doc-annotate/scripts/revise_docx.py`）的替换源——「今天给文本、明天要修订稿」无需重做。

## 五之二、复核 → 写作回流（P6）

复核发现的落地形态有三条去向，**不得混淆**：

| 去向 | 载体 | 触发 |
|---|---|---|
| 原位批注 | `ibd-doc-annotate` 注入 docx/PDF | 批注版形态 |
| **可粘贴定稿文本** | 清单 `rev` 字段（逐条） | 文本定稿形态（**常态**，非例外） |
| 修订稿（留痕/无痕） | `revise_docx.py --mode revise/clean` | 用户明确要求 |

> 复核产出**如何喂给改稿**是有定义的：`rev` 即为标准接口。缺 rev 的条目不得静默丢弃——入总览「待定稿」清单。

## 六、批注纪律（跨项目）

- **全量进批注**：确认的问题**不分大小全部进批注**（批注体现全量）
- **清单照常保留**：问题清单 / 精简总览**与批注并行交付**，编号一一对应
- **被禁止的只有一种**：只进清单、不批注
- **覆盖单元 = 根因问题**：同源连锁错误**合为一条**，位置由清单兜底（不是每个表象各批一条）
- **条数上限**：单文件 ≤200 条；>400 条**拆分交付**——超限处置是**拆/并，不是删条目**

**用户原话**（存档）：

> 「错误不分大小都要批注」
> 「批注要体现全量，清单本身还是要留的」
> 「全量覆盖也不能个个都批」

**细则落点**：`ibd-finance-review` execution-discipline 铁律 2 + 细则 9、issue-list-format §1.1、`ibd-doc-annotate` validate_issues、[annotations.md](annotations.md) §3。

**驱动案例**：某芯片设计项目 v3 遗留 7 项低危 → v4 全部转批注 Z-12~Z-18。

## 七、复核深度档位（L1/L2/L3 · 声明单的默认预设）

> **定位（2026-09-28 起）**：档位**不再是独立于检查项的第二套选择**，而是 [check-scope.md](check-scope.md) §七那张「默认勾选组合」表的别名——选定档位＝把声明单预填一遍，**预填之后仍可逐项加减**。这样「深度」与「查了什么」说的是同一件事，不会出现「选了 L3 却漏了某项」的口径裂缝。
> **为什么原本要有档位**：复核精细度若无显式定义即落入模型随机性（同委托产出粒度时大时小）——**未定义即未约束**。深度是委托的显式参数，不是 AI 的临场发挥。

> **分档轴 ＝ 性质**（2026-09-29 用户校正）：**L2 装「机器能判的」**（格式规范／数值正确性／执行要求）；**L3 装「只有人能判的」**（专业判断）。

| 档位 | 名称 | 做什么 | 不做什么 | 适用场景 |
|---|---|---|---|---|
| **L1 快扫** | 表面核对 | 标点/错别字/明显数字错误/禁词扫描 | 不做勾稽、不逐数登记、不出台账 | 定稿前最后一遍过；片段粘贴快速过 |
| **L2 标准**（**默认档**） | 数字与格式全核 | L1 ＋ A 域全项 ＋ B1–B8（含 **B6/B7 交稿前自检与自评**，随交付步执行）＋ **五类机械勾稽全算（C-Q 全量）＋ 逐数台账（C-D，零未核项）** ＋ 问题清单全量输出 | **不做专业判断（C-P）——不出「会计处理是否恰当」的意见** | 章节复核常规委托（未声明深度时） |
| **L3 深核** | 专业判断 | L2 ＋ **C-P 专业判断全 16 维**（`ibd-finance-review` 维度走查，AI 只提质疑）＋ **（预留）法律专业复核、行业专业复核** | —— | 需要会计处理／法律／行业**判断意见**时；问询回复定稿 |

**路由与声明**：
- 触发语映射：「快速过一遍」「扫一眼」→ 推荐 L1（仍走三要素反问确认）；用户表态档位 → 照办；**未表态 → AI 推荐 L2 并反问确认**（R-0057，不再静默默认）。
- **模糊时反问一问**（与修订形态反问同纪律）。
- **档位落地方式 = 预填声明单**（§零）：报告头与该声明单**同一份**——「本次复核深度＝L2 标准（含勾稽与台账，未含会计专业判断）」。声明未做与声明 SKIP 同纪律（静默降档＝静默失败）。
- **升档随时可加**：L2 交付后用户要求「再深核一遍」→ 在 L2 产物之上补 L3 差量，不重跑 L1/L2。

## 八、报告头范围声明（与进门声明首尾一致）

> **范围选择器（域 × 子项）**已升格为进门第一档，明细见 [check-scope.md](check-scope.md)、动作规范见本文 §零。本节只留报告头的**落款义务**：凡非「全项」复核，交付报告头必须显式写明——「本次核对范围＝财务勾稽（域）；**未核：文字与格式／内容质量／禁用词**」。**动手前声明什么，报告头就写什么**，两处不一致即视为静默缩范围。
