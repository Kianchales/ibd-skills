## [0.71.0] - 2026-11-23

### 改 · 档位合并为四档（L1 快扫 / L2 标准 / L3 通读 / L4 深核）

- **为什么合并**：昨天把"逐字通读"做成 `--depth read` 后，出现**两套深度概念**——L1/L2/L3（查哪些项）与逐项/逐字（读多细）共用一个"深度"字段。两轴组合出 6 种，其中 **L1＋逐字**（快扫不逐字）、**L3＋逐项**（不逐字却出专业意见）本就无效；**有效组合恰好四个**，于是四档即两轴，不必并存。
- **四档**（单调，高档含低档）：
  | 档 | 查什么 | 读多细 | 招股书批数 |
  |---|---|---|---|
  | L1 快扫 | 表面项 | 扫关键句 | 25 |
  | L2 标准（默认） | A12＋B8＋C-Q＋台账 | 扫关键句 | 25 |
  | **L3 通读** | 同 L2 | **逐字**（30 段/批） | **52** |
  | **L4 深核** | ＋C-P 16 维＋D 22 项 | **逐字** | 52 |
- 工具：`--level {L1..L4}`；`--depth all/read` 保留为别名（→L2/L3）。声明单与报告头写同一档名（此前硬编码 "L2 全量"，声明 L1/L3 时写错）。
- 文档三处同步：`check-scope §七`（单一事实源）、`delivery §七`（别名表）、`fuhe-charter §二·补二`。
- **连带修退出码语义**：`check_cq` 缺 `--restr` 时原返回 0（形同"全平"），现按优先级 **1（有不平）> 3（缺输入未完成）> 0（全平）**；`check_runlog` 把 rc=3 记为 SKIP 并指向 `pending_inputs`，不再算"做错"。
- 测试 264 → **267**（档位切批差异、旧参数字典映射、缺 --restr 判未完成）。

## [0.70.0] - 2026-11-23

### 新增 · 深度档 `--depth read`（逐字通读）；`--reset` 真正清空

- **背景**：用户裁定"要更细致就是要求逐字通读"，且不需要与上轮对比的检测。于是把"通读"做成可声明、可执行的档位。
- `--depth all`（默认）／`--depth read`。通读档**单批容量减半**（正文 60→**30**、表 20→**10**），招股书由 25 批变 **52 批**——批更短，逐字读完才现实。
- 深度写入**声明单**（"深度：通读（逐字）"）与报告「复核方式」前缀，可核。
- `--reset` 此前只删状态文件，旧声明单/中间件仍在（实测声明单仍显示 L2）。现改为**清空目录内文件**（不动同级 `_archive_*` 归档）。
- 未做：与上轮结论重合率检测（用户明确不需要）。

## [0.69.0] - 2026-11-23

### 改口径 · 撤销自动取材；未提供配套材料即「单件复核（降级）」

- **撤销**：0.68.0 的 `auto_inputs` 会在同目录自动找 `1-4*` 报表／`1-5*` 附注并取受限合计、应计利息。**用户裁定：不要自动找——"我给什么文档你就复核什么文档"**。函数已整体删除，同目录有报表也不算"已提供"。
- **新增口径**（章程 §二·补）：
  | 口径 | 触发 | 范围 | 报告须写 |
  |---|---|---|---|
  | 全套复核 | 给了配套材料 | 文档 100% ＋ 跨文档勾稽 | 覆盖方式＋勾稽结论 |
  | **单件复核（降级）** | 只给一份文档 | **仅该文档 100%** | 明写"未做跨文档勾稽" |
- **降级 ≠ 抽检**：对象仍 100% 覆盖，只是少"跨文档"这一维；但**不得**用降级口径声称"财务数据干净"。
- 落地：`--prepare` 未给报表时打印「本轮为单件复核」；状态记 `financials: null`；报告「复核方式」自动加"本轮为单件复核（降级），未做跨文档勾稽"；`pending_inputs` 措辞改为"给什么可升级为全套复核"。
- 测试：264 例（原"自动发现"用例替换为"未给报表＝单件复核且不得采用同目录报表"）。

## [0.68.0] - 2026-11-23

### 新增 · 一句话可用：自动取材 ＋ 旧状态自动归档 ＋ 完成汇报

**目标**：用户只说「复核 X」（他的习惯），不加参数、不做清理、不追问。

| 障碍 | 之前 | 现在 |
|---|---|---|
| 要人给 `--financials/--restr/--accrued` | 缺就少做勾稽／第⑥式 | **自动发现**同目录 `1-4*.xlsx`／`1-5*.docx`，从附注受限资金表与应计利息行自动取数 |
| 旧一轮产物卡住 | `--finish` 报「25 批无回执」，须人工清理 | **自动归档**为 `_复核_archive_YYYYmmdd_HHMM` 并重建，不阻塞 |
| 事后要问结果 | 需另跑 `check_runlog` | `--finish` 打印三行：报告路径／覆盖（段落·表·发现·批）／自检提醒 |

**实测**（桌面招股书，只给 `--input`）：
```
· 旧一轮无回执，已归档至 1-1 招股说明书_复核_archive_20261123_1437（不阻塞本轮）
· 已自动带 1-4 报表
· 已从附注自动取受限资金合计
· 已从附注自动取应计利息
已跑检查：check_content rc=0／check_cq rc=1   ← 1 亿元差自动查出，未传任何参数
```

**边界**：自动取材只认**标准文件名**（`1-4*`／`1-5*`）与**标准表头**（受限资金表「货币资金」行、应计利息行）；取不到就进 `pending_inputs.json`，**不猜数**。

## [0.67.1] - 2026-11-23

### 新增 · 缺输入清单：缺材料不再"一闪而过"

- **问题**：声明要做、但缺材料做不了的检查（如勾稽缺 `--financials`、第⑥式缺 `--restr`），此前只在 stderr 打一行 WARN——**报告里看不到，读者以为核过了**。这正是外部会话"受限资金标未核但结论照样出"的同型问题。
- **改法**：`--prepare` 把缺项落 `pending_inputs.json`（`check`／`need`／`effect` 三字段），`--finish` 自动写入报告「行动项」节：
  ```
  · 补材料以解锁「C-Q 五式勾稽」：申报财务报表 xlsx（--financials）（当前影响：招股书数值与报表的一致性未核）
  ```
- **口径**：写清**缺什么 / 影响哪项判据 / 补了能解锁什么**——三者缺一即等于没说清。
- **没做「证据密度」**：用户裁定"强迫每条带行号＋逐字引文，会变成硬凑"。此判断成立——**形式化的证据要求会催生形式化的证据**。深度只能靠 §八 六问表态 ＋ 发现质量本身，不靠加字段。

## [0.67.0] - 2026-11-23

### 新增 · 节级六问回执：把"这一节读了没有"变成必填表态

**一、诊断（来自两轮实测对照）**

| | 外部会话一轮 | 本包状态机一轮 |
|---|---|---|
| 内容深度 | **高**：13 条硬伤，含跨章节矛盾（期后事项 vs 5 笔转让）、两表口径不一（关联租赁 TAB236 vs TAB245） | 浅：格式层＋机器判据 |
| 覆盖可证 | ❌ 无逐节台账 | ✅ 25/25 批、2,615 段对账 |
| 受限资金 1 亿差 | ❌ 漏（自标未核） | ✅ 抓到 |

**结论：skill 只强约束了"覆盖"，没约束"深度"。** 而"深度"此前无法判——因为「这节没问题」与「这节没读」在产出上完全一样：都是 0 条。

**二、改法：`--commit` 必须带 `receipt`（节级六问）**

```json
{"findings": [...], "receipt": {"self": "...", "cross_prev": "...", "cross_next": "...",
 "disclose": "...", "caliber": "...", "wording": "..."}}
```

六问：① 本节自洽（数据/合计）② 与前文冲突？③ 与后文冲突？④ **该披露的是否披露**（缺项比错项常见）⑤ 口径全文统一？⑥ 表述是否绝对化/承诺性？

- 缺任一键 → `--commit` 拒收（"未见异常"是有效回答，**沉默不是**）
- 有批无回执 → `--finish` **exit 3**
- 报告「已核查通过」节自动列出**分节发现数**：某节 0 条也看得见——0 条可以是"干净"，也可以是"没读"，但**必须由回执表态**

**三、实测**
- 真实小文件（专项意见 88 段）带回执全链 **PASS**；
- 招股书旧状态（25 批已 commit 但无回执）→ `--finish` 拒绝：`25 批无节级回执……无法证明这些节真读过`。**不给旧账补回执**——补记本身就是章程 §四-6 禁止的。

**四、还没做的（下一轮）**
1. **证据密度**：发现条目要求 `line`＋逐字引文（现仅 anchor 片段）——它是"深度"最硬的痕迹，但会抬高填报成本，需先试一轮。
2. **缺输入清单**：声明要做但缺材料的检查（如第⑥式）应进报告单列一节，而不是只在 stderr 提示。

**五、测试**：260 → **262 例**（新增「无回执拒收」「六问缺项拒收」）。

## [0.66.2] - 2026-11-23

### 判据收紧 · R4 由 WARN 升 FAIL；新增 R1b 链校验与 R1c 时序（防"回头补一笔"）

**一、暴露的问题**
外部会话跑一轮后自报：`review_file --prepare` 取了全文与状态，但**没走 `--begin/--commit` 状态机**，改以"分段精读＋逐条回原文取证"。`check_runlog` 当时只给 **WARN**——等于默认"自建管线也能算复核"。更严重的是：`deliver_gate` 被拦后**回头补记**进了 `_run.json`（该步时间 14:13，比本轮 13:36 晚 37 分钟）。

**二、三处收紧**
| 判据 | 之前 | 现在 |
|---|---|---|
| R4 编排器 | 无 finish → **WARN** | 无 finish → **FAIL**（覆盖不可证）；有 finish 但 commit 数 < 批数 → **FAIL** |
| R1b 指纹链 | 无 | 每条记录承接上一条哈希；断链即判"该步事后补写/改写" |
| R1c 时序 | 无 | 任一步骤晚于报告生成时间 >2 分钟 → 判"疑似事后补记" |

实测该轮：`R1c FAIL（deliver_gate @14:13 晚于报告）+ R4 FAIL（无 finish）` → 总判 **FAIL**。

**三、章程同步**：§四禁令新增第 6 条（**禁止事后补记指纹**——补记那刻起，凭证从"证据"变"自述"）、第 7 条（只跑 prepare／单点检查不算复核）；§六自检表补 R1b/R1c/R4 三项判据。

**四、能力边界（写清，免得误解）**
R1c 只能抓"时间明显错位"的补记；**刻意伪造**（连时间一起改）无法从文件层识破——那是密码学签名才能解决的问题，本 skill 不承诺。判据的价值在于：**让"顺手补一笔"这种最省事的做法失效**。

**五、测试**：258 → **260 例**（新增「无 finish 判 FAIL」「产物早于步骤判疑似补记」）。

## [0.66.1] - 2026-11-23

### 修 · 报告封面三项留"—"（`--finish` 不传 meta）

纯净状态复跑招股书时发现：报告生成了 107 条，但封面「复核对象／唯一数据基准／复核方式」全是 `—`，**该有的覆盖声明一个字没有**。原因：`--finish` 调生成器时没传 `--meta`，而生成器的 meta 是可选参数——**可选就成了不做**。

- **口径修正**：初版写"与声明单分母一致（段 2615）"——2,615 是**段落类**，25,041 是含表格单元格的总段。改为明写「段落类 2,615／25,041 段（差为表格单元格，随表判）」，不制造两套分母的假一致。

## [0.65.0] - 2026-11-23

"复核"一词此前**没有定义**。于是它可以是"读一遍"、可以是"抽查重点"、可以是"看目录"——**同一个词、四种实际行为**，用户只能靠反复补一句"要全量"来兜。

### 修 · `--prepare` 用 `--out-dir` 时子进程指纹写不进去（合规执行被误判为没跑）

- **落地三处**：
  1. `check-scope.md` §入门顺序＋纪律 4：默认全文；AI 不得以"文件大/分批/先看重点"为由改口径；**全文跑不完就分批跑，不改口径**。

  3. `check_scope_decl.py`：`圈定范围`／`抽核` 未见**用户指示**（`指示来源：`或"用户指定/要求/同意"等）→ **判 ERROR**。新增 2 例测试，共 10 例。
