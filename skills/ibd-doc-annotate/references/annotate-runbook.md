# 批注落地规程（annotate-runbook.md）

> 本册是步骤 **2. 执行注入 / 修订** 中**批注侧**的详规：命令、脚本自动完成事项、docx 跨 run 锚定、PDF 侧要点、同段多批注的 range 修复、表格型文档的锚点选法。

## 一、命令与产物

**载体选择**：Word `docx`（推荐，批注体验最佳：可回复/解决/接受拒绝）或 PDF。
⛔ 招股书 PDF→docx 转换有版面失真风险，**禁止作为批注载体转换链路**；PDF 就用 PDF 批注。

```bash
# Word 载体（输出 <原文名>_批注版.docx + _批注总览.md）
python scripts/annotate_docx.py --docx <原文.docx> --issues issues.json [--out <输出.docx>]
# PDF 载体（--pages "5-6" 可只保留节选页；缺省保留全文）
python scripts/annotate_pdf.py --pdf <原文.pdf> --issues issues.json [--pages "5-6"] [--out <输出.pdf>]
```

批注脚本自动完成：编号分配（按清单顺序，作者代号+序号）→ 锚点定位 → 批注注入（正文 4 行紧凑排版）→ 总览生成（md + docx 双格式，2026-09-18 用户裁定）。

后处理：`scripts/fix_missing_ranges.py` 补插丢失的批注 range（同段多批注冲突），详见本册 §五。

## 二、docx 跨 run 锚定

- **跨 run 锚定**：docx 锚点常横跨多个 run——脚本按字符坐标把 run 切成片段（首片段复用原元素、其余深拷贝保留 rPr），段落文本零改动；含 `w:br/w:tab` 的 run 判定为复杂 run 不自动切
- **复杂 run 检测为兜底而非缺陷**：真实申报稿正文多为简单 run，自动处理率高；少量兜底条目人工定位后如需批注/修订可手工加或扩清单重跑

## 三、PDF 侧要点

- **pymupdf 页对象须持有引用**：`page = doc[pno]` 后再 `add_highlight_annot`，内联 `doc[pno].add_highlight_annot(...)` 的页代理被 GC 会报「annotation not bound to any page」

## 四、批注排版纪律

- **批注内禁空行段**（用户裁定）：4 行紧凑，边界靠加粗引导词；不要插空 `<w:p/>`
- **编号一次性分配**：批注/修订稿/总览共用同一编号，禁止生成后再改顺序

## 五、同段多批注互相清除 range（实测 2026-09-06）

主循环逐条注入时，同段落后续批注的段落重建会删除先前已插入的 `commentRangeStart/End`，导致 comments.xml 有批注但 document.xml 丢 range（check_annotations 报 cs/ce/ref 对数 < 批注数）。修复：跑 `fix_missing_ranges.py <docx> <issues.json>`（本包 scripts/ 下）后处理补插（按 issues.json 锚点重定位切 run 插 range），补完重跑门禁；交付前门禁必过。**门禁只校验 cs/ce/ref 对数**——2026-09-14 修掉其「锚点落在单个 run 内时 end 标记插到 start 之前」的顺序颠倒缺陷（对数相等故会静默放行）

## 六、表格型文档的锚点选法（实测 2026-09-20）

**表格型文档（财务报表附注）锚点优先选「数据行内全文唯一数值」**（实测 2026-09-20 某科创板在办项目申报财务报表附注，23 条）：附注正文以表格为主体，**表头/标题单元格与合并单元格常含多 run 或换行**，若以其文本作锚点会命中「复杂 run → 注入受限 MISS」（实测两条：表标题「净资产收益率和每股收益情况」、表内负数列「-300,000.00」）。改用**同表数据行内全文唯一的数值串**（如 `618,700,673.50`、`-29.1125`、`20,132,615.91`）即可正常注入。定锚前先做一次命中计数（正文段落＋表格单元格段落），**取命中数 = 1 的数值串**；命中数 >1 的须再降级（多行重复的合计数改用同表独有明细数）或接受「首命中」并在总览标注。**财务报表附注类文档的批注清单，锚点字段应默认按「唯一数值」而非「表标题/句段」填报。**
