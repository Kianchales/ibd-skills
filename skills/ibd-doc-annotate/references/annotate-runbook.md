# 批注落地规程（annotate-runbook.md）

> 本册是步骤 **2. 执行注入 / 修订** 中**批注侧**的详规：命令、脚本自动完成事项、docx 跨 run 锚定、PDF 侧要点、同段多批注的 range 修复、表格型文档的锚点选法。

## 一、命令与产物

**载体选择**：Word `docx`（推荐，批注体验最佳：可回复/解决/接受拒绝）或 PDF。
⛔ 招股书 PDF→docx 转换有版面失真风险，**禁止作为批注载体转换链路**；PDF 就用 PDF 批注。

```bash
# Word 载体（输出 <原文名>_批注版.docx + _批注总览.md）
python scripts/annotate_docx.py --docx <原文.docx> --issues issues.json [--out <输出.docx>]
# PDF 载体（--pages "5-6" 可只保留节选页；缺省保留全文）
python scripts/annotate_pdf.py --pdf <原文.pdf> --issues issues.json [--pages "5-6"] [--out <输出.pdf>]
```

批注脚本自动完成：编号分配（按清单顺序，作者代号+序号；同前缀超 99 条顺延双字母分段，序号恒两位）→ 锚点定位 → 批注注入（正文 4 行紧凑排版；段落内非文本内容原位保留）→ 总览生成（**恒只产 md、为中间件不交付用户**；人读报告改由 `review_report_to_xlsx.py` 出复核报告 Excel）。

后处理：`scripts/fix_missing_ranges.py` 补插丢失的批注 range（同段多批注冲突），详见本册 §五。

## 二、docx 跨 run 锚定

- **跨 run 锚定**：docx 锚点常横跨多个 run——脚本按字符坐标把 run 切成片段（首片段复用原元素、其余深拷贝保留 rPr），段落文本零改动；含 `w:br/w:tab` 的 run 判定为复杂 run 不自动切
- **复杂 run 检测为兜底而非缺陷**：真实申报稿正文多为简单 run，自动处理率高；少量兜底条目人工定位后如需批注/修订可手工加或扩清单重跑

## 三、PDF 侧要点

- **pymupdf 页对象须持有引用**：`page = doc[pno]` 后再 `add_highlight_annot`，内联 `doc[pno].add_highlight_annot(...)` 的页代理被 GC 会报「annotation not bound to any page」

## 四、批注排版纪律

- **批注内禁空行段**（用户裁定）：4 行紧凑，边界靠加粗引导词；不要插空 `<w:p/>`
- **编号一次性分配**：批注/修订稿/总览共用同一编号，禁止生成后再改顺序

## 五、同段多批注互相清除 range

主循环逐条注入时，同段落后续批注的段落重建会删除先前已插入的 `commentRangeStart/End`，导致 comments.xml 有批注但 document.xml 丢 range（check_annotations 报 cs/ce/ref 对数 < 批注数）。修复：跑 `fix_missing_ranges.py <docx> <issues.json>`（本包 scripts/ 下）后处理补插（按 issues.json 锚点重定位切 run 插 range），补完重跑门禁；交付前门禁必过。**门禁只校验 cs/ce/ref 对数**——2026-09-14 修掉其「锚点落在单个 run 内时 end 标记插到 start 之前」的顺序颠倒缺陷（对数相等故会静默放行）

> **根因已修（2026-09-29 注入器原位保留版起）**：段落重建改为只重建锚点覆盖的文本 run、非文本内容原位保留，同段多批注不再互相清除 range，本工具降级为**旧版产出的存量修复**用途（补完仍须重跑门禁）。

## 六、表格型文档的锚点选法

**表格型文档（财务报表附注）锚点优先选「数据行内全文唯一数值」**（实测某科创板在办项目申报财务报表附注，23 条）：附注正文以表格为主体，**表头/标题单元格与合并单元格常含多 run 或换行**，若以其文本作锚点会命中「复杂 run → 注入受限 MISS」（实测两条：表标题「净资产收益率和每股收益情况」、表内负数列「-300,000.00」）。改用**同表数据行内全文唯一的数值串**（如 `618,700,673.50`、`-29.1125`、`20,132,615.91`）即可正常注入。定锚前先做一次命中计数（正文段落＋表格单元格段落），**取命中数 = 1 的数值串**；命中数 >1 的须再降级（多行重复的合计数改用同表独有明细数）或接受「首命中」并在总览标注。**财务报表附注类文档的批注清单，锚点字段应默认按「唯一数值」而非「表标题/句段」填报。**

## 七、注入会丢弃同段 `w:tab` run（「原文零改动」须逐段核验）

- **症状**：注入后 `check_annotations` PASS，但「原文未改动」核验失败——逐段比对可见某段少 1 个字符。实测：段落 `10.<TAB>股东分红回报规划的制订周期和调整机制`（run 拆为 `'10.'`＋`'\t'`＋`'股东…'`）注入后变成 `10.股东…`，中间的 `w:tab` run 被段落重建吞掉
- **触发面**：锚点所在段落内**另含 `w:tab`/`w:br` 的兄弟 run**（即使锚点本身不跨复杂 run 也会中招）。招股书正文中 Tab 极少（多为 `N.<TAB>标题` 的编号行），故通常只 1~2 处、易被漏掉
- **必做核验**：交付前**逐段比对原文与批注版 `p.text` 列表**（`[i for i,(a,b) in enumerate(zip(A,B)) if a.text!=b.text]`），不能只跑 `check_annotations`——门禁只查批注配对，查不出正文被改
- **修复（zip 级补回，勿用 python-docx 重存）**：定位该段 XML 中承载 `10.` 的 `<w:r>`，其后插一个只含 `w:tab` 的 run，保持 `rPr` 一致：
  `<w:r><w:rPr><w:rFonts w:hint="eastAsia"/><w:color w:val="000000"/></w:rPr><w:tab/></w:r>`
  用 `zipfile` 重写 `word/document.xml`（其余条目原样回写），**不要**用 python-docx 打开另存——避免批注部件被重序列化。补完重跑逐段核验＋门禁双校验

> **根因已修（2026-09-29 注入器原位保留版起）**：未覆盖 run（含 `w:tab`/`w:br` 兄弟 run）原样保留，不再被段落重建吞掉；本节**逐段比对核验纪律仍为交付前必做**（不能只跑门禁），zip 级补回手段保留用于旧版产出。

## 八、复核对象带修订标记（`w:ins`/`w:del`）时的口径

- **症状**：`python-docx` 读出的 `p.text` 出现**语义残缺**（如 `包括政府机关、和重大安保等领域，以及等行业应用领域`——「特种安全」「城市安全、智能治理…」整段列举凭空消失）。这不是文档坏了，而是**读到了错误口径**
- **根因**：`Paragraph.text` 只拼接 `<w:p>` 的**直接子** `<w:r>/<w:t>`。被 `<w:ins>`／`<w:del>` 包裹的 run 不是直接子元素，故① `w:ins` 内的新增文本**读不到**、② `w:del` 内的 `<w:delText>` 本就不计入。结果 `p.text` ≈ 「未触碰的原文」，既非"接受修订后"也非"拒绝修订后"，据此复核会**大面积误判**（凭空报"句子残缺"）
- **复核前必做探测**：`len(re.findall(r'<w:ins ', xml))` / `<w:del ` / `<w:delText`。非零即处于修订未接受态
- **两套正确口径**（按客户意图二选一，勿混用）：
  - **接受修订后** = `''.join(t.text for t in p.iter(qn('w:t')))`（`iter` 会下钻 `w:ins`；`w:del` 内的 `delText` 非 `w:t` 故自然排除）
  - **拒绝修订后（原稿）** = 同上再把 `w:delText` 计入、把 `w:ins` 内文本剔除
- **判据**：客户说"我已完成修改"≠ 修订已接受；**先探测再复核**，并在交付说明中讲清复核依据的是哪套口径。若客户要求继续迭代，**优先让客户在 Word 里"接受所有修订"后另存**再跑链路（本包注入器不处理修订标记，混跑会有 range 与修订标记的交互风险）
- **配套观察**：`commentReference` 计数可判前序批注是否被清理（客户"清洁"后应为 0，且 `word/comments.xml` 部件消失）——注入前确认，避免与残留批注冲突

## 九、二次批注（在已带批注的文档上注入）

- **注入前先探测既有批注**：`commentReference` 计数 / `word/comments.xml` 部件存在性（§八配套观察同源）。非零即在他人批注底稿上作业，按下述路径二选一，**不得不判定直接注入**
- **修好版注入器（2026-09-29 原位保留版起）→ 可直接注入**：段落重建只重建锚点覆盖的文本 run，同段他人批注锚点（`commentRangeStart/End`）、书签、超链接、`w:tab`/`w:br` 兄弟 run 等非文本内容**原位保留**——双方批注共存，无需剥离
- **旧版脚本（修复前版本）禁用直接注入**：旧版段落重建清空全部非 run 子元素，会**静默删除同段他人批注锚点**。对旧版产出或无法升级的场景，**要么先剥离**既有批注（Word 审阅面板「删除全部批注」后另存，或等价脚本，须连空 run 一并清）得干净底稿，**要么换用修好版**再注入
- **交付前三重校验**：① 逐段比对原文与批注版 `p.text`（§七核验法）；② 门禁 `check_annotations`；③ 二次批注场景加验「他人批注锚点仍在」——批注版 cs/ce 对数 ≥ 注入前既有批注数，缺了即回滚排查
