# 护栏体检详表（维护域 · 步骤 1）

> 脚本单一事实源：`scripts/check_methods_health.py`（治理 D 档建立）。蒸馏 S7 第⑤步自动执行（沉淀后门禁）；维护域按需手动执行。

## 用法

```
cd {METHODS_ROOT}
python scripts/check_methods_health.py            # 全量检查（打印逐项结果）
python scripts/check_methods_health.py --quiet    # 安静模式：省去表头与统计行，**ERROR/WARN 明细照常打印**
python scripts/check_methods_health.py --json     # 结构化输出（含 verdict/error/warn/抽样数/issues，供上层消费）
python scripts/check_methods_health.py --strict   # WARN > 0 时以退出码 3 退出（默认不影响退出码）
```

> **判定接口与退出码**（2026-09-26 WO-18 立；判据：**退出码不承载信息，报告才是接口**）：
> **判定接口 ＝ 报告输出**（文本，或 `--json` 的 `warn` 字段与逐项 `issues`）；**退出码只表「有无 ERROR」**，不表 WARN。
> 退出码：`0` = 无 ERROR（可有 WARN）｜`1` = 有 ERROR｜`2` = 前置失败（未找到库）｜`3` = `--strict` 下 WARN > 0。
> ⇒ **自动化若只读退出码，WARN 不可见**——须另读报告或改用 `--json`；需要「WARN 即阻断」的场景显式加 `--strict`。
>
> **⚠️ 事实订正（2026-09-26）**：此前记录「`--quiet` 吞掉 WARN ⇒ 无人值守下 WARN 永久不可见」**不成立**——ERROR/WARN 循环本就在 `if not quiet` 之外，两种模式下均照常打印，且 `--json` 早已含 `warn`。真实缺口仅为「退出码看不见 WARN」，而按上引判据，这**本就不该由退出码承载**。
>
> **留痕纪律（取证／对照类运行必读）**：本脚本**默认把本次结果追加进库操作日志**（同日同「结果行」已存在则跳过）。⇒ **凡「故意制造缺陷」的对照运行（阴性／阳性对照、探针、排障），必须加 `--no-log`** —— 否则会把**故意造出来的 ERROR 写成库的真实体检记录**，污染 append-only 台账（台账＝接续时判断「上周发生了什么」的唯一依据，且**按纪律不回改历史行**，一条伪事件会长期误导）。**取证要留痕、对照不留痕**。

> **体检前置 · 审计面清单**：体检/审计的**作用面须显式枚举**，不得默认等同 `methods/`。三者缺一即为盲区：
> ① 库内正文面 `{METHODS_ROOT}/`（含 `40_单案/`、`50_分卷/`、`30_行业版/`）；
> ② **库内归档面** `cases_md/`（产出件归档，**可能落后**）；
> ③ **蒸馏现场面** `<蒸馏工作区>/cases/`（产出件原始存放地，**全量**）。
> **凡查产出件/案目录，① 与 ③ 两处并查**——**「库内搜不到」≠「不存在」**（实证：曾据此误判天广实 PL 提炼件「未归档」，实际在工作区）。
> 历史教训（历次审计只扫 `methods/`，18 案范式文件缺归集，长期不可见）。

## WARN 档位约定（2026-09-26 WO-19 立）

- **本库 WARN 一律 `soft`**（`severity=soft`）：只进报告与日志，**不影响退出码**。
- **不设 `hard` WARN**：需要阻断的场景应把该检查**升格为 ERROR 项**——档位保持单一，避免「软硬混用」造成判读歧义。
- **⚠️ 关于「警告生命周期绑定检查」——本库不适用**：其做法是「停用某检查 ⇒ 清除该检查产生的旧 `lint_warnings`」。本脚本每次**全库无状态重算**，WARN 由当前实况现场算出、**不落盘、无陈旧态可清**。该机制解决的是**有状态系统**的「陈旧警告」问题，本库结构上不存在该问题（**属设计优势，非缺口**）。
- **要观测「新增／已消」的动向**：不靠陈旧警告，而靠**操作日志逐次留痕 ＋ 计数 diff**（见 WO-26）。
