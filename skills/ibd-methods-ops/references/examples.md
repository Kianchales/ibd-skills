# 示例（examples.md）—— 第一次把库跑起来

> **本册只给「串联示例」**；每一步的**规则本体**在各自册，不在此复制：
> 建库与库规范 → [methods-guide.md](methods-guide.md)｜蒸馏生产 → [distill-methods.md](distill-methods.md)｜检索 → `ibd-methods-query`｜库规矩 → [library-rules.md](library-rules.md)

## 示例 0 · 从零建库 → 就绪验证（**推荐首跑**）

**场景**：完全没库，第一次用。

| 步 | 你做 | 会发生什么 |
|---|---|---|
| 1 | 说一句：「**帮我建方法论库**」（或直接抛一次检索需求） | 走**「库配置」四问引导**（或 `ibd-methods-query` 的**冷启动引导档**） |
| 2 | 回答「库放哪」——**默认建议 `~/methods/`**，你也可以给任意路径 | 在该路径下建**空库骨架**（按 [methods-guide.md](methods-guide.md) §三「起步结构」的生成物 ＋ §九 空库起步模板） |
| 3 | 确认后端（本地目录／Obsidian／云知识库任选） | 生成 `library.config.json`（**落点＝本 skill 安装目录**） |
| 4 | **就绪验证（一条命令）** | 见下 |

```bash
python scripts/refresh_index.py --methods-root <工作区根>
```

**判定**：**EXIT 0 即「库已就绪」**。该命令会生成／刷新索引体系与库自描述，正常输出形如：

```
=== 索引体系刷新（库根: <你的库根>）===
✓ parse_titles.py — DONE
✓ gen_index.py — DONE
✓ gen_toc.py — DONE
✓ gen_entry.py — 入口已重写
✓ gen_refgraph.py — 引用图谱已生成
✓ gen_schema.py — schema 版本水位 = <skill 版本> ｜ 库内容水位 = —
=== 全部完成 ===
```

> ⚠️ **新空库不要去跑全库体检**（`check_methods_health.py`）——那是**内容库**的体检：空库**必然**报「库内 schema 入口缺失／生成物引用断链／索引行号无法抽查」等项，**属设计使然，不代表装坏了**。体检的正确时机是**库里有内容之后**。
> ⚠️ **配置是本机文件**（不随包分发）：换机或重装后需**重建**；**库本身在你指定的目录里，不会丢**。

## 示例 1 · 沉淀第一份材料（内容从零到一）

| 步 | 你做 | 会得到 |
|---|---|---|
| 1 | 「**执行蒸馏学习**」＋ 给材料（单文件／文件夹／项目） | 走蒸馏链（选材 → 材料准备 → 蒸馏 → 综合成文 → 入库 → **索引刷新** → 护栏校验） |
| 2 | 材料不齐时 | 如实报告缺口，并把待补材料**登记至 `<工作区根>/state/待补学清单.md`** |
| 3 | 入库后 | 条目落库并**自动刷新索引**（无需手动） |

**沉淀的判据**：能在索引里**查到新条目编号**，且条目标题目录里有它的**行号**。

## 示例 2 · 检索验证（闭环最后一环）

| 步 | 你做 | 会得到 |
|---|---|---|
| 1 | 「**查 XX 问题怎么写**」（走 `ibd-methods-query`） | 命中：条目编号 ＋ 文件 ＋ 行号 → 定向读取 |
| 2 | 若**索引路与全文路皆空** | **如实告知「本库暂无对应条目」** ＋ 声明 `已检索（索引 n ＋ 全文 m）` |
| 3 | 同时 | **把该缺口登记至 `<工作区根>/state/待补学清单.md`** |

**闭环示意**：

```
建库 → 蒸馏入库 → 检索命中（编号即引用）
                    └─ 未命中 → 登记 <工作区根>/state/待补学清单.md
                                        └─ 下次蒸馏把它补上 → 再从清单销项
```

> **关键**：**登记与销项是同一本账**（`state/待补学清单.md`）——写作侧、检索侧登记的缺口，蒸馏选材时能直接捞到；**换名字另起一本账，等于把缺口丢进黑洞**。

## 示例 3 · 反向场景：写作时发现缺条目

| 步 | 表现 | 处置 |
|---|---|---|
| 1 | 写作查库时**两路皆空** | 向使用者明确提示「该问题在库中暂无对应条目（已检索：索引 n ＋ 全文 m）」 |
| 2 | 继续写 | **降级不阻断**：改用 writing-style 高频句法库兜底（「能写、但不地道」档） |
| 3 | 收尾 | G4 对照表声明「本库暂无对应条目」＋ 所引句式清单 ＋ **登记至 `state/待补学清单.md`** |

> 写作侧的规则本体不在本 skill：见 `ibd-doc-write` 的「降级与缺口登记」。

---

## 三个最容易踩的（新用户）

1. **以为装了包就有库** —— 库要自己建（本册示例 0），包只给能力。
2. **建完库就去跑全库体检、看到一片红以为坏了** —— 空库**不该**跑体检（见示例 0 的告警）。
3. **缺口登记随手换个名字** —— 必须落 `state/待补学清单.md`；三处异构命名会让回收机制看不见。
