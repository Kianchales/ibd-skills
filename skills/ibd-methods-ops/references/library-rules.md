# 方法论库 · 规则总览

> **本文件是什么**：把散布在 ADR／契约／SKILL 纪律／手册／门禁脚本里的规则，按「**四层**」收敛成一张可查阅的地图。
> **本文件不是什么**：**不是细则事实源**——每条规则的真身在下表「细则落点」；本文件只做导航与关系说明，冲突时**以细则为准**。
> **维护**：改细则 → 顺带核对本文件对应行；本文件自身不承载新规则。

## ① 体系层（跨 skill）

### 1.1 判据集（13 条 · `docs/CONVENTIONS.md` §一）

| 判据 | 核心内容 | 用在什么时候 |
|---|---|---|
| **发布分界** | 是否依赖**具体项目事实**——领域知识公开、项目事实私有 | 决定内容进公开包还是私有层 |
| **介入点判据** | 能否给出**客观判据**：能 → 脚本门禁；不能（判断/拍板）→ 人工介入点 | 新增一环时决定要不要留人 |
| **收录门槛** | 是否**超出当下任务必要范围**（防队列变第二个 MEMORY） | 决定规则/事故是否入册 |
| **事故处置三选一** | 新增护栏（脚本门禁/检查清单/ADR）／裁定不设（记理由）／列待办 | 事故发生后 |
| **归档层级判据** | 归档物一律入顶层归档区；**归档前核对引用面**——被护栏依赖的属活跃资产，回迁 | 归档任何文件前 |
| **盘点事实源** | 盘点类任务先读**工作日志台账**（私人库，落点见接入指南）建基线；记忆摘要与 `_backup/` **可作线索不得作结论** | 任何盘点/清点 |
| **能力裁断前置核验** | 「某工具能不能用」须先核**本机环境**；上游 skill 的禁令是给**其运行环境**写的 | 迁移/引用外部 skill 时 |
| **护栏以实测命中为准** | 批量护栏动作须逐项**实测生效**；「声明已覆盖」≠「已覆盖」 | 加 `.gitignore`/门禁规则时 |
| **骨架标准强制面** | P4 骨架标准**只强制公开包**；私有包缺口不计欠债（`EXEMPT` 级呈现） | 全局体检统计口径 |
| **强制面分层** | 骨架层只强制公开包；**工程层全量强制 17 个自建包**——两层互不覆盖 | 同上 |
| **仓健康判据** | `git fsck` **无 `error:` 行**即健康；`dangling` 不判不健康 | 仓体检 |
| **落点归属判据** | 资产归属由**能力域**决定，不由"当时顺手放哪"决定；同域只允许**一个**细则事实源 | 新增/迁移脚本或知识段 |
| **文件类型词用产品名** | 面向读者写 Word/Excel/PPT/PDF（技术对照语境例外） | 写任何交付文档 |

### 1.2 工程范式（`docs/ENGINEERING.md`）

**8 原则**：单一事实源 · 只读优先 · dry-run · 幂等 · 结构幂等 > 文本启发式 · 输出契约化 · 零私有绑定（＋分层强制面）。
**写操作六步**（改库/改脚本的铁律）：
① 备份 → ② dry-run → ③ 幂等检查 → ④ 执行 → ⑤ **改后自校验**（`compile()` ＋ **行尾守恒**；双 CR 不得新增）→ ⑥ 收尾（刷索引/跑门禁/留痕）。
**脚本五段头**：用途 · 用法 · 参数 · 退出码（0/1/2/3）· `--json`；错误走 stderr。
**目录与命名**：`scripts/_lib/` 放共享库；脚本 snake_case、文件 NN_ 前缀。

> ⚠️ **今日实证（I-0024 复发）**：第 ⑤ 步必须**内建进脚本**，不能只写在文档里靠人记得跑——A10 行尾门禁在发布环节，日常改库不经过它。

### 1.3 人工介入点（13 处 · `docs/CONVENTIONS.md` §三）

四类：**①判断类**（4 处，脚本替代不了的语义核对）· **②拍板类**（5 处，等一句话）· **③兜底类**（3 处，降级出口，**属设计不是欠债**）· **④环境盲区**（1 处，写进边界声明）。
与本库直接相关的：**#8 方法论学习范围与沉淀去向**（全部由用户定）· **#9 S7 体检发起时机**（满 ~40 案例）。

## ④ 触发层（流程与纪律）

### 4.1 蒸馏全流程（S1–S7 · `references/distill-methods.md`）

`S1 选材 → S2 材料准备 → S3 阅读包 → S3.5 既有方法论速览（预取激活）→ S4 三专家并行产出（§S4 五要素／三要素）→ S4.5 自检门禁 → S5 写作角色综合成文 → S5.5 场景演练（未演练不算提炼合格）→ S6 入库（反向更新）→ S7 回写（行号级）`

### 4.2 S7 回写三过滤（`docs/adr/0007`）

| 过滤 | 内容 | 目的 |
|---|---|---|
| ① **复现阈值** | 跨案例复现 **2 次**即并入（Q10 修订：原 5–10 次） | 守数量（防低复现噪声） |
| ② **冲突改旧** | 新候选与既有条目冲突 → **先修订旧条目**而非新增 | 守一致性（防同主题多版本并存） |
| ③ **用户裁定再裁定** | 与用户既有裁定冲突 → **不得直接覆盖**，停下提请再裁定 | 守权威（防静默覆盖用户裁定） |

### 4.3 S7 执行纪律（9 条 · `SKILL.md` §S7）

①起草前先汇编工作表 → ②书写形态遵循契约 → ③落盘脚本块级锚点＋幂等限本条目 → ④完成后必跑 refresh＋health → ⑤抽验窗口覆盖「适用场景」行 → ⑥引用与数字须来源对齐 → ⑦案数不写死数字 → ⑧契约自检前置（0 ERROR 才落盘）→ ⑨案名一律用规范案名。

## ⑤ 规则之间的关联与优先级

### 5.1 引用链（谁引用谁）

```
CONVENTIONS（判据集）
   └─ 强制面分层 → ENGINEERING（工程层全量强制）
   └─ 落点归属判据 → 决定细则落哪个 skill
                        └─ entry-contract（条目怎么写）
                              ├─ check_entry_contract A1-A4（机器拦）
                              └─ SKILL §S7 纪律①-⑨（人/流程遵守）
ADR-0007（三过滤）→ S7 回写决策
ADR-0016（分层强制）→ ENGINEERING §7
ADR-0017（书写契约）→ entry-contract
ADR-0018（案名规范）→ 案名规范表 ＋ A4
```

### 5.2 冲突裁决顺序（高 → 低）

1. **用户当场裁定**（最高；写入 ADR 后成为第 2 级）
2. **ADR / 判据集**（有裁定来源的成文规则）
3. **契约与手册**（库层细则）
4. **SKILL 纪律**（流程性要求）
5. **历史惯例**（最低；与上面冲突时一律改历史）

**三条硬裁决规则**：
- **规范优先**（用户 2026-09-19 裁定 D6-1）：单案层回到 §S4/§S5 规范字段名，不迁就历史写法。
- **冲突改旧**（ADR-0007 ②）：修订旧条目，不新增平行版本。
- **不得静默覆盖用户裁定**（ADR-0007 ③）：冲突则停下再裁定。
- **强制面互不覆盖**（R-0009/ADR-0016）：骨架层与工程层分别计数，**不混算欠债**。

### 5.3 统计纪律（三条自检 · 2026-09-19 落 · 动因 I-0025）

**凡「统计类结论」上报前必须过三条自检**。动因是同一天两次同型误判：回写清单报「0 销项」（实际 47，状态列是 `| [x] |` 表格形态）、案号报「**29 案未分配**」（实际仅 2 案无号——`grep` 抓到表头说明句「案号 AN0001-AN0021」当成了首案案号）。**这两次的错误结论都直接进了用户决策面。**

1. **命中为 0 或结果全同值 → 必核**（几乎总是模式写错／取错行形态，而非真的「没有」）
2. **与上次统计差异 > 50% → 必核**（同口径稳定量的突变本身就是信号）
3. **换第二种形态或工具交叉一次**（表格行 vs 列表行、`grep` vs python 解析、「首个命中」vs「众数」）

**反模式**：单一模式匹配就上报、只看 `tail` 输出、把「工具报 0」当成「确实没有」。

## ⑥ 易误解点（实战教训清单）

| # | 容易误解 | 正解 |
|---|---|---|
| 1 | 「`分卷/` 是生成物，不手改」 | ❌ **分卷 = 手写条目正文的唯一存放地**（P 系列 442 ＋ 体例域 276）；只有「索引/目录/路由入口」等才是生成物。2026-09-19 已更正契约 §1 |
| 2 | 主文件写「当前为空（待补做）」＝ 真没做 | ❌ 可能是**过期陈述**（P 系列 442 条早已产出，主文件却仍写"当前为空"）——**判断前先核分卷/索引实况** |
| 3 | 「案名 = 简称」 | ❌ 是**证券简称**；在审企业取交易所 IPO 项目页「公司简称」。禁截断（「微容」≠「微容科技」）、禁全称、禁代号 |
| 4 | 分卷不跑 A1/A3 ＝ 漏检 | ❌ **有意设计**：分卷字段自成一套（语用/方法/互见），强套主库字段规范会产生无意义 ERROR |
| 5 | 「裸 `PAGE N` 没改 ＝ 没修完」 | ❌ **不可机械转换**：只见「PAGE 249」无法判断是招股书还是第几轮回复。归 D6-2「只约束今后」；能判定的（`第1轮 PAGE 73`→`问1 P73`）已全改 |
| 6 | 推送失败时 git 打印 `Everything up-to-date` | ❌ **不可信**（伴随 HTTP 408/502）；判据只认 `main -> main` 或 `ls-remote` 比对；稳妥做法＝清代理＋加大 postBuffer 重试 |
| 7 | 案数写「五案验证」「N 案共通」 | ❌ 案数随回写变化，写死即失真；统一「多案验证／多案共通」 |
| 8 | 跨案层条目下写「本案实证」 | ❌ 库是跨案层，「本案」**无指代对象**；跨案层用 `**实证**`／`**<案名>实证**` |
| 9 | 回写 ＝ 改写旧条目 | ❌ 高重合＝**并入**既有实证区（不改案数表述）；中高＝**独立段**；只有冲突才改旧 |
| 10 | 契约要检查所有加粗字段 | ❌ 契约**只约束 9 个字段名**，其余（内容小标题/门禁标记/元信息）**不检查**（强制面收缩原则） |
| 11 | 改了内容 = 索引自动更新 | ❌ 必须跑 `refresh_index.py`（parse→index→toc→entry 四步）；改了标题/行数不刷索引，目录行号即失效 |
| 12 | 行尾/编码不会出问题 | ❌ **双 CR 是静默缺陷**（`.py` 里 `\r` 也是换行 ⇒ `compile()` 抓不到）；改 CRLF 文件禁 `split("\n")+join("\r\n")`；**追加内容用「按文件实际行尾 `split(nl)`／`join(nl)`」**——2026-09-19 又栽一次：`seg.rstrip("\n")` 在 CRLF 文件上留下 `\r`、再加 `\r\n` 即成双 CR（被落盘前断言拦下） |
| 13 | 产出文件写「案号：待分配」＝ 正常流程 | ❌ **是欠账**：`S-TBD-NN`／`PL-TBD-NN` 占位属历史（当时号未定）；现号已定（AN0001–0075），应回填为 `S-AN{案号}-NN`。2026-09-19 已回填 cases/ 层 5,700+ 处 |
| 14 | `state/` 是杂项目录 / 可以随手放东西 | ❌ 它是**状态台账唯一落点**（进度·登记·反查表），有明确判据与四问门槛（见 `state/README.md`）；内容/任务/规矩分别归 methods／tasks／docs |
| 15 | 统计脚本报 0／全同值 ＝ 确实没有 | ❌ **先怀疑检测器，再怀疑数据**：命中 0、结果全同值、与上次差异 >50% 三者任一 ⇒ 必换第二种方法交叉（§5.3 统计纪律；I-0025 两次误判都属此类） |
