# 条目与回写书写契约

> **一句话**：回写产出的内容与库内既有知识必须**同规**——同一字段、同一标签、同一来源标注；本契约是这一"同规"的**单一事实源**。
> **裁定** D1–D5（全部回改／标签收敛双轨／标签去日期／来源统一前置／契约落本文件）。机制侧（触发·流向·顺序·三过滤）见《回写机制统一设计》。

## 2 实证项：四字段模型

**一个「实证项」＝ 四字段**，与排布无关 —— 机器解析只认字段，不认排版。

| 字段 | 必填 | 规范 |
|---|---|---|
| **案名** | ✅ | **规范案名 ＝ 证券简称**（与单案 `case` 字段一致，如「中科仪」；未上市／在审企业取申报文件中的公司简称）——**禁**公司全称、**禁**截断简称（略去通名后缀，如「微容」≠「微容科技」）、**禁**内部代号；不得省为「本案」。白名单与登记见 §2.1 |
| **案号** | 建议 | `AN00NN`；用于反查单案文件与回写清单 |
| **内容** | ✅ | 该案在本条主题下的**做法/数据/口径**（陈述式；禁评价性论证与形容词堆砌） |
| **来源** | ✅ | 见 §4；数字须与来源同源（同一句内禁跨来源混列） |

### 2.1 案名白名单（落地 A4）

> 用户原话：「案名一定要用规范的案名，用证券简称。」

- **单一事实源**：库根《`方法论_案名规范表.md`》——表一（有单案文件）／表二（无单案文件的早期案）构成**白名单**；**表三 ＝ 别名映射（库内旧写法 → 规范案名）**，仅供回改脚本使用、**不入白名单**（别名一旦出现在标签里即报 ERROR）
- **核定口径**（口径「核定后修改，核定不了就删了那个简称」）：已上市／挂牌取**证券简称**；在审取**交易所 IPO 项目页「公司简称」字段**（当日实例：云深处→「云深处」、上海超硅→「上海超硅」、兆芯→「兆芯集成」、维安→「维安股份」、鑫华→「鑫华科技」、盛合→「盛合晶微」）；**核不出来的一律从表中删除**，不留悬案
- **适用范围**：库内**一切案名引用位**——实证标签 `**<案名>实证**`、并列清单 `（案名）`、`案名/案名`、族条目尾注 `（案名）`、表格「案名」列、正文指代
- **落地口径**：① 新案蒸馏**先登记规范案名**再写条目；② 白名单外案名引用 → A4 报 ERROR；③ 疑似截断（某白名单案名的真前缀）→ A4 报 ERROR 并给出规范名；④ 标签内写死案数（`三案实证`）→ A4 报 ERROR
- **校验**：`python scripts/check_entry_contract.py --methods-root <工作区根>`（A4；白名单为单案 `case` 字段 ＋ 登记表的并集）

## 3 三种排布（同一数据，三种呈现）

**排布 1 · 列表式（默认）** —— 适用：≥1 案且单案内容 ≤2 行
```
**实证**：
- 环能涡轮（AN0019）——FOB/CIF/CFR「孰晚」确认时点，占比 FOB 49.20%/EXW 22.18%（招 P152；问1 P176-177）
- 森峰激光（AN0021）——出口数据差异率 0.76%/1.02%/0.16%（问1 P216-217）
```

**排布 2 · 独立段式** —— 适用：单案增量 ≥3 行，或含子结构（多级列表/表）
```
**<案名>实证**：
- 细项一……（来源）
- 细项二……（来源）
```

**排布 3 · 表格式** —— 适用：≥3 案且需逐案列出处（列名固定）
```
**实证**：

| 案号 | 案名 | 实证 | 出处 |
|---|---|---|---|
| AN0042 | 三协电机 | …… | 招 P14；问1 P182 |
```

**排布 4 · 回写修订标记型** —— 适用：中/中高重合**扩展**既有条目的适用场景（`apply_rewrite.py` 产出）
```
> **适用场景扩展 YYYY-MM-DD（<案名>）**：<扩展内容> —— <依据>（<来源>）
```
> **与「标签禁用第三条」的关系（勿混）**：本形态**含日期**，但**不受**禁日期约束——该禁令只管 `实证` 标签（`**实证**`／`**<案名>实证**`）；本形态属**修订留痕**（与 §S6「冲突修订留痕」同族），日期是其功能所需。此前它未登记于本节，属**契约册漏收**（审计 C-04 补）。

## 4 来源标注契约

**格式**：`（来源简称 + 空格 + P + 页码）`；多来源用 `；`，页码区间用 `-`、并列用 `、`

**硬性要求 · 禁裸页码（2026-09-28 立）**：**凡引用必写来源简称**——`（P180）`／`（PAGE 180）` 这类**只写页码、省掉简称**的写法**不合规**。

- **为什么**：来源简称是「这条内容出自哪份文件」的**唯一机器可读线索**。省掉它，溯源校验就只剩「有没有标注」、判不了「标注对不对」——实测全库 **3984** 处标注中 **1506 处**因省略简称而**无法机械复验**（占 38%），是溯源校验可判案率仅 **18.5%** 的**最大单一原因**。
- **与 §S7 回写纪律 ⑥ 的关系**：⑥（「引用与数字须来源对齐……回原文抽验时按『数字能否在引用所指文件里命中』判定」）说的是**怎么做抽验**；本条说的是**标注怎么写才验得动**——⑥ 是人工版，本条把它的前提写成**格式硬要求**。
- **不构成省略理由**：卷内上下文单一**不是**理由——推断会出错，而出错的推断等于**造假证据**。确无法判定轮次的，用兜底简称 `回复`（见上表），**不得留空、不得只写页码**。
- **存量不回溯**：本要求**只管新写与新回写**；存量 **1506 处裸页码**属**语义面**（要逐条判「那一页出自哪份文件」），**由人裁定后改，AI 不猜**。门禁是否为此加项，待溯源校验可判案率达标后再评估（现**刻意不加**，否则会把大批存量一次判红）。

| 简称 | 指代 |
|---|---|
| `招` | 招股说明书（默认最新版） |
| `招·注册稿` | 需区分版本时 |
| `问1` / `问2` | 第 1／2 轮问询回复 |
| `上会` | 上会稿 |
| `反馈` | 反馈意见回复 |
| `回复` | 问询回复**轮次无法判定时的兜底**（优先用 `问1`／`问2`；分卷回改时登记） |

**四条规则**
1. **来源在前、页码在后** —— 禁 `（PAGE 195、220 招股书）` 这类颠倒形态
2. **同括号同源** —— 一个数字只挂它实际出处；跨来源须分别标注
3. 多来源用 `；` 分隔；`、` 只用于页码并列
4. 页间分隔统一 `、`（禁 `/P109` 形态）
5. **适用范围** —— 上述「页码区间用 `-`」**只作用于本节的规范格式**（**含空格＋`P` 分隔**，如 `问1 P348-352`）；**不适用于「层级-页码连写」形态** —— 连写时**层级分隔符与区间符必须异形**（层级用 `-`、页区间用 `~`，如 `8-1-63~65`），否则 `8-1-63~65` 与「三级层级＋单值」`8-1-2-13` 的**字符形态相同、不可判读**。规则全文见 `pending-rules` ＋ 方法论条目 `S-010117`。

### 4.2 来源代号的**物理指向**（单一事实源 · 2026-09-26 WO-33）

> **本节此前只定义「代号是什么意思」，从未定义「代号指向哪个文件」** ⇒ 来源是**异质的**
> （`招` → `cases/<案>/…招股说明书*.txt`；`财务包` → `cases/<案>/阅读包_财务.txt`），
> 「把 `招 P152` 回到原文逐字命中」这类**溯源校验无法机械化**（本库已发生过串台事故，见 §参考纪律⑥）。

- **单一事实源**＝生成物 `_generated/来源代号映射.json`（由 `scripts/gen_source_map.py` 重扫 `cases/` 生成，**禁手改**）。
  结构：`codebook`（代号→语义）｜`cases.<案名>.sources[]`（`code`／`kind`／`version`／`round`／`file`／`lines`／`pages`／`text_available`）｜`unmapped`（无法归类者）｜`no_material`（零材料案）。
- **机械可行性（实测）**：材料 txt 带 **`===== PAGE N =====`** 页标记（实测 485 个来源中 **477 个页码可解析**）⇒
  「页 → 行」可机器换算，**页级溯源可落地**。
- **代号扩展入表**：实测自 `unmapped` 反哺新增 `落实函`（审核中心意见落实函，科创板常见件）。
  新增代号须**同改** `gen_source_map.py` 的 `CODE_RULES` ＋ `codebook` —— 未入表者只落 `unmapped`、不静默丢弃。

### 4.3 行范围位（A1 · **新条目适用，存量不回溯**）

**格式**：`（<代号> P<页> L<起>-<止>）`，如 `（招 P152 L3-8）`；无行号需求时可省，仍写 `（招 P152）`。

- **为什么只对新条目**：给 1,689 条存量补行号属**内容回写**，需逐条核原文（AI 不猜）；且**行号只在「值不在源里」时才具诊断力**——
  本库量级远超该前提，行号是**规模必然**，但仍须**增量推进**。
- **何时必须给**：实证项中的**数字**（占比／金额／比率）建议带行范围，使「该数字能否在源里逐字命中」可机械核。
- **解析约定**：页→行以 `===== PAGE N =====` 为界；同页内 `L1` 为该页首行。

### 4.4 降级留痕（A6 · **显式声明，禁静默**）

凡来源标注**未能达到契约精度**者，须**在标注位就地留痕**（而非默默降级）：

| 降级情形 | 写法 | 说明 |
|---|---|---|
| 只有页、无行范围 | `（招 P152）` | 合规默认，**不算降级** |
| 轮次判不出 | `（回复 P30）` | 兜底代号，见 §4 表 |
| 仅有 PDF、无 txt | `（招 P152 ⚠️无文本源）` | 对应映射表 `text_available: false` |
| 页码本身不可解析 | `（招 第152页 ⚠️页码未解析）` | 对应映射表 `pages: null` |
| 整条无来源 | **不允许** | 四字段模型「来源」为**必填**（§2） |

**判据**：降级必须**可被机器识别**（⚠️ 标记 ＋ 固定词），使降级率可统计；**静默降级 ＝ 记为零风险，是最坏的一种失真**。

### 4.1 非案例来源条目的「实证」位

**触发**：条目**并非**由案例蒸馏而来，而是**外部规范**（国标／行业标准／法规条文／监管规则等）入编。

**规则**：

1. **字段名不变**——仍用 `实证`（不新造字段名，保校验白名单与跨册一致性）；
2. **内容改挂规范出处**——`实证` 位**以规范条款号承载、不挂案名**，写法：
   `- **实证（规范源＝<规范名＋编号，如 GB/T 15834—2011《标点符号用法》>，非案例）**：<§条款号：规则摘要>；<§条款号：…>`
3. **必标「非案例」**——使人一眼辨明证据类型，避免下游按案例检索；
4. **「适用场景」须落到投行文档**——给出该规范在申报文件／内部报告中的**具体落点**，不空谈规范本身。

**先例**：体例域卷 01-4 的 `S-010117`–`S-010119`（标点符号体例族，规范源 GB/T 15834—2011）。

## 5 标签禁用四条

| 禁用 | 理由 |
|---|---|
| `本案实证`（**仅限跨案层**） | 跨案层条目下「本案」**无指代对象**（库是跨案层，没有"本案"）⇒ 跨案层用 `实证`；**单案层与产出层（`40_单案/`、`cases/*/产出_*`）不适用本条——那里的规范名就是 `本案实证`**（§6，D6-1 规范优先） ⚠️ 原表述「为两层字段一致，统一为 `实证`」为 D1 旧口径，已被 D6-1 取代 |
| 标签内**写死案数**（`（五案）`／`（5 案）`） | 案数随回写变化，写死即失真 |
| 标签内出现**日期／「回写」／批次** | 动作与时序不是知识属性；可追溯性由单案文件 ＋ 蒸馏笔记承载 |
| 标签括号内**塞案名**（`（易事达）`） | 案名是字段不是标签；同一案应落为 `**<案名>实证**`（排布 2） |

> **`拆解` 的登记依据**：W 条目（投行语言专项）固定段序为
> `投行语言特征 → 原文实证 → 拆解 → 句式模板 → 适用场景`。其中 `投行语言特征` 答「**是什么**」，
> `拆解` 答「**为什么这样写**」（机理解释），二者语义不同、不可互替——21 处稳定一致出现，
> 且内容有独立价值（把语言现象从"习惯"上升为"机理"）⇒ 判定为**漏登记的规范要素**，非别名。
> 故从 `ABOLISHED` 移入 `CORE_FIELDS`（同步 `scripts/check_entry_contract.py`）。

**强制面收缩原则**：契约只约束上述 **10** 个字段名；其余 `- **X**：`（内容小标题如 `周期性`／门禁标记 `G1…G4`·`R1…R4`·`AP-W`／元信息如编号引用）一律视为**非字段**，**不做检查** —— 否则长尾会逼出上百条无意义规则。

**受理形态**：A3 受理**两种形态** —— **列表形** `- **X**：`（主形态）＋ **顶格形** `**X**：`（无列表符，登记为**合法第二形态**）。扩面动因：实测顶格形 **5,067 处＝全部字段标签的 20.5%** 此前**完全不受检**，其中废止别名 1,315 处（已同批归一）。**只查字段名、不管形态**（顶格与列表在渲染上等价，为统一形态去改 20% 库面不划算）。
**② 冒号前允许「出处括注」**：字段名与冒号之间**可插入一段 `（出处）`** —— 如 `- **原文实证**（招股书 PAGE 7）：…`。原判据要求**紧跟冒号** ⇒ 这类写法**静默零检出**（实测该形态 **237 处、捕获 0**）。现判据为 `**<字段名>**（可接一段括注）[：:]`（全角/半角括号与冒号均可）。

### 6.1 为什么单案层是「本案实证」、跨案层是「实证」

| 层 | 写法 | 依据 |
|---|---|---|
| 单案层（案例层） | `本案实证` | 「本案」**有指代对象**（即该案）；且该名是 §S4 冻结模板原文 |
| 跨案层（主库） | `**实证**` ／ `**<案名>实证**` | 规范**未定义跨案层字段**（§S4 只定义案例层条目模板）；主库是跨案层，「本案」无指代 ⇒ 由本契约定义 |

**实测分布（三层实测，作为「异名是设计」的证据）**：

| 层 | `实证`（短式） | `本案实证`（全式） | 规范名 |
|---|---|---|---|
| 主库根（跨案层） | **224** | **0** | `实证` / `<案名>实证` |
| 单案层 `40_单案/` | 0 | **1,490** | `本案实证` |
| 产出层 `cases/*/产出_*` | 0 | **2,404** | `本案实证` |

**结论：跨层传递不需要"名字映射"表** —— 回写从单案取内容落为主库实证项，本就是**结构搬运**（案名成为字段、页码转契约格式），字段名差异不构成额外成本。（勘误：首版契约曾把「两层异名需映射」列为"规范优先"的代价，属**夸大**，已纠正。）

1. **只用 §3 的三种排布**，不得自创标签形态（历史反例①：`**<案名>实证（YYYY-MM-DD 回写）**` 曾作为纪律写入 SKILL.md，已按 D2/D3 废止；**历史反例②**：批次临时回写脚本产出 `- **新案实证（AN00XX 简称）**：…`（案名位被解析为「新案」）⇒ A4「未登记案名」**246 行全数返工**。**纪律**：回写**首选复用 `scripts/apply_rewrite.py`**（其模板 `- **<案名>实证**：<标题> —— <实证首句>（<来源>）` 即 §3 合法形态）；确需自建临时脚本时，标签串**照抄该模板**，禁「案号 + 案名」复合式、禁把状态词（新案/跨案）写进案名位）

## 10 条目状态块（Status）分型（L2 · 2026-09-26 WO-33）

> 此前留痕**只有一型**（`> **适用场景扩展 YYYY-MM-DD（<案名>）**`，§3 排布 4）——它只表达「**补强**」，
> 无法表达「**被取代**」与「**源头冲突**」。两类后果完全不同：前者是知识增长，后者是**口径风险**。

| 型 | 写法 | 何时用 | 与契约的关系 |
|---|---|---|---|
| **补强**（既有唯一型） | `> **适用场景扩展 YYYY-MM-DD（<案名>）**：…` | 中/中高重合**扩展**既有条目的适用场景 | §3 排布 4，**含日期不受禁日期约束** |
| **被取代**（`Outdated`） | `> **已被取代 YYYY-MM-DD（<新编号>）**：本条原述…，现据…改为…` | 新条目**在实质上覆盖**本条，本条不再独立成立 | **保留原文**（禁删），只加状态行；`<新编号>` 必填 |
| **源冲突**（`Disputed`） | `> **源头冲突 YYYY-MM-DD（<案A> vs <案B>）**：… | 两案来源对同一问题给**不同口径**，暂未裁定 | **只标不改**，交用户裁定（同 `adversarial-review.md` 口径） |

**三条硬约束**
1. **只加不删**：状态块是**叠加**在正文之上的注释行；**禁**改写或删除被标注的原句（受保护内容不可覆盖）。
2. **必须带日期**：与排布 4 同理——状态行的日期是其**功能所需**（区别于 §5「标签内禁日期」只管 `实证` 标签）。
3. **`被取代` 须给后继编号**：没有后继编号的「取代」＝**无引用条目子句**，无法追溯 ⇒ 视为未完成。

**校验边界（诚实声明）**：状态块为**叙述形态**，当前**无机器校验**（不入门禁）；
其可靠性依赖 `adversarial-review.md` 的对抗性复核与人工裁定。**这是有意的**——
把它做成字段级强校验会迫使存量 1,689 条全部补状态位（内容回写），与本库「不回溯」原则冲突。

## 11 条目生命周期（5 态状态机 · A4 · 2026-09-26 WO-33）

> **为何要做**：条目会**过期**。没有状态位时，「这条还成立吗」只能靠人重读全文；
> 状态下沉为**条目的一个属性**后，「哪些需要复检」变成一次筛选。
> **为何只对新条目**：状态位是**内容字段**；给存量全部推定并落盘 = 1,689 条内容回写（AI 不猜、且违反不回溯）。

**五态与转换**（`draft → active → contradicted ／ stale → archived`）

| 态 | 含义 | 进入条件 | 可否被检索当结论用 |
|---|---|---|---|
| `draft` | 候选，未经 S6 裁决 | 蒸馏产出但未入库 | ❌ 不得作结论 |
| `active` | 生效（**默认**） | 过 S6 四态裁决与门禁后入库 | ✅ |
| `contradicted` | 与他条**冲突**（未裁定） | 发现两条对同一问题口径互斥 | ⚠️ 用则须同时引冲突条 |
| `stale` | 依据已过时（如准则修订／材料更新） | 来源变旧、或对应案有新版本文件 | ⚠️ 用则须核 |
| `archived` | 归档，不再维护 | 被取代且无独立价值 | ❌（正文保留，可追溯） |

- **转换留痕走操作日志（旧称：事件流）**（`log_event.py --action 治理`），**不在条目内写状态变迁史**——避免把过程写进知识。
- **存量推定**：全部存量条目**推定为 `active`**（不落盘、不标注）；**仅在状态真的要变时**才落字段。
  这条同时是「不回溯」与「不失真」的平衡点：**推定不等于断言**，故不落盘即不产生错误事实。
- **不可变事件日志**：状态变更事件**只追加、不改写**；回滚以**新事件**表达（`stale → active`），不删旧事件。
- **快照**：状态变更**不自动存正文快照**——本库的「快照」职能由 **git 真身仓** 承担
  （**区别于需自建 `content_snapshot` 的方案**：那类载体有 Web 端无版本控制，本库有）。
  **若确需回滚正文，走 git**，不在库内另建快照层（避免第二套事实源）。

**边界**：本状态机**当前无机器校验**；五态取值若日后要落为 frontmatter 字段，须**先立字段名与校验器**（属新一轮规范面变更），不可先散落。

## 12 「互见」字段（R2 · **新条目强制，存量不回溯** · 2026-09-26 WO-33）

> **本库不建反链**。但「**这条和哪条相关**」是条目自身的知识属性 ⇒ 以**单向字段**承载，
> 由 `gen_refgraph.py` 现算反视图——**信息反向可得，字段保持单向**。

- **格式**：`- **互见**：<编号>（<一句说明>）；<编号>（…）`；**无关联写 `- **互见**：无`**。
- **适用范围**：**跨案层**（`10_跨案域/`）与 **分卷**（`50_分卷/`，字段名已是既有约定，实测 1,028 处）。
  `40_单案/`（案内自指，无互见语义）与 `30_行业版/`（I-CL 条目另制）**不适用**。
- **强制性＝增量水位**：族内序号 > `HUXIAN_WATERMARK`（2026-09-26 冻结）者视为新增 ⇒ 缺字段即 **ERROR**
  （体检第 21 项）。**存量 1,689 条不回溯**——补存量需语义判断（AI 不猜）。
- **⚠️ 水位表不得随新增条目更新**：更新它等于把新条目「祖父化」，规则即静默失效（属**设计上的失效面**，已在覆盖边界声明）。
- **只判有无、不判内容**：指向是否合理属 `govern/adversarial-review.md` 面（AI 判读 + 人裁定）。
- **知识来源**：入库时由 S6a 映射表（重合度判定）**顺带产出**互见候选——**不额外增加人工步骤**。

| **问题索引**（旧称：语义册） | 回答「这个问题域有哪些条目」——条目编号 ↔ 问题分类 ↔ 短标签。 |
| **位置目录**（旧称：定位册） | 回答「这个编号在哪个文件第几行」——按行号只读那几行。 |
| **库首页**（旧称：入口薄壳） | 库的门面文件，只有路由表和用法，读库先看它。 |
| **生成物** | 脚本从正文现算出来的文件（`_generated/` 下），人和 AI 都不手改。 |
| **操作日志**（旧称：事件流） | 只追加的流水账，记「发生过什么」；状态类信息不进这里。 |
| **蒸馏** | 从一条新 IPO 案例里提炼可复用做法、落成新条目的过程（七步）。 |
| **护栏体检** | 22 项自动化检查，一次扫全库的结构健康。 |
| **重跑校验**（旧称：幂等自证） | 把索引生成器重跑一遍和现库逐字节对比，一致才健康。 |
| **条目数对账**（旧称：守恒对账） | 几个地方数出来的条目数必须相等，对不上就是有增删没同步。 |
| **失效引用**（旧称：悬空引用） | 指向不存在编号的引用——现在新增一条即 ERROR，无豁免。 |
| **无引用条目**（旧称：孤儿条目） | 在册但没有任何条目引用它的条目——只是提示，不是错误。 |
| **未分类**（旧称：待归类） | 还没挂上问题分类的条目，合法中间态，靠全文检索兜底。 |
| **双路检索** | 硬纪律：索引路＋全文 grep 同时跑，两条路都空才算「库里没有」。 |
| **四栏** | 体检输出格式：ERROR（真坏）/ UNVERIFIABLE（验不了）/ WARN（提醒不拦路）/ NOTES（**判据已认定合法**的形态，留可见性但不计数；2026-10-03 增）。 |
| **唯一匹配门** | 改文件前确认目标文字恰好出现 1 次，否则拒绝改——防改错地方。 |
| **AI 起草、用户裁定** | AI 准备证据和方案，内容拍板权永远在人。 |

> 落点选本册的理由：本册是「条目与回写书写契约」单一事实源，该纪律 ①②③⑧⑩ 均为契约的执行侧落点；**原 `SKILL.md` §S7 步骤仍保留并内联指向本节**。

## 禁止写法

| 禁止形态 | 原因 | 正确做法 |
|---|---|---|
| **案内序号**（如 `PL-15-01`／`PL-19-02`／`W-AN0061-C02` 出现在**跨案引用**处） | 案内序号是**产出件内部**的「族-序」编号，**与主库编号体系不对应** ⇒ 读者无法定位（实测：23 处此类引用无处可指） | 入库时**归一为主库六位编号**（如 `PL-15-01 → PL-010106`）；确需引用产出件时写「案名＋产出件名＋序号」 |
| **占位编号** `S-TBD-NN`／`PL-TBD-NN` | 已废除 | 由主理人按族内 max+1 分配正式编号 |
| 族内跳号 | 破坏「族内连续」 | 按族内 max+1 连续分配 |
| **以动作名作层名**（如「五·附、补蒸更新」／「4.6 第一轮补蒸新增范式」／「（补蒸后 28 条）」／以动作词命名的过程件文件名） | 层由**功能**定义、不由**动作**定义 —— 把**一次动作**做成与原蒸馏**并列的一层**，读者会把同一层内容当成两类资产 | 增量条目**直接按其维度并入对应章**（编号顺延、不另立层）；计数**只写当前实际条数**；确需独立承载的只有「**条目修订与口径登记**」这类**功能性**内容（可独立成附节，但**不以动作名命名**）；过程件命名用**事实词**（如「第 N 轮增量」＝说明新到位材料）。详见 `distill-methods.md` §S7.1 |

> **纪律**：凡「形态像编号」的引用，映射前必核三事 —— ① 出现位置（主库卷内＝主库编号；案目录/单案文件＝案内序号）；② 括注描述是否与目标编号标题**逐字一致**；③ 该案是否有独立产出件。任一不符 ⇒ **不改，登记待核对**。
